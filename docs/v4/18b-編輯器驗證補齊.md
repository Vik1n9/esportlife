# S18b · 編輯器驗證落差補齊（單筆驗證＋條件式積木）

狀態：✅ 完成
前置：S18a S19c
預估：1 session
推理難度：低
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：規則來源明確（逐條對得到 `tests/kernel/*.mjs` 的行號），沒有平衡判斷，也不新增
內容。難的地方只有一個——**不准把驗證寫得比測試嚴**，寫嚴了既有資料一載入就滿江紅。

## 為什麼做這件事

S18a 說明書的開場白是這樣寫的：

> 手寫這些條目要同時記住：欄位名、觸發條件語法、互斥成對、選項 2~4、效果只能用
> modifiers 的四種寫法、素材分池不重疊、天生特質必須指派池……**記錯一項，測試才會
> 告訴你。**

三個大內容站（S18／S19b／S19c）跑完之後回頭量，發現這句話對編輯器自己也成立：
`validateEntry` 只做四件事（辨識鍵唯一、事件卡專屬檢查、效果寫法、條件式語法），
**特質卡、合成配方、訓練事件卡三類根本沒有專屬驗證分支**。於是有一批規則測試擋得住、
表單放行——填的時候是綠的，貼回去 `npm test` 才紅，正好是這個工具存在要消滅的失敗模式。

其中最該擋的是 §14.8.4：訓練事件卡「單純成功或單純失敗**絕對禁止**更動心理數值」。
S18 那 60 張訓練卡就是用這個編輯器產的——**沒出事是靠人肉遵守，不是靠工具**。

`docs/v4/20b-組裝前架構審查.md` 掃過交接鏈，抓到編輯器認得 `unique` 階而引擎沒有
store（A2），但沒有掃驗證覆蓋率，所以這份落差清單是新的。

## 範圍

### 必讀規格

V4 §13.1（雙面性）、§13.2（副作用分級）、§13.3（互斥）、§14.1（天生池上限與
mentalBias）、§14.2（兩池不重疊、死配方規則）、§14.6（配方形狀）、§14.7（條件式）、
§14.8.4（訓練卡心理禁令）、§6.2（受傷只在大失敗）。

**權威是測試不是規格書**：規則若規格寫了而測試沒驗，只能是警告；測試驗了才是硬紅。
反過來，工具**永遠不准比測試寬鬆**。

### 做了什麼

**1. 三個單筆驗證函式（`tools/schema.js`）**

| 函式 | 擋什麼 | 測試出處 |
| --- | --- | --- |
| `validateTrait` | 副作用非空、重度只給史詩／傳說、傳說必 heavy＋career 池、**互斥對稱** | `tests/kernel/traits.mjs` 68／83／93／95／132 |
| `validateFusion` | 稀有恰 2 素材／史詩 2~3、素材分池（稀有吃 persona、史詩吃 performance）、產物不得是傳說 | 同上 242／51、§14.6 |
| `validateTrainingCard` | **`success`／`failure` 不得動心理（§14.8.4）**、受傷只在大失敗、pool 與 tier 一致 | `tests/kernel/training.mjs` 106／129 |

`editor.js` 的 `validateEntry` 加三行 dispatch，比照既有的 `validateEventCard`。

⚠ **兩處刻意寫得比規格鬆**，理由寫在程式碼註解裡：

- `tilt`／`pariah` 是 common 卻標 heavy——`traits.mjs:83-87` **明文豁免**（v4.2 把
  心態崩盤／圈內毒瘤重寫成雙面特質）。驗證跟著豁免，豁免清單與測試同源，改要一起改。
- 「益處非空」規格有（§13.1 沒有純副作用特質）但測試沒驗，且 `glass`（玻璃體質）
  現況就是 `effects: {}`——所以是**警告不是硬紅**。要升成硬紅得先補內容。

**2. 天生池取得率常駐顯示**

`checkInnatePoolSize` 改成永遠回訊息：N、`0.8 ÷ N`、離 15% 死線的餘裕，直接印在天生
分頁頂端（不必開關係檢查面板）。N=4→20%、**N=5→16%（現況，貼線警告）**、N=6→13.3%
（破線）。池開得越大每一個越拿不到，與直覺相反，所以要一直看得見。

同時補兩條原本沒驗的：天生特質必須指派 persona／performance（`traits.mjs:237`）、
`mentalBias` 維度不得重複（§9.1）。

**3. 條件式積木模式**

`type: 'cond'` 從裸 JSON textarea 變成雙模式：

- **積木**（預設）：`and`／`or`／`not` 容器可加減子條件，葉節點 `stat`（謂詞／比較子／
  值三個下拉與數字框）、`has`（階／特質鍵）、`hasCount`。只產得出合法結構。
- **原始 JSON**：既有 textarea 原樣保留，25 張任務卡都是那樣寫的，不能斷。

兩模式共用同一份 `value[f.key]`，切換不動資料——25 張 × trigger/goal 兩欄實測
round-trip 逐字不變。**不擴充謂詞表**（那是 `src/engine/conditions.js` 的事）。

**4. 順手修的兩個既有缺陷**

超出原訂範圍，但都讓工具違反自己站規格的不變式：

- **`effects.attr` 誤報**：`validateEffects` 的跳過清單有 `mental`／`buff`／`injury`
  沒有 `attr`（S18 擴充時漏的），**60 張訓練卡誤報 28 張**「效果鍵不被引擎消費」。
  誤報比漏驗更傷——它訓練開發者無視紅字。
- **輸出排版偏移**：序列化器用 `JSON.stringify` 的雙引號、且無條件把物件展開多行，
  但資料檔通篇單引號＋短物件內聯。違反 S18a 不變式「輸出排版與既有檔案一致，貼回去
  的 diff 只有新增那幾行」。改成單引號＋100 欄內放得下就內聯。

### 不做

- 不動 `src/`／`tests/`（驗證覆蓋率的站，不是修內容的站）
- 不改既有資料迎合新驗證——跑出來的紅是內容缺口，見下面交接筆記
- 不修 20b 的 A1／A2／A3（要動 `src/`，屬 S21 或單開站）
- 不擴充謂詞表、不動 `EFFECT_KEYS`
- 不加相依套件、不做即時預覽（會耦合 `src/ui/*`，就不是唯讀消費者了）

## 交接筆記

**2026-08-15 完成。程式與測試未動**（`src/`、`tests/`、`index.html` 零 diff）。

### 現在擋得住、以前擋不住的

特質：互斥對稱（會直接說「要在 X 的 exclusiveWith 補上 Y」）、副作用非空、重度分級
與種類相容、傳說必 heavy＋career。配方：形狀與分池、產物不得是傳說。訓練卡：§14.8.4
心理禁令、受傷檔位、pool/tier 一致。天生池：取得率、合成池指派、mentalBias 維度重複。

### 還是驗不到（留給下一站）

- **取得率 ≥15%**：除了天生池的封閉式 `0.8 ÷ N`，其餘素材要跑 160 段生涯才量得到
  （§21.3 明文：設計時算不出來）。工具只查「有沒有來源」，機率層是 S19c 的驗收線。
- **條件式的形狀**：只驗語法與謂詞名，不驗「這個組合引擎吃不吃得下」（§12.3 刻意）。
- **`unique` 階與引擎脫節**：`tools/schema.js` 認得 `unique`，但 `TIER_STORES` 沒有
  這個 store（20b 的 A2）。本站不修——要動 `src/`。編輯器目前的 `ALL_TRAIT_KEYS`
  也**不含** `UNIQUE_TRAITS`，所以 unique 特質在下拉選單裡是看不到的。
- **總數斷言**：測試寫死了 69 特質／60 訓練卡／86 事件卡等數字，新增內容必然要同步
  改測試——工具不會提醒這件事。

### 新驗證跑出來的內容缺口（不是 bug，別順手改）

`glass`（玻璃體質）`effects: {}` 是純副作用特質，違反 §13.1「亦無純負面特質」。
測試沒驗這條所以只給警告。要補的話是內容站的事：給它一個益處（§14.8.2 第 6 條
「極端標籤檢驗」——想一個現實中職業隊伍容忍玻璃體質的理由）。

### 踩過的坑（改動時小心）

1. **不准把驗證寫得比測試嚴**。第一版把 `tilt`／`pariah` 的 heavy 標成錯，其實
   `traits.mjs:83-87` 明文豁免；把「益處非空」寫成硬紅，`glass` 立刻紅。兩者都會讓
   既有資料一載入就滿江紅，開發者很快就學會無視紅字——**誤報比漏驗更傷**。
2. **積木的數字框用 `change` 不是 `input`**：每次變動都重畫整棵樹，用 `input` 會打
   一個字就失焦。
3. **原始模式的 textarea 不重畫**：`draw()` 會吃掉輸入焦點，所以 raw 模式的 input
   handler 只寫回 value ＋驗證 ＋`onChange()`，不呼叫 `draw()`。
4. 沿用 S18a 的坑 2／坑 3 依然成立：先寫回 `value` 再驗證；`onChange` 要一併更新
   輸出 pre。
5. **測試腳本會抓到過期的 DOM handle**：點 `.item` 會觸發 `render()` 重建整個
   section，之前抓的 `ElementHandle` 就失效了——每次點擊後要重抓。
