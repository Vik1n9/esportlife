# S18a · 內容編輯器（事件卡／特質）

狀態：未開始
前置：S17 S19a
預估：1 session
推理難度：中
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：規格明確、沒有平衡判斷，但要讀懂兩套資料 schema 與既有的效果表達方式
（`kernel/modifiers.js` 的四種寫法）才做得出正確的表單。降級到 Haiku 的風險是做出
一個能填但填出來的東西貼回去會壞的工具。

---

## 為什麼做這件事

S18（事件卡 26 → 80~150 張）與 S19b（傳說特質 6 → 20）是整條線最大的兩塊內容工。
手寫這些條目要同時記住：欄位名、觸發條件的寫法、互斥群組要成對、選項數必須 2~4、
效果只能用 `kernel/modifiers.js` 的四種寫法、素材分池不能重疊……**記錯一項，
測試才會告訴你**。

做一個編輯器，把這些規則變成表單約束與即時驗證，內容站就只剩「想文案」這件事。

**這個工具只面向專案開發者，不是遊戲的一部分。**

排在這裡的理由：S17 定案事件卡 schema、S19a 定案特質 schema，兩者都定了才動手，
工具不必跟著改；而 S18／S19b／S19c 三個內容站排在它後面，正好用得上。

## 範圍

### 要做

**1. 建立 `tools/` 目錄，與遊戲完全分離**

```
tools/
├── index.html        入口：選「事件卡編輯器」或「特質編輯器」
├── editor.js         表單渲染與驗證（由 schema 驅動）
├── schema.js         ★ 欄位描述：兩套資料的權威 schema 描述
└── editor.css        樣式（可沿用 src/styles.css 的色階變數，但獨立一份）
```

- **不改 `index.html`**，不從遊戲任何地方連過去
- `tools/index.html` 開法與遊戲一樣：`npm run serve` 之後開
  <http://localhost:8080/tools/>
- ⚠ repo 根目錄由 GitHub Pages 直接服務，所以 `tools/` 線上也打得開。這是可以接受的
  （它不碰玩家存檔、不影響遊戲），但**頁面上要明寫「開發者工具，非遊戲內容」**

**2. `schema.js` 是這個工具的核心設計**

不要把欄位寫死在表單程式碼裡。寫一份**宣告式的欄位描述**，`editor.js` 依它渲染：

```js
export const EVENT_SCHEMA = {
  id:      { type: 'string', required: true, unique: true, hint: 'kebab_case，全域唯一' },
  name:    { type: 'string', required: true },
  prompt:  { type: 'text',   required: true, hint: '具體場景，不要抽象描述' },
  kind:    { type: 'enum',   options: ['normal', 'indulgent', 'romance', 'patch'] },
  options: { type: 'list',   min: 2, max: 4, of: OPTION_SCHEMA },
  // …觸發條件、優先度、互斥群組依 S17 的定案填
};
```

這樣後面改 schema 時**只改這一個檔**，不必動表單邏輯。這是這一站最重要的架構決定
——V4 之後 schema 還會再動，寫死等於保證要重做。

**3. 直接讀現有資料，可瀏覽也可改**

零建置 ESM，工具可以直接 import 遊戲的資料模組：

```js
import { EVENT_CARDS } from '../src/data/events.js';
import { BASE_TRAITS, RARE_TRAITS } from '../src/data/traits.js';
import { EPIC_TRAITS, LEGENDARY_TRAITS, FUSIONS } from '../src/data/epics.js';
import { ATTRS, ATTR_NAMES } from '../src/data/attributes.js';
```

**能讀既有條目比只能新增有用得多**——大部分工作是調整既有內容而不是從零寫。
提供：列表瀏覽 → 點進去載入表單 → 改 → 產出新版本。

屬性鍵、心理維度、特質鍵這些下拉選單一律從資料模組取，不要手打——手打就會漂。

**4. 即時驗證**

表單旁邊就要紅：

| 檢查 | 對象 |
| --- | --- |
| id 唯一、格式正確 | 兩者 |
| 選項數 2~4 | 事件卡 |
| 互斥群組要成對（標了互斥就要有另一張同群組的） | 兩者 |
| 效果只能用 `modifiers.js` 的四種寫法（加法／`mul`／`floor`／`cap`／旗標） | 特質 |
| 每個特質都要有副作用（§13.1 無純正面特質） | 特質 |
| 素材分池不重疊（稀有吃人格／媒體，史詩吃競技表現） | 配方 |
| 效果鍵是否真的被引擎消費（掃 `src/` 有沒有人讀） | 特質 |

最後一項特別有價值——打錯一個效果鍵不會有任何錯誤訊息，那個特質就只是靜靜地
沒有效果。

**5. 輸出**

靜態頁寫不了檔案，所以：

- **複製到剪貼簿**：產出可直接貼進 `src/data/*.js` 的物件字面值
- **下載 `.js` 片段**：同上，存成檔
- 輸出格式要**跟既有檔案的排版一致**（縮排、引號、尾逗號、欄位順序），
  貼回去不該產生無關的 diff

**6. 寫一份 `tools/README.md`**

開法、每個欄位的意思、產出怎麼貼回去、schema 改了要動哪裡。S18／S19b 的執行者
會先讀這份。

### 不要做

- **不要動 `src/` 任何檔案。** 工具是唯讀消費者
- **不要動 `index.html`**，不要從遊戲連過去
- **不要讓工具寫檔。** 沒有 File System Access API、沒有後端。輸出只有剪貼簿與下載
- **不要加相依套件。** 零建置是硬約束，工具也一樣
- **不要順手改 schema。** 發現 S17／S19a 定的 schema 有問題，寫進交接筆記
- **不要做遊戲內容**（S18／S19b／S19c）。這一站只做工具

## 規則與不變式

- `npm test` 前後**完全不變**（沒碰遊戲程式）
- **零相依**：`tools/` 不引入任何外部套件、不從 CDN 載東西
- **schema 只寫一次**：欄位名稱與可選值全部來自 `tools/schema.js` 或 `src/data/*.js`，
  `editor.js` 裡不該出現硬寫的欄位名清單
- **產出貼回去要能過測試**：至少手動驗一輪——用工具產一張事件卡與一個特質，
  貼進資料檔，`npm test` 仍全綠，然後把它們移除
- **輸出排版與既有檔案一致**：貼回去的 diff 只有新增的那幾行

## 完成定義

```bash
npm test
```

全綠，項數與 S19a 結束時相同。

```bash
git diff --stat -- src/ tests/
```

輸出為空。

```bash
npm run serve
```

開 <http://localhost:8080/tools/>，逐項確認：

1. 事件卡列表載得出現有的全部卡片，點進去能編輯
2. 特質列表載得出四階特質，點進去能編輯
3. 故意填一個重複 id、只填 1 個選項、寫一個不存在的效果鍵 → 三種都要當場紅
4. 產出一張新事件卡，複製貼進 `src/data/events.js`，`npm test` 全綠
5. 產出一個新特質（含副作用），貼進 `src/data/traits.js`，`npm test` 全綠
6. 驗完把兩筆測試資料移除

第 3 項是這個工具的價值所在——沒有當場紅，它就只是個排版器。
