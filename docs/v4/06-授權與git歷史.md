這段跟「作者未回覆、以未獲授權處理」已經不一致。怎麼改是人的決定，不是 AI 的。
把事實列清楚就好：

**不要在問題裡給法律意見**，也不要在選項描述裡暗示哪個選擇「比較安全」。
如果人問到法律問題，說明這超出能判斷的範圍，建議諮詢律師。

**（二）git 歷史怎麼處置**

事實：`3c23597 Initial commit` ～ `3379e0b` 共 20 個 commit 就是原始棒球遊戲本體
（`yakyolife.html`）。

選項各自的後果（照實寫，不推薦）：

| 選項 | 後果 |
| --- | --- |
| 保留歷史不動 | 最省事。歷史裡的原始程式碼仍可被取出 |
| 從 `a71ee13` 之後開新 orphan 分支當 main | 舊歷史仍在 repo 裡（除非另外清），但預設看不到 |
| `git filter-repo` 重寫歷史 | 不可逆。所有 commit hash 改變，已 clone 的副本會對不上 |
| 開新 repo，只帶現況 | 乾淨但失去全部歷史脈絡 |

**第二步：照決定執行**

- 文件類改動直接做
- **歷史改寫類的動作，執行前再確認一次**：說清楚會跑什麼指令、影響哪些 commit、
  是否可逆。得到明確的「執行」才動手
- 改寫歷史前一定要有備份（例如先 `git clone --mirror` 到別的路徑）

### 不要做

- **不要自己決定授權怎麼寫。** 這是人的決定
