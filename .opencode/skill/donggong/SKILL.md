# 動工：接續 V4 重建的下一站

使用者說「動工」或「開工」或「接續下一站」時，依序執行。**不要跳過任何一步。**
一個 session 只做一站（AGENTS.md 的硬規則）。

## 1. 抓下一站（確定性，不靠記憶）

```bash
node docs/v4/next-station.mjs
```

- **exit 非 0 或輸出解析錯誤** → 先修 `docs/v4/next-station.mjs`（它與
  `docs/v4/README.md` 同源，README 一變動腳本就要同步），修完重跑，**不准跳過腳本
  直接人肉看 README 開工**。
- 有「進行中」站 → 續做那一站（讀它的交接筆記，已回填）。
- 否則用 `question` 工具**問使用者要做哪一站**：把「下一站」與「可並行的已解鎖站」
  全列成選項，**每個選項的 label 附上難度＋建議模型**（例：`S15b 生命週期曲線（高 · Opus 5）`），
  選項描述寫「建議切換到 Opus 5 模型」。把「下一站」放第一個並在 label 尾加「（推薦）」。
  使用者選定後，**先依該站的建議模型提醒切換**，再開工。

## 2. 載入共通上下文（每次都要）

- `docs/v4/00-共通規則.md`（不跳過：repo 事實、血緣規則、難度分級、四項檢驗、收尾動作）
- `docs/v4/00b-穩定點快照.md`（現在站在哪裡、安全網守得住什麼）
- 目標站的說明書（腳本輸出的 `doc` 路徑）

## 3. 讀規格對應章節

照目標站說明書「必讀規格」指名，讀 `ESPORT-DESIGN-V4.md` 的對應節。**沒讀完對應章節
不准動數值**（共通規則第三節）。

## 4. 開工

照說明書「範圍／要做／不要做」施作。**不要碰其他站的檔案**（說明書「不要做」那節）。

## 5. 收尾（照 AGENTS.md，順序固定）

0. 過四項檢驗（§0.5）
1. `npm test`
2. 回填該站交接筆記
3. 更新 `docs/v4/README.md` 狀態表（該站改「完成」；站結構有變動的話同步
   `docs/v4/next-station.mjs`）
4. `WORKLOG.md` 最上方加一筆
5. commit（一站一個）
