# V4 重建工作說明書 · 索引

`ESPORT-DESIGN-V4.md` 要把 esportlife 從「年回合 × 擲骰加點 × OVR」翻成
「月回合 × 賽馬娘設施制 × 十二技能／隱藏心理／教練評價」。

這不是改版，是重建。V4 同時動四根互相咬死的柱子——屬性刻度（1–80 → 0–100）、
回合粒度（年 → 月）、成長模型（擲骰加點 → 設施制）、評估層（OVR → 教練評價）。
任一根單獨改都會讓其餘三根的既有校準失效，所以沒有分批上線的路徑。

工作量約 2400 行重寫 ＋ 900 行淨室重寫 ＋ 事件卡 26→80~150 張 ＋ 特質全面補副作用。
**單一 session 吃不下**，所以拆成 31 站，每站一份說明書，各自能獨立開工。
主線施工途中再拆出 8 站（S15b／S17a／S17b／S18b／S19d／S20c–h 等，見下方狀態表），
主線共 39 站。v4.3.3 追加庚組 8 站（S23–S30，NPC 選手與戰隊）、v4.4 追加辛組 6 站

S24 拆四站（S24a–d，附錄 #74，版號不升），庚組 8→11 站；v4.6.1 追加**壬組 6 站**

## 怎麼用這套文件

> 說「動工」即由 `next-station.mjs` 自動解析下面的狀態表、抓出下一站並載入對應說明書
> ——不必手動找「第一個未開始且前置完成」的站。腳本與本表同源，本表一變動腳本必須
> 同步更新（見 `AGENTS.md` 收尾流程）。

1. 看下面的狀態表，找第一個「未開始」且前置都已「完成」的站
2. **依該站的建議模型切換**（模型選單操作，不是這裡跑指令）
3. 讀 [`00-共通規則.md`](00-共通規則.md)（每次都要，不要跳過）。
   要知道「現在長什麼樣」看 [`00b-穩定點快照.md`](00b-穩定點快照.md)——基準座標、
   承重牆、量到的數字、已知缺口
4. 讀該站說明書，照著做
5. 收尾：跑測試 → 回填該站的「交接筆記」→ 更新下面的狀態表 → 更新 `WORKLOG.md` → commit

一個 session 只做一站。做完就停，不要順手開下一站——「不要做」那節存在的理由就是
防這個。

## 開發者工具

### 內容編輯器 · [`tools/`](../../tools/README.md)

寫**事件卡／訓練事件卡／特質卡／生涯任務卡／合成配方／天生特質**一律用編輯器，不要
手寫資料檔——欄位名、效果寫法、雙面性、互斥對稱、素材分池、檔位與心理的邊界、關係
斷裂，填的時候就會紅。手寫的話這些要全部記在腦子裡，而且**記錯一項，測試才會告訴你**。

```bash
npm run serve      # 開 http://localhost:8080/tools/
```

⚠ 必須經 `npm run serve`：頁面直接 `import` `src/data/*.js`（所以工具永遠跟遊戲資料
同源），用 `file://` 開會被 CORS 擋。

輸出只有剪貼簿與下載 `.js` 片段，排版對齊既有資料檔，貼回 `src/data/*.js` 之後跑
`npm test`。工具不寫檔、不連進遊戲、零相依。用法與每一欄的意思看
[`tools/README.md`](../../tools/README.md)。

> **同步點**：動到 `src/engine/conditions.js` 的謂詞或 `src/kernel/modifiers.js` 的
> 效果鍵，`tools/schema.js` 的 `PREDICATES`／`EFFECT_KEYS` 要**同一個 commit 一起改**
> ——否則工具會把新謂詞擋掉、把新效果鍵標成「不被引擎消費」。
