> 2026-08-20。範圍：V4 重建全 68 站的開發流程成本。程式與測試未動，本檔是提案，

## 一、量到的數字

全部由 repo 現況實測，不是估計：

- 程式碼 33,279 行（`src` `tests` `tools` `scripts`）。
- Markdown 95 檔、1,986,537 bytes。**文件體積約為程式碼的兩倍**。
- 文件變更 +56,242 行 / −611 行（刪除率 1.1%）；程式 +57,302 / −1,514。
  文件是純追加，寫進去就不再收斂。
- `docs/v4` 968,854 bytes，其中「交接筆記」421,998 bytes，占 **43%**。
- 跨檔重複：長度 40 字以上的句子，126 條各自出現在 2 個以上檔案，合計重複 299 次。
- 血緣（A／B 批）敘述散在 14 個 md 檔。

### 每站固定前置（`donggong` skill 第 2、3 步強制載入）

估算法：CJK 每字約 0.95 token，ASCII 每 4 字約 1 token。

- `docs/v4/README.md` 12,882
- `docs/v4/00b-穩定點快照.md` 5,301
- 目標站說明書（以 S49 為樣本）5,496

## 二、為什麼消耗這麼大：三個機制

不是「工作太多」，是三個可修的洩漏。

### 洩漏一：讀取單位是「檔案」，不是「切片」

- `README.md` 12,882 token，開工只需要其中一列狀態與前置站的一句話。載入率 2%。
- 收尾要改狀態表，於是同一份 12,882 token 再進上下文一次。
- 規格書 75,737 token，站說明書已經明確指名「必讀規格：V4 §5.3、§7、§20.2」，
  但沒有工具能按 § 切片，只能整檔或大段讀。
- `WORKLOG.md` 100,153 token，規則只要求讀前三條（3,300）。

**這是最大單筆浪費，也最好修**——規格書有 26 個 `##` 節、96 個 `###` 子節，錨已經在了。

### 洩漏二：同一事實抄四份

每站收尾寫進四個地方：站說明書交接筆記、`README.md` 狀態表與「現況」段、`WORKLOG.md`、
`CHANGELOG.md`。以 S49 抽樣，四檔各提及 3 至 9 次。四份都是散文，都會被後續 session 載入。

`AGENTS.md` 與 `.opencodereview/rule.json` 也是雙抄——`AGENTS.md` 第 7 條自己承認
「兩處同源，同一個 commit 一起改」。這正是專案「單一來源規則」禁止的事，規則沒有套用到規則自己身上。

### 洩漏三：文件沒有壽命，只有出生

- 交接筆記的讀者只有下一站。下一站做完就沒有人再讀，但它永久留在會被載入的檔案裡，
  已經長到 `docs/v4` 的 43%。
- `README.md` 的「現況」段是一段隨站數滾動增長的長句（4,690 bytes），每站追加，從不裁切。
  它記的內容狀態表已經有了。
- `CHANGELOG.md` 37 條、`WORKLOG.md` 102 條，都是月級以上的歷史，沒有封存線。

## 三、沒有意義、可以直接砍掉的消耗

依「省下的 token × 施作成本」排序：

1. **`README.md` 全檔載入**（省約 12,000 / 站）。開工只需要單站切片。
2. **`AGENTS.md` 的 path-scoped 工程規則**（省約 2,400 / 站）。條件語言、modifier 效果鍵、
   單一來源三節只在動到那些檔案時有用，卻每 session 全量注入，而且 `rule.json` 已有一份。
3. **`CLAUDE.md` 的 RTK 完整指令表**（省約 1,100 / 站）。核心規則只有三條
   （一律加 `rtk`、鏈中每段都加、要原始輸出用 `rtk proxy`），其餘是查得到的工具文件。
4. **規格書大段讀**（省約 5,000–10,000 / 站）。指名章節已經寫在說明書裡，缺的只是切片器。
5. **過期交接筆記**（省約 2,000 / 站，並縮小整個 `docs/v4`）。
6. **`README.md` 現況段**（省約 1,200 / 站）。狀態表已涵蓋，敘述是重複。
7. **審查包的未追蹤檔全文**（不定，尖峰很高）。`station-review.mjs` 對未追蹤檔附全文，
   新增大檔時會整檔進上下文。

合計每站可省 24,000–28,000 token，即固定前置的 **75% 以上**。

## 四、整套換掉還是改良

**改良，不要換。** 判斷理由：

貴的原因是上面三個洩漏，不是流程設計錯。流程實際交付的東西是有效的：68 站零回歸、
`npm test` 19,919 項、審查閘門是確定性的（委託模式不呼叫 LLM、不需 API key，本身幾乎不花錢）、
單一來源規則擋掉過四類實際 bug、S30／S36／S50 的「收斂站」模式證明可行。
整套換掉會把這些一起丟掉，換來的是重新踩一次同樣的坑。

流程層只有兩處值得動：

1. **加站規模上限**。「一 session 一站」保留，但說明書若估超過 400 行 diff 或跨 3 個以上模組，
   先拆站再開工。額度耗盡後的續接 session 要重付一次完整前置，是隱性成本最高的失敗模式。
2. **審查包瘦身**。未追蹤檔全文改為「超過 200 行只附前 100 行加結構摘要」。

## 四之二、散文的三種壽命（規格書 70,071 token 的處置）

規格書 3,757 行裡散文 1,609 行。問題不是「寫散文給 AI 讀」本身，是**三種壽命完全不同的
東西被寫在同一份檔、同一時間載入**：

1. **現行規則**——現在什麼是真的。每站都要，該短。
2. **不變式**——什麼不准被破壞。該被**執行**，不該被讀。
3. **決策理由**——這個數字為什麼是這個數字。只有要**改**它的時候才需要，約二十站有一站。

正文 70,071 token、附錄「決策紀錄摘要」#1–#86 另計 5,667 token，三種混在一起，所以每站三種全付。

### 不變式改成測試，不是散文

全檔 40 行 ⚠ 警示，只有 13 行提得出守它的測試。**四分之三的警告沒有任何東西在守。**

有守的那幾條證明了正確形狀：`coaches.js` 檔頭指名 `tests/kernel/coaches.mjs` 守戰力點平均 2.0；
§5.2 錯位輪替指名 `tests/kernel/training.mjs`。這兩條在正文只需要一行加一個檔名——真正
攔住錯誤的是紅燈，不是句子。

規則：每一段 ⚠ 要嘛指得出守它的測試（壓成一行），要嘛指不出（那它根本沒被保護，補測試）。
測試檔平常不進上下文，壞掉才讀，常駐成本零。

### 理由外部化，改成按需拉取

附錄 #1–#86 就是 ADR，機制已經有了，但它與正文同檔，而且正文把同一套理由再講一次。
以 #79 為例，`OPPONENT_SUPPORT_RESIDUAL` 在規格書出現 11 次、`WORKLOG.md` 4 次、
`CHANGELOG.md` 4 次、站說明書 2 次。

做法：正文理由段刪除，只留「理由見 #79」；決策紀錄搬去 `docs/spec/decisions.md`，
**預設永不載入**；切片器只在該站說明書寫明要動那個常數時才拉對應條目。

方向反轉是關鍵——理由現在是「以防萬一」推進上下文，該改成「真的要動它了」才拉。

### 數字的家是 `src/data/*.js`，不是規格書

`coaches.js` 檔頭已經是正確示範：講清楚為什麼從一個數字改成六種機制、警告 2.0 硬約束、
指名守門測試、解釋 `offerPenalty: false` 是免疫寫法。理由住在唯一會改它的人一定會打開的
檔案裡，只有那個人付 token。規格書不必重述，只留系統形狀與生成的表。

### 可直接刪的散文

- 歷史沿革與轉址 40 行（「原 §5.5 邊界已廢除，已移至 §14.8」）——會永遠累積，git 裡有。
- 站號提及 361 處——規格書不該知道 S46、S49 是誰。站號是排程狀態，屬於狀態表；
  「六選一（S46 定案）」把規格和工期混在一起了。
- 重述程式碼 17 處（「實作上覆盤的 id 是 `vod`」）——grep 兩秒的事。

⚠ **別砍過頭。** 68 站沒走鐘靠的就是這些理由。沒讀過「戰術覆盤 vs VOD 研究是刻意的鏡像
對」的 agent，會很樂意把兩個看起來重複的選項合併並稱之為簡化。目標不是少寫理由，是讓理由
**在危險發生的那一刻才出現**，而不是每站預先躺在上下文裡等一個大概不會來的用途。

## 四之三、能用腳本做的不要給模型

**判準一：這件事有沒有唯一正確答案。** 有，就是腳本的工作。
**判準二：這個提示如果被忽略，誰會發現。** 沒人發現，它就不是保護，只是安慰。

腳本不只省 token，是省錯誤——腳本不會忘、不會漂移、失敗會叫。

### 實例一：雙註冊表同步（已經有測試，卻還在付提示費）

`AGENTS.md`「條件語言規則」561 token ＋「Modifier 效果鍵規則」418 token ＝ 979 token，
每 session 注入；`.opencodereview/rule.json` 再講一次（`PREDICATES`／`COND_NODES`／
`EFFECT_KEYS` 各出現 2 次），審查時三度注入。

而 `tests/kernel/conditions.mjs` 第 139–155 行**早就在守**：`QUERIES` 與 `PREDICATES`
雙向差集、`COND_KINDS` 與 `COND_NODES` 雙向差集；`tests/kernel/traits.mjs` 守反向死鍵；
`tests/kernel/coaches.mjs` 守戰力點平均 2.0。

979 token × 68 站 ≈ **66,600 token，買的是一件 `npm test` 0.8 秒就會抓到的事**。
處置：`AGENTS.md` 這兩節刪除，只留一行「雙註冊表由 `tests/kernel/conditions.mjs` 守，
漏一邊會紅」。

### 實例二：狀態表（腳本已存在，全檔讀卻沒撤掉）

`docs/v4/next-station.mjs` 166 行，已經解析站 id／名稱／文件路徑／狀態／前置／難度／
建議模型，還做前置完整性檢查與依賴解算——確定性的部分它全做了。但 `donggong` skill
第 2 步仍要求讀 `README.md` 全檔 12,882 token。**腳本寫了，全讀沒撤。**

### 實例三：收尾的機械動作

- 狀態表把該站改「完成」＝一個字串替換，應是 `next-station.mjs --done S49`，
  現在要為此把 12,882 token 的 README 再讀進來一次。
- `CHANGELOG.md` 條目可由 commit 訊息與版號生成，不必手寫。
- 血緣 A／B 批查詢是查表，不是判斷（見第四階段）。

### 已經做對的示範：OCR 委託模式

`scripts/station-review.mjs` 的切法是全專案最佳實踐——**確定性工程給腳本**（檔案篩選、
規則解析、`npm test` 閘門、diff 組裝，全程不呼叫 LLM、不需 API key），**語意判斷給 agent**
（逐檔審查意見）。這個切法沒有推廣到別處，是本次檢討最直接的可複製資產。

### 腳本清單

1. `next-station.mjs --brief <站號>`：擴充既有解析器，輸出完整開工簡報，取代六檔全讀。
2. `next-station.mjs --done <站號>`：機械更新狀態表。
3. `scripts/spec-slice.mjs §5.3 §7 §20.2`：按 § 切規格書（約 30 行，併入第 1 項）。
4. `scripts/gen-spec-tables.mjs`：從 `src/data/*.js` 生成規格書表格區塊，加測試比對。
5. `scripts/changelog-from-commits.mjs`：`CHANGELOG.md` 不手寫。
6. `scripts/context-budget.mjs`：量測前置 token，超線非零退出。

### 留給模型的（刻意不腳本化）

`WORKLOG.md` 條目的「方向」段、校準站「破帶才有授權」的判讀、站的拆法與範圍、
版本級別 X／Y／Z 的判斷、審查意見本身。這些需要理解意圖，腳本化只會產出正確格式的廢話。

### 給 `AGENTS.md` 的長期防再膨脹規則

> 任何要寫進 `AGENTS.md` 的規則，先問能不能用測試守。能，就寫測試，`AGENTS.md` 只留
> 一行指路。規則檔的成本是「每 session × 每站」，測試的成本是「壞掉時才付」。

## 五、方案

### 第一階段：前置瘦身（約 1 站工作量，立即見效）

1. `AGENTS.md` 砍到 40 行以內，只留不隨檔案變動的內容：收尾流程順序、commit 格式、
   版本編號規則、回覆風格、動工規則、rtk 三條。
2. 條件語言、modifier 效果鍵、單一來源三節從 `AGENTS.md` 移除。其中**雙註冊表同步已由
   `tests/kernel/conditions.mjs` 第 139–155 行實際守著**（見四之三實例一），
   直接刪成一行指路即可，不必搬家；其餘 path-scoped 的規則移進
   `.opencodereview/rule.json`（本來就是該格式），由審查閘門與第二階段的簡報腳本
   按「本站要動的檔案」注入。消掉雙抄，每站省約 979 token。
3. `CLAUDE.md` 整份刪除、`AGENTS.md` 的 rtk 規則一併刪除，改裝 `rtk init -g` 的
   自動改寫 hook（rtk 本身提供，宣稱所有對話與子 agent 100% 採用）。兩處合計約
   1,435 token／session，買的是「讓 agent 記得多打四個字元」，hook 做同一件事
   且不會漏。裝不了 hook 時才退回留三條核心規則。
4. 新增 `scripts/context-budget.mjs`：算出下一站前置的 token 估算，超過 10,000 就非零退出。
   預算從此可測，不靠感覺。
5. `AGENTS.md` 加一條防再膨脹規則：任何要寫進規則檔的約束，先問能不能用測試守；
   能，就寫測試，規則檔只留一行指路。規則檔的成本是「每 session × 每站」，
   測試的成本是「壞掉時才付」。

### 第二階段：切片載入（約 1 至 2 站工作量，收益最大）

6. **擴充既有的 `docs/v4/next-station.mjs`**（166 行，已經解析站 id／名稱／文件路徑／狀態／
   前置／難度／建議模型，並做前置完整性檢查與依賴解算）成 `--brief <站號>`，取代
   `donggong` skill 第 2、3 步的六檔全讀。腳本已經寫好了，全讀卻沒撤掉——先撤全讀。
   輸出單一份簡報：
   - 該站狀態表那一列，加各前置站交接筆記的「給下一站」小節；
   - `00-共通規則` 只輸出該站難度與分類相關的節；
   - `00b-穩定點快照` 只輸出基準座標與紅線數字；
   - 依說明書「必讀規格」欄位，按 § 從 `ESPORT-DESIGN-V4.md` 切出指名章節；
   - 依「要動的檔案」從 `rule.json` 帶出對應規則。
   目標：前置壓到 8,000 token 以下。
7. 加 `next-station.mjs --done <站號>`：機械更新狀態表，不必為改一個字把 12,882 token
   的 README 再讀一次。
8. `ESPORT-DESIGN-V4.md` 拆成 `docs/spec/§NN-*.md`，主檔只留目錄；附錄決策紀錄 #1–#86
   獨立成 `docs/spec/decisions.md`，**預設永不載入**，只在該站要動對應常數時由切片器拉。
   26 個 `##` 節就是天然切線。切片器與人工閱讀都受益。
9. 不變式測試化：全檔 40 行 ⚠ 逐條過一遍，指得出守門測試的壓成一行加檔名，
   指不出的補測試。現況只有 13 行提得出測試（見四之二）。
10. 新增 `scripts/gen-spec-tables.mjs`：規格書 664 行表格改由 `src/data/*.js` 生成
    （`<!-- gen:COACHES -->` 區塊），加測試比對生成結果與檔案內容。消掉手抄第二份。
11. 改寫 `.opencode/skill/donggong/SKILL.md`：第 2、3 步改為「跑 `next-station.mjs --brief`，
    讀它的輸出」。skill 本身也順勢縮短。

### 第三階段：文件收斂（約 1 站工作量）

12. 定四抄的單一來源：
    - 交接筆記是唯一的站級事實來源（下一站真的會讀它）；
    - `README.md` 狀態表只留機器可讀欄位，「現況」段刪除，需要時由腳本從狀態表生成；
    - `WORKLOG.md` 每條上限 15 行，只寫意圖與脈絡，實作細節指向交接筆記；
    - `CHANGELOG.md` 由 `scripts/changelog-from-commits.mjs` 從 commit 訊息與版號生成，不手寫。
13. 交接筆記加壽命規則：後續站完工後，把該站交接筆記壓成「給下一站的輸入」與「刻意沒做」
