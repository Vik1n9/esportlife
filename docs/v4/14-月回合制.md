# S14 · 月回合制

狀態：未開始
前置：S13
預估：1 session
推理難度：**高**
建議模型：Opus 5（`claude-opus-5`）
理由：架構級改動。主迴圈、年曆展開、階段協定三者要同時換粒度而不破壞

`phases/*` 全部要改。降級的風險是硬把月迴圈塞進 `runYear` 裡，變成一個誰都不敢碰的
巨型函式。

---

## 為什麼做這件事

現行是**年回合**：一年一次 `phaseTraining`（擲骰加點），然後 `calendarFor` 展開賽段。

V4 §3.2 要**月回合**：每月選一個行動（訓練活動／英雄池練習／休息／復健），一年約 12
個養成回合＋賽事事件序列。這是賽馬娘式節奏的骨架——沒有它，設施制訓練（S16）與體力
管理（S13）都沒有施展的空間。

V4 §3.3 的單年結構：

| 月份 | 階段 | 回合類型 |
| --- | --- | --- |
| 1 月 | 休賽期 | 養成回合（轉會/續約/集訓） |
| 2–3 月 | 春季常規賽 | 養成回合 ×2 |
| 3–4 月 | 春季季後賽 | 事件序列 |
| 5 月 | MSI（若出線） | 事件序列 |
| 5–8 月 | 夏季常規賽 | 養成回合 ×3 |
| 8–9 月 | 夏季季後賽 | 事件序列 |
| 10–11 月 | 世界賽（若出線） | 事件序列 |
| 12 月 | 休賽期 | 養成回合 |

## 範圍

### 要做

**必讀規格**：V4 §3（時間結構與回合制）、§4（回合執行序列）、§19（DEMO 範圍）。

**1. `src/engine/calendar.js`：order 空間從賽段序換成月序**

現行 `calendarFor(state, leagueKey)` 把一年展開成依 `order` 排序的階段清單。
機制對，粒度不對。

改成：一年展開成 12 個月的清單，每個月標明是**養成回合**還是**事件序列**，
賽事插在對應的月。

⚠ **賽區差異要保住。** `data/regions/*` 的 `splitsOf(year, region)` 說明各賽區各年
有幾個賽段（1~3 段），MSI 接在第幾段之後也因區而異。月序表要能表達這些差異，
不能寫死成 §3.3 那張表——那是「兩賽段賽區」的樣子。

做法建議：保留「賽段 → 月份區間」的映射，讓賽段數決定月份怎麼分配。
S05 若已重排過 `data/formats/calendar.js`，看它的交接筆記有沒有為這站鋪路。

**2. `src/engine/game.js`：`runYear` 拆成月迴圈**

現行結構：

```
runYear = divider → phaseTraining（年度加點）→ for (phase of calendarFor) → 年末
```

新結構：

```
runYear = divider → for (month of monthsOf(year)) → 依 month.kind 分派 → 年末
```

`month.kind` 分兩類：養成回合交給新的 `phases/month.js`，事件序列交給既有的
`phases/*`（`split`、`msi`、`worlds`…）。

**保住依賴方向**：`phases/*` 不 import `engine/game.js`。主迴圈認得階段，階段不認得
主迴圈。這條線斷了瀏覽器 ESM 會直接爆。

**3. 新增 `src/phases/month.js`**（V4 §4 的七步回合執行序列）

```
1. 顯示當月狀態（體力、屬性摘要、本月賽事預告）
2. 玩家選擇一個行動（訓練活動／英雄池練習／休息／復健）
3. 結算行動（屬性成長、體力消耗/恢復、成功率判定）
4. 事件判定（條件優先→隨機；固定 1 張，有機率 2 張）
5. 若有事件：呈現→選擇→結算
6. 若本月有常規賽：逐場列出結果（不互動）→結算影響
7. 推進到下一月
```

⚠ 第 2、3 步的**行動選單與成長結算是 S16**，第 4 步的**觸發引擎是 S17**。
這一站只搭骨架：先用暫時的行動選單（沿用現有的加點介面）與現有的 `drawEvents`，
各標 `TODO(S16)`／`TODO(S17)`。

**4. 刪掉 `src/phases/alloc.js`**

年度加點階段不存在了。

**5. `src/ui/runner.js` 與 `src/ui/board.js` 的 phase index**

現行是 `0=訓練 / 1=賽季 / 2=休賽期`（一年三段）。月回合下這個劃分沒意義了，
改成月份推進的顯示。

**6. `src/phases/split.js` 拆分**

現行的 `SPLIT` 階段一次做完「例行賽 → 休息室 → 季後賽 → 事件卡」。月回合下：
- 例行賽結果分散到對應月份的第 6 步
- 季後賽變成獨立的事件序列（S15 會做成五拍結構，這站先維持現狀）

**7. 讓 S07 的「體力節奏」檢查真的有意義**

S13 讓它跑得動，這一站接上真正的月迴圈之後才驗得出「每 3–4 個月休息一次」。
數字不對就回頭調 S13 的曲線——那是允許的，記進交接筆記。
