## 範圍

### 要做

**1. NPC schema 定案**（§20 資料模型的延伸，不併入玩家 state）

- `npc_roster.json` 欄位：`player_id`（僅 ID，無真實姓名）、`team_id`（縮寫）、
  `birth_year`、`position`、`career`（效力戰隊年表＋賽事名次）、六屬性／潛力／
  `lifecycle`（peak_age／rise_k／fall_k）、技能、`psych` 六維、特質、敘事標籤。
- 資料檔標頭 CC BY-SA 出處註記格式。
- 玩家 state 是否新增欄位（例如隊友改存 NPC 引用）——定案後回寫 §20.2。

**2. §11.1 逐選手對手模型定案**

- 現況：對手是聚合強度（`kernel/strength.js`），團隊強度差 → 單局勝率。
- 定案：五名對手如何由 NPC 池構成（按位置抽？強度如何聚合回 §11.1 公式？）、
  明星項（`min(6.0, 0.06 × (P − par)^1.35)`）與對手強度階梯（MSI 地板 72／世界賽
  74）在新模型下的去留、160 段不變式怎麼改寫。
- 輸出必須是一份 S29 可以直接照做的規格，不是開放式討論。

**3. §14.3 百分位改法定案**

- 兩條暫代路線改回百分位：究極綠葉「助攻前 10%」、網紅選手「評分低於中位數」。
- 定案：母體定義（全部選手？同年齡段？同賽區？）、由 `cleaned_players.json` 的
  哪些欄位算、門檻怎麼寫進引擎（靜態查表或函數）。
- §21.3 的登記條目與附錄 #32 在此站關閉。

**4. 隊友池規則定案**（S28 輸入）

- 隊友從 NPC 池抽選的規則：按年代（史實出場年）過濾？按位置？與現行
  `rollRoster`（`MATE_NAMES` 隨機抽 4 人配 rating）的關係——取代還是共存？
- `MATE_NAMES` 的去留決定。

**5. 探勘風險預先定案**

- GPL 早期（2012）Liquipedia 覆蓋稀薄時的 Leaguepedia 備援規則：何種缺口觸發
  備援、備援資料的標記方式（S24 依此執行）。

### 不要做

- **不推翻 §23.1 的四件定案**（一次到位、去姓名、Liquipedia 主源、LLM 語意離線快取）
- **不寫爬蟲、不碰程式**。純文件站——產出是 §23 細部規格與受影響節的回寫
- **不刪 §21.3 與附錄的歷史登記**——關閉條目時標記已定案，不抹掉痕跡

**定案清單（每條的消費站見規格 §23.8 消費表）**：

1. **Schema（23.3）**：遊戲資料一律 ESM `.js`（`src/data/npc/{roster,percentiles}.js`），
   中間 JSON 只住 `tools/npc/`——全 repo 沒有任何 JSON import，別開先例。
   `peak.rating` 是唯一強度骨幹；**刻意不存 potential 與技能值**（NPC 不成長、
   技能依 §8 權重現算——存了就是第二份手抄本）。`fetch_priority 2` 範圍定案
   （歷年 Worlds／MSI 參賽隊員 ＋ 四大賽區歷年賽段冠軍隊員）。
2. **逐選手對手（23.4）**：定案是「身分實體化」——**階梯表仍是對手強度唯一來源**，
   NPC 陣容是階梯水準的具象，不是新強度來源。這是刻意保守：頂端落差餘裕只剩
   0.082（00b 快照），強度數學亂動會在 160 段之外才現形。`OPPONENT_SUPPORT` 9.0
   拆成顯式對手明星項＋carry 份額＋殘項，**殘項起始 3.5 不是定案，終值歸 S30**。
   ⚠ S29 注意：選隊池要排除玩家自己的隊（季後賽不自己打自己）；`intlBoost`
   掛鉤預留 0 給辛組。
3. **百分位（23.5）**：究極綠葉吃同位置全年代母體 P90 場均助攻；網紅選手改讀
   `peakRating` 對歷史母體中位數——**`careerScore` 條件退役**，理由是它是遊戲
   內部量、歷史資料沒有對應欄位（這點 00b 的「兩套母體並存」不變：史實母體仍歸
   §14.3 路線吃）。S26 要記得 trigger 與 goal **兩端**都改（暫代門檻出現兩次），
   母體 < 100 的位置留絕對門檻。
4. **隊友池（23.6）**：`MATE_NAMES` 退役（十二名全是真實選手 ID，進 NPC 池當
   `player_id`）；業餘期換虛構名池。隊友 rating 窗口 par±7 漸寬到 ±14 不空手。
   `state.mates` 擴 `{ npcId, name, position, rating }`，**SAVE_VERSION 歸 S28 bump**。
5. **備援（23.7）**：Liquipedia → Leaguepedia → synthetic 三級，逐筆標
   `data_source`；GPL 2012–2013 預估最薄，S24 探勘報告要附實測覆蓋表。
