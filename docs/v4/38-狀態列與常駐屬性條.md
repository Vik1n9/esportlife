建議模型：Sonnet 5（`claude-sonnet-5`）
理由：規格已由 S37 細化到可施工粒度，判斷成本低。但**本站是壬組的骨架站**——

## 為什麼做這件事

§22.1 的狀態帶四列與 §22.5 的常駐屬性條從未實作。現行狀態帶是四個數字格
（年齡／年份／核心技能／生涯薪資），其中：

- **體力看不到**——體力是玩家要主動管理的資源（§6），排訓練時得先開面板才知道
  還剩多少。這是 §0.5 防農檢驗直接禁止的事（附錄 #76）。
- **屬性看不到**——只在屬性點分配那幾秒出現，決策時讀不到成長餘裕（§7.1）。
- **核心技能格違反 §22.1**「決策不提供技能讀數」：技能是導出值（§8.2），
  印在常駐區就等於給了一個可最佳化的總分。
- **沒有階段與倒數**——「距季後賽 3 月」是體力節奏（§6.1）的規劃資訊。

## 範圍

### 要做

**1. 新引擎輔助 `nextStageIn(state)`**（`src/engine/calendar.js`）

- 讀既有的 `calendarFor(state, state.league)`（回傳 `{kind, month, order, …}[]`）。
- 回 `{kind, month, monthsAway}`；當年已無下一階段時回 `null`。
- **純函式、DOM-free**——照 `ARCHITECTURE.md`「引擎不知道 DOM 存在」的分工。
  不在 UI 層算月份，因為倒數要進測試。

**2. `#board` 改成五列**（`index.html` ＋ `src/ui/board.js`）

```
列1  選手ID·位置·年齡 ｜ 年.月 · 階段 ｜ 距下階段倒數 ｜ ☰ ↺
列2  體力條 ＋ 區間標籤 ＋ 短期效果／受傷
列3  賽區 ｜ 隊伍名 ｜ 排名 —（資料待接）
列4  生涯任務指示（無任務時整列折疊，§22.5）
列5  12 月進度（沿用現行 #lamps）
```

- **移除核心技能格**（修 §22.1 違規）。技能讀數唯一落點是選手 tab（§22.3），
  該 tab 由 S40 建；在 S40 完成前技能值暫時只在現行面板可見，可接受。
- **移除生涯薪資格** → §22.3 明訂它屬選手 tab 的「薪資」列；同樣在 S40 落地。

**3. 常駐屬性條**（新檔 `src/ui/attrbar.js`）

- 六格「現值／潛力／蓄力」，三欄 × 兩列 grid。
- **緊貼行動列上方**（§22.1：兩者同屬拇指區，中間不得插入其他區塊）。
- 有可分配點時右上出現 `〔+N〕` 入口，點擊進現行屬性點分配流程。
- 匯出 `highlightAttrs(keys)` 供 S39 的訓練選項連動。

## 規則與不變式

- **`.abrow.mini` 必須掛 `.static`**：它是唯讀回饋，不是可按的控制項
  （`DESIGN.md` 原則 6：玩家碰得到的與碰不到的要看得出差別）。
- **狀態帶不得出現任何技能值**（§22.1）。
- **心理六維與教練評價不得顯示**（§22.4）。聲量是例外。
- `nextStageIn` 必須是純函式且 DOM-free。
- `src/styles.css` 檔頭的「鐵則」註解區塊不得失效；新增規則要一起補進去。

## 完成定義

- `nextStageIn` 有**先紅後綠**的新測試（AGENTS.md：新測試要先紅過才算守得住），
  涵蓋：賽段中／季後賽當月／MSI 年與非 MSI 年（`monthLayout` 的 `msiMonth` 分支）／
  12 月無下一階段。
- `npm test` 全綠。
- **手動走查**（`npm run serve` → <http://localhost:8080>；⚠ 引擎測試完全不碰 DOM，
  這是本站唯一守門）：
  1. 開局 → 連走三個訓練月：體力條、階段、倒數、月進度每月都更新。
  2. 屬性條六格常駐可見，蓄力刻度隨加點變動；`〔+N〕` 只在有可分配點時出現。
  3. 有生涯任務時第四列展開、無任務時整列折疊。
  4. 狀態帶**找不到任何技能數字**。
  5. 跑到季後賽月：倒數歸零、階段名切換正確。
  6. 重整頁面 → 「繼續上次的生涯」接得回（`localStorage` key `esportlife.save.v4`）。
