## 為什麼做這件事

V4 §15.5（v4.1 新增）。這是一個純網頁、無局外成長的遊戲——**一局結束就什麼都不留**。
§1.3 又寫明「大部分 run 是平庸／邊緣選手」。兩件事加起來，平庸局的結算畫面現在只是
一堆沒破門檻的數字。

§14.3 的替代性路線給了平庸局**機制上的終點**；這一站給的是**敘事上的收束**：
把「什麼都沒拿到，但在同一支隊待了九年」寫成一段有份量的文字。

> ⚠ **v4.3 增訂**（§20.2）：資料來源擴充 `lifecycle`（生命週期參數，巔峰／衰退的
> 年齡軌跡）與 `traitGraph`（特質持有與合成狀態）——「巔峰」「轉折」段可讀曲線，
> 不必再用 age 猜。§14.3 五條 route 路線的敘事出口由 S18 補卡後可用，本站讀 S17a
> 帳本與 S17b 的 `labels[]`（route 標籤）。

## 範圍

### 要做

**必讀規格**：V4 §15.5。

**1. `src/engine/biography.js`（新檔）**

段落模板 × 事實填空。**沒有 LLM，沒有隨機文案**——同一段生涯必定產出同一篇傳記。

資料來源**限定**在：

- S17a 的帳本：`milestones[]`、`teamHistory[]`、`awards`、`intlRecord`、`disbandCrises`
- `honors[]`
- 四階特質 ＋ 天生特質 ＋ `fusedAway`
- S17b 的 `labels[]`（`route` 標籤與失敗降階的標籤）

⚠ **不讀隱藏心理六維**。六維到結算都還是不可見的（§9.1）——傳記寫出來就等於揭底，
把整個「因隱藏、果可見」的循環一次報廢。

**2. 五段結構**

出道 → 巔峰（或「沒有巔峰」）→ 轉折 → 結局 → 歷史定位一句。

每一段都要能在**事實不足時退化**而不是留空：沒進過國際賽就寫沒進過，不要跳過那一段。
這是驗收線「不出現空欄位或佔位符」的實際意思。

**3. 兩種語氣**

§15.5 給了兩個方向：「電競新聞報導」與「維基百科式」。挑一種做完，另一種寫進交接
筆記留給後續——**不要兩種都做半套**。

建議先做維基百科式：它容忍事實稀疏（平庸局正是事實稀疏的那一種），新聞體裁需要一個
「戲劇性主軸」，平庸局常常沒有。

**4. 平庸局優先驗收**

模板覆蓋率**以生涯評分後 50% 的 run 為準**。冠軍局本來就有一堆榮譽可寫，真正需要
傳記的是另外那一半。

**5. 接進 `src/ui/summary.js`**

現有的結算畫面已經有分享種子與分享圖，傳記接在同一個區塊。

### 不要做

- **不要讀隱藏心理六維**
- **不要生成隨機文案**。同一段生涯必定同一篇
- **不要新增遊戲數值**。傳記是純輸出，不回頭影響任何判定
- **不要動 `engine/career.js` 的評分**
- 不要兩種語氣都做

## 規則與不變式

- S07 不變式全綠（這一站不動任何判定，紅了就是接錯地方）
- **確定性**：同一個 state 跑兩次，輸出字串完全相同
- **無佔位符**：160 段生涯的傳記掃過去，不出現 `undefined`／`{}`／空段落
- **不讀六維**：`grep -n "mental" src/engine/biography.js` 應該是空的
- **後段局覆蓋率**：生涯評分後 50% 的 run，每一段都寫得出至少四段
