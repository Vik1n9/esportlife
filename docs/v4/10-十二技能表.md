（L1 0.034、最扁 TOP 前二 0.409、SUP agi 0.100、ADC/SUP 只有 1.79 倍）。

### 二、⚠ 唯一改到測試的地方：巔峰上界的母數（是換單位，不是放寬）

換完表跑第一次時 `巔峰上界：沒有任何一段生涯超過突破後的硬上限` **紅了一項**
（160 段裡 2 段，最高 101 > 100）。查下去不是通膨，是那條檢查的母數寫錯了：

- 它量的 `peakOvr` 是 `ovr()` 的輸出，而 `ovr()` ＝ 屬性加權平均 **＋ §10.2 的加法特質
  修正**（神之領域 +2、不老傳奇 30 歲後 +1），母數卻只寫了屬性硬上限 100。
- 舊表下沒人碰得到那條線：六個屬性都有 OVR 權重，要把加權平均練到 99 等於六格全滿。
  S10 之後 `vit` 權重歸零，打野／輔助的 awr＋syn＋dec 佔到 **0.967／0.970**——三個屬性
  練滿就是 99，神之領域持有者再 +2 就越線。兩段紅的都是神之領域持有者，屬性長相是
  `awr 100 / syn 100 / dec 98~100`。
- 所以這與 S09 為「加點是決策」換分母是同一類修正：**門檻對權重表免疫，但對特質持有
  不免疫**。改法是把上界寫成 `硬上限 ＋ §10.2 允許的加法修正`，而且那個 3 是**掃特質
  資料表算出來的**，不是手填——哪天有人違反 §10.2 加了第三個 `ovrAdd`，上界會跟著鬆，
  那是 code review 該看到的訊號。
- **通膨真正的守門員（平均巔峰 ÷ 上限 ∈ 0.68–0.82）一個字沒動，而且是綠的。**

如果下一站的人認為這個修正不該做，回退方式是把 `hardCeiling` 換回 `ATTR_CAP_GODHAND`；
那樣就要接受「§10.2 明文允許的 +2 會讓檢查紅」這件事。

三件事值得下一站知道：

1. **S09 交接筆記第七節那個缺口被關掉了。** S09 說頂端訊號餘裕掉到 0.078–0.130、
   `alt-*` 的 0.0777 已在門檻 0.08 之下、四組會誤報一組。換表之後四組全在門檻之上
   （最低 0.0947）。**不是因為調鬆，是訊號真的回來了**。
2. **「加點是決策」從擦邊變成有餘裕**（0.059–0.073 → 0.133–0.218，門檻的 2.9–4.7 倍）。

   撒——「投錯格子」的浪費回來了。這是 S09 兩條修法之外的第三條路，而且是規格書自己
   帶來的。
3. **平均巔峰上移約 +0.02（比例）。** 同一個機制的另一面：能長的方向少一個，同樣的
   訓練預算換到更多加權後的成長。**但這不是通膨**——S09 的四組裡有兩組（.7178／.7236）
   低於 §17.2 的驗收帶 0.735–0.775，S10 之後**四組全部落在帶內**。也就是說換表把分布
   推回規格書要的位置，`GROWTH_BASE` 不需要跟著動（也不該動，那是 S09／§5.3 的旋鈕）。

`seed-*` 這一組的其他數字（給 S11 對照用，S11 說明書點名要比）：
