# 內容編輯器（tools/）

開發者工具，**不是遊戲的一部分**。寫事件卡／特質卡／生涯任務卡／合成配方／天生特質
用。遊戲不從任何地方連到這裡，`index.html` 沒動。

## 開法

```bash
npm run serve
```

開 <http://localhost:8080/tools/>。頁面直接 import `src/data/*.js` 填下拉選單、
載入既有條目——所以工具**永遠跟遊戲資料同源**，欄位可選值不會對不上。

## 五個分頁

| 分頁 | 資料 | 規格 |
| --- | --- | --- |
| 事件卡 | `src/data/events.js`（一般事件卡）＋ `src/data/trainingCards.js`（訓練事件卡） | §12.2／§5.4 |
| 特質卡 | `src/data/traits.js`（通用＋稀有）＋ `src/data/epics.js`（史詩＋傳說） | §13／§14.1 |
| 任務卡 | `src/data/quests.js` | §12.3 |
| 配方 | `src/data/epics.js` 的 `FUSIONS` | §14.6 |
| 天生特質 | `src/data/innate.js` | §14.1 |

## 每欄的意思

- **四池**（persona／performance／psych／career）：事件卡與特質卡共用同一套
  （§12.2）。psych／career 不入合成。
- **時段標籤**：觸發的前置過濾器。不匹配當下時段的卡連候選池都進不去。
- **互斥群組**：同一回合的兩張卡不得同組；`solo_<id>` 表示自成一格。**必填**。
- **條件式**（任務卡的 trigger／goal）：`['and', ['stat', 謂詞, 比較子, 值], ['has', 階, 鍵]]`。
  工具驗**語法與謂詞名**，不驗形狀——形狀由 §12.3 條件式自由組合。
- **效果**（特質的 effects／sideEffects）：`kernel/modifiers.js` 的四種寫法
  （數字簡寫＝加法、`{mul}`／`{floor}`／`{cap}`／`true` 旗標）＋§7.2 六窗口。
  副作用與益處共用同一組鍵，方向相反。
- **maintain（維持條件）**：特質分頁的維持條件欄位。舊資料裡它是函式
  （`data/traits.js` 的單身／圈內毒瘤）——載入檢視時放行，產出時原樣保留；
  新寫的請用條件式陣列。

## 關係檢查（右上角按鈕）

橫跨資料掃五類問題（§14.8）：

1. **素材競態**：一個素材被多條配方共用。池內共用是設計上的取捨（同階配方爭奪素材），
   跨池共用（同一素材同時被稀有與史詩配方引用）才是錯誤。
2. **死配方**：素材沒有可達取得路徑。可達來源＝事件卡（FLAG_TRAIT）、扮演卡
   （PERSONA_RULES）、生涯條件（veteran／single／disc）、天生特質池、其他配方產出。
   ⚠ 工具只查「有沒有來源」——取得率 ≥15% 的實測線在 S19c 用 160 段生涯驗收。
3. **觸發斷裂**：事件卡旗標指向不存在的特質鍵、任務卡條件式引用不存在的謂詞或素材鍵。
4. **效果鍵被引擎消費**：特質宣告的效果鍵不在 `schema.js` 的 `EFFECT_KEYS`＝打錯鍵，
   特質會靜靜地沒有效果。
5. **池指派完整**：特質都有池歸屬（未指定預設 persona）；psych／career 不入合成。
6. **天生特質池上限**：≤ 5（§14.1，0.8 ÷ N ≥ 15% 死線）。

## 合成圖譜（右上角按鈕）

力導向佈局（自製模擬，零相依），展示「下層素材 → 上層產物」的合成樹。節點顏色
= 階級（common 灰／rare 藍／epic 紫／legend 金）。

## 產出怎麼貼回去

1. 編輯完成後按「複製片段」或「下載 .js」。
2. 把片段貼進對應資料檔的陣列／物件裡（排版與既有檔案一致：2 空格縮排）。
3. 跑 `npm test`——工具產出的卡片要能過全部測試。
4. ⚠ 貼回去時**留意既有卡片的結構**（欄位名、效果寫法），工具的 schema 是權威，
   遊戲引擎的消費端在 `src/engine/*`。

## schema 改了動哪裡

欄位描述集中在 `tools/schema.js`。**改 schema 只改這一個檔**，不要動 `editor.js`
的表單邏輯。

⚠ 兩個同步點（新內容會踩到）：

- **新增效果鍵**：`src/kernel/modifiers.js` 的消費端＋`schema.js` 的 `EFFECT_KEYS`
  要一起加——否則工具會把新鍵標成「不被引擎消費」。
- **新增謂詞**：`src/engine/conditions.js` 的 `QUERIES`＋`schema.js` 的 `PREDICATES`
  要一起加——否則條件式驗證會擋掉新謂詞。

## 產出的假卡測試

完成定義第 4 項：「產出一張事件卡＋一個特質，貼進資料檔，`npm test` 全綠，然後
移除」——那是人工驗證步驟，工具本身不寫檔（無 File System Access API、無後端）。
