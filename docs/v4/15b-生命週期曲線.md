# S15b · 生命週期曲線

狀態：未開始
前置：S09 S14
預估：1 session
推理難度：**高**
建議模型：Opus 5（`claude-opus-5`）
理由：成長與衰退統一成同一條曲線之後，六屬性各自帶五個參數（peak_age／rise_k／fall_k／
fall_accel／decline_pull）——每個參數的隨機範圍都直接決定「幾歲到巔峰、多久衰退、
衰退多急」。錯誤要到 160 段生涯的終局分布才看得出來（巔峰年齡、退役年齡、老將存活率），
不是 `npm test` 當場紅。這是 v4.3 四根柱子裡唯一「兩端平衡一起動」的一根。

---

## 為什麼做這件事

V4 §7.2 把「固定年齡衰退表」換成**統一生命週期曲線**。

現行（S09 的產出）是寫死的三件事：

- 30 歲起算衰退，agi／vit／tec 每年降、awr／dec 續升、syn 不動
  （`src/data/attributes.js` 的 `DECLINE_*` 表 ＋ `src/engine/attributes.js` 的
  `applyAgeDecline`）
- 退役硬上限 34（`retirementAge`），特質用 `retireAge` 抬到 36～41
- 掛載禁令的「直接加值」：神之領域 +2 教練評價、不老傳奇 30 歲後 +1、突破上限

這三樣是棒球版的遺毒——衰退是斷崖不是漸進、老將靠意識吃飯是寫死的特例、退役是硬
截止不是市場淘汰。v4.3 起：

1. **天花板曲線**：`effective_potential(attr, age) = base_potential × ceiling_curve(age)`
   ——成長與衰退是同一條曲線的兩面，屬性「現在的天花板」隨年齡起伏。
2. **衰退跟隨**：`annual_pull = (current − effective_potential) × decline_pull`，
   訓練可抵消一部分。曲線往下掉、屬性值被往下拉，自然而非斷崖。
3. **種子隨機化**：六屬性各抽 5 個參數（共 30 次），亂數流接在「業餘隊伍」之後。
4. **特質調整窗口**：特質不再直接加值，改透過六個預定義窗口（加法／乘法＋clamp）調整
   曲線參數。
5. **退役硬上限廢除**：曲線自然衰退，由市場淘汰（§18.1）與三層退役事件（§18.2）收束。

## 範圍

### 必讀規格

V4 §7.2（生命週期系統全節，含種子隨機化表與特質調整窗口表）、§7.1（潛力衰減，
微基準要重驗）、§7.3（起始屬性 k_i 讀 effective_potential 後重校）、§18.1（衰退與
市場淘汰）、§18.2（位置需求門檻）、§20.2（state.lifecycle）。

### 要做

**1. 天花板曲線 `effective_potential(attr, age)`**

```
effective_potential(attr, age) = base_potential × ceiling_curve(attr, age)
ceiling_curve(age) = age ≤ peak_age ? (age/peak_age)^rise_k
                                   : e^(−fall_k × (age−peak_age)^fall_accel)
```

六屬性的參數基準值與隨機範圍照 §7.2 種子隨機化表（agi 的 peak_age 22、awr 的 29……）。
「老將靠意識吃飯」從寫死特例變成 awr 的 peak_age 晚、fall_k 極小的曲線結果。

**2. 衰退跟隨**

```
annual_pull = (current − effective_potential) × decline_pull
實際衰退 = max(0, annual_pull − 訓練抵消量)
```

訓練抵消量留給 S16 接（成長的一部分），這一站先把 `annual_pull` 與「曲線下掉時屬性
被往下拉」的機制落地。**衰退在年度邊界發生**——年界由 S14 的月曆定位，所以前置含 S14。

**3. 種子隨機化**

六屬性 × 5 參數 = 30 次抽取，亂數流位置接在「業餘隊伍」之後（§7.2，§1.4 的 birth 流
尾端）。**不要再動前面的抽取順序**——動了就位移所有既有種子的天賦（S19d 那站已經
警告過一次）。

**4. 特質調整窗口（六窗口）**

| 窗口 | 類型 | clamp |
| --- | --- | --- |
| peak_age_shift | 加法 | [−4, +4] |
| rise_k_mul | 乘法 | [0.5, 2.0] |
| fall_k_mul | 乘法 | [0.3, 2.5] |
| fall_accel_mul | 乘法 | [0.5, 2.0] |
| decline_pull_mul | 乘法 | [0.4, 2.0] |
| growth_rate_mul | 乘法 | [0.5, 2.0] |

結算順序**先加後乘**，寫死。這些窗口是資料，不是程式碼——S19a 重建特質時把效果
宣告成窗口鍵，`kernel/modifiers.js` 的既有四種寫法擴一類「窗口」讀取即可。

**5. `state.lifecycle` ＋ `SAVE_VERSION`**

`state.lifecycle` 存六屬性的五個參數（§20.2）。`SAVE_VERSION` 加一。

**6. 廢退役硬上限 → 市場淘汰（§18.1）**

移除 `retirementAge`（34）與 `retireAge` 效果鍵的讀取。市場淘汰的引擎**已存在**
（`phases/transfer.js` 的 `FLOOR_RATING` 釋出、無報價→退役、減薪留下），這一站要做的
是**把硬上限拿掉**，讓「無報價 → 只剩退役」成為唯一收束。

**7. 位置需求門檻（§18.2 草案）**

教練評價低於最低聯賽 min 則無報價；位置不缺人時門檻 +4；先發合約剩餘 ≥ 2 年時 +6。
調整量待試跑，先照草案掛上、留可調常數。

### 重驗 S09 微基準

S09 的微基準（0.0260 對門檻 0.0375）是在**無年齡曲線**的 effective_potential 下量的。
曲線一加，天花板隨年齡起伏，§7.1 的級距冪 n 與 §7.3 的起始屬性 k_i 都要讀新函式
重校。收斂判準沿用 S09 的「平均巔峰 ÷ 屬性上限 = 0.755」（S07 不變式）。

### 不要做

- **不要動訓練成功率**（S16 的訓練事件卡）。這一站只動成長與衰退的「天花板」端
- **不要重建特質**（S19a）。窗口機制建好、舊鍵變死鍵就停手
- **不要動體力**（S13 定案，`formFactor` 中點與 §11.1 體力項是配著分布回推的）
- **不要動 `positionPower` 的乘法項**（S12 交接筆記第一節：動了要回來重算
  `OPPONENT_SUPPORT`）
- **不要改 §1.4 birth 流前面的抽取順序**（種子隨機化只接在尾端）

## 規則與不變式

- S07 不變式全綠。**特別盯「平均巔峰 ÷ 屬性上限 ≈ 0.755」**——曲線動了天花板，這一條
  最容易跑掉
- **同種子同曲線**：同 seed 跑兩次，`state.lifecycle` 六屬性參數完全相同
- **窗口 clamp 生效**：峰值偏移不得超出 [−4, +4]，衰退倍率不得超出 [0.3, 2.5]
- **衰退是跟隨不是斷崖**：曲線過峰後，屬性值應平滑收斂到 effective_potential，
  而不是在某個年齡一次掉一截
- **無硬上限**：`grep -n "retirementAge\|retireAge" src/` 輸出為空
- **掛載禁令加值清乾淨**：`grep -n "ratingAdd\|abilityCapUp\|epic.ageless" src/engine/`
  輸出為空（特質資料檔的死鍵除外，S19a 處理）
