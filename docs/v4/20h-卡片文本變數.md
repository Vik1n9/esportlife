# S20h · 卡片文本變數

狀態：未開始
前置：S20g
預估：1 session
推理難度：中
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：機制本身很小（填空函式已經存在，只是沒被匯出），難的是**降級路徑**——
一張採訪卡在「玩家沒有任何頭銜」的年份要說什麼。降級的風險是把變數做成可空、
於是玩家某天讀到「作為 ，你有什麼話想說？」。

> ⚠ **編號非字母序**：本站是 PR #16 第二輪審查後追加的，排在 S20g 與 S20d 之間。
> 依賴關係以狀態表的「前置」欄為準。

---

## 為什麼做這件事

使用者在 PR #16 提出：賽事成績變數的用途之一是**讓隔屆的事件抓它來改文本**，
例如採訪時「作為〈衛冕冠軍〉，你有什麼話想要對對手說的嗎？」。

實測：**卡片文本目前不能讀狀態。** `src/data/*.js` 裡每一個 `prompt`、
`good.text`、`bad.text`、扮演卡選項標籤都是純字面字串，經
`shared.js:49`（`yield card('', ev.name, ev.prompt)`）原樣送到
`ui/log.js:16` 的 `renderCard`，再以 `innerHTML` 進 DOM——**中間沒有任何替換**。

今天要讓文本隨狀態變，唯一的辦法是**換掉整張卡**：扮演卡支援 `need` 述詞，
`roleplay.js:71` 的 `presser_underdog` 就是這樣做的（`need: (s) => (s.seedRank||1) >= 3`）。
可行，但每一個狀態變體要寫一張完整的卡，組合會爆炸。

### 機制其實已經存在兩份，只是沒被匯出

| 位置 | 形狀 |
| --- | --- |
| `biography.js:23-29` `fill()` | `/\{(\w+)\}/g`，**缺變數直接丟例外**（模組私有，6 行） |
| `summary.js:66` | `q.replace(/\{n\}/g, state.name)`，單變數的土製版 |
| `data/events.js:1006` `FAN_QUOTES` | **這份資料檔已經在用 `{n}` 佔位符** |
| `tests/kernel/biography.mjs:22` `MARKER = /[{?]|undefined/` | 已經把「未填的 `{`」當成測試失敗 |

也就是說 **`{變數}` 已經是本專案認可的語法**，資料檔裡也已經有先例。
這一站只是把它從傳記擴到卡片。

## 範圍

### 要做

**1. 把 `fill()` 拉成共用**

`biography.js:23-29` 目前是模組私有。移到共用位置並匯出，**傳記繼續用同一份**
（不要複製第二份——N16 的教訓）。

**2. `cardVars(state)` 解析器**

傳記的契約是「引擎在每個呼叫點明確供給變數」，卡片沒有那樣的呼叫點，
所以需要一個集中解析器，在 `shared.js:49`（事件卡）與 `:184`（扮演卡）
的 `yield card(...)` 之前填。

建議的變數集（本站定案）：

| 變數 | 來源 |
| --- | --- |
| `{name}` | `state.name`（⚠ 見下方轉義警告） |
| `{team}` | `state.team` |
| `{year}` `{age}` | `state.year`／`state.age` |
| `{lastTitle}` | S20g 的 `lastFinish` → `FINISH_LABELS` |
| `{oppTitle}` | 對手的上屆身分（有標記時才有） |

⚠ **轉義**：`renderCard`（`ui/log.js:16`）走 `innerHTML` 且**不轉義**——
`escapeHtml`（`dom.js:28`）目前只用在 board／panel／summary 的 `state.name`，
卡片這條路沒有。注入玩家自填的 `state.name` **一定要在填空點轉義**。

**3. 降級路徑——這是本站真正的難點**

`fill()` 對缺變數是**丟例外**（刻意的，160 段測試會抓出來）。但一張採訪卡在
「玩家沒有任何頭銜」的年份必須還是說得出話。

⚠ **不要把變數做成可空**（會生出「作為 ，你有什麼話想說？」）。
走 `biography.js` 既有的做法：**備用模板**——那份資料每個模板鍵都有降級的兄弟
（`amateurOnly`／`domesticNoIntl`／`bestSeasonNoIntl`），選哪一版是引擎的事、
填空只負責機械替換。卡片沿用同一個形狀。

**4. `MARKER` 檢查擴到卡片**

`tests/kernel/biography.mjs:22` 目前只掃傳記。擴成掃**所有卡片 body**——
未填的 `{`、`?`、`undefined` 出現在玩家看得到的文字裡就是測試失敗。
這是本站唯一能保證「降級路徑真的有效」的機制。

**5. 規格 §12.2 增訂**

`ESPORT-DESIGN-V4.md:1061` 的事件卡結構目前**沒有文本變數的概念**。
把 `{變數}` 語法、可用變數集、降級規則寫進去。

**6. 改寫採訪類卡片**

`roleplay.js` 的 `presser`（3 張）與 `intl`（5 張）是使用者點名的場合。
用變數改寫，讓一張卡吃掉多個狀態變體。

⚠ `presser_callout`（`roleplay.js:47`）現在寫「這輪對上**他們**」——那個刻意的
匿名代詞正是因為沒辦法指名對手。有了 `{oppTitle}` 就可以具體化。

### 不要做

- **不要讓變數可空**（見上方降級路徑）。
- **不要複製第二份 `fill()`**——傳記與卡片共用同一份。
- **不要在卡片文本裡放運算式**。`fill()` 的語法是 `\w+`，沒有點號、沒有運算式，
  維持這個限制（資料檔不該有邏輯，`data/biography.js` 檔頭明文寫過這條分工）。
- 不要順手改卡片的效果數值（那是平衡）。
- 不要新增卡片——本站只改既有卡片的文本。

## 規則與不變式

- **玩家永遠看不到未填的佔位符**——`MARKER` 掃過所有卡片 body，160 段生涯零命中。
- **缺變數要走備用模板，不是空字串**。
- **`fill()` 只有一份**，傳記與卡片共用。
- **卡片 body 注入 `state.name` 必須轉義**（`renderCard` 不轉義）。
- 既有不變式維持：UI 不得出現 `coachRating(`（`invariants.mjs:258`）
  與六維心理名稱（`:704`）——新文案不得洩漏。
- `npm test` 全綠。
