## 範圍

### 要做

**必讀規格**：V4 §19（DEMO / MVP 範圍全節）、§3.3（單年結構）。

**1. 起始狀態落在職業第一年**

V4 §19.2：

> 起始：玩家已在職業隊（主場賽區），職業第一年。

`src/engine/state.js` 的 `createState` 現在生的是 16 歲、`stage: 'AMATEUR'`、
在網咖隊。改成職業第一年的新秀。

起始屬性值用 S08 洞 3 定的（0–100 刻度下的職業新秀）。

**2. 業餘期／AM2 階梯休眠，不刪除**

`src/engine/roster.js` 的 AMATEUR → AM2 → PRO 階梯、`src/data/teams.js` 的
`TEAMS_AMATEUR`／`AMATEUR_CUPS`、`tests/phases/amateur.mjs`——**全部留著**。

V4 §19.4 的擴展路徑是「DEMO 驗證 → 補業餘期 → 補完整多年生涯」，刪掉就要重寫。

做法：加一個開關（`state.stage` 直接從 `PRO` 開始就自然跳過了），
`tests/phases/amateur.mjs` 改成直接構造 AMATEUR 狀態來測，不依賴 `createState`。

**3. 完整單年循環**

V4 §19.2：

- 約 12 個養成回合（休賽期、春/夏常規賽）
- 至少一個賽事事件序列（春季季後賽）
- MSI/世界賽事件序列（**可強制出線供測試**）
- 訓練活動菜單、體力系統、屬性→技能成長
- 事件卡子集、特質子集
- 常規賽結算、年末結算（薪資/續約/特質）

「可強制出線供測試」那條要做成一個測試開關，讓 MSI 與世界賽的序列在 DEMO 裡驗得到。

**4. 年末結算**

薪資、續約、特質。多年生涯的部分（衰退、退役、生涯評分）在 DEMO 裡不是重點，
但**不要拿掉**——跑得完整段生涯是既有測試的前提。

**5. V4 §19.3 的六項驗證重點**

跑完 DEMO 逐項確認，結果寫進交接筆記：

- 月份制回合循環正確
- 體力節奏（3–4 月一休）符合預期
- 屬性→技能成長正確（含潛力衰減）
- 事件觸發（條件優先、互斥、第二張）正確
- 賽事事件序列完整
- 年末結算邏輯正確
- **生涯任務卡跨回合存活**（開卡 → 進度 → 期限，V4 §12.3）
- **生涯傳記寫得出來且無佔位符**（V4 §15.5）

**6. 瀏覽器實測**

```bash
npm run serve
```

開 <http://localhost:8080>，**真的玩完一整年**。確認：
- 訓練菜單的成功率會隨體力變化
- 體力條會動
- 月份推進看得懂
- 賽事五拍完整
- **進行中的生涯任務看得到目標與剩餘期限**（§12.3 明文要求可見）
- 年末結算出得來，**結算畫面有生涯傳記**
- 存檔／讀檔往返正常

引擎測試驗不到 UI，這一步不能省。

### 不要做

- **不要刪業餘期的程式碼與內容**
- **不要為了 DEMO 砍掉多年生涯的邏輯**（退役、衰退、生涯評分）
- **不要在這一站調平衡。** 發現數值不對就回報給對應的站，不要就地改
- **不要新增內容**（事件卡／特質）
