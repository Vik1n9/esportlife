## 為什麼做這件事

§22.1 的狀態帶四列與 §22.5 的常駐屬性條從未實作。現行狀態帶是四個數字格
（年齡／年份／核心技能／生涯薪資），其中：

- **體力看不到**——體力是玩家要主動管理的資源（§6），排訓練時得先開面板才知道
  還剩多少。這是 §0.5 防農檢驗直接禁止的事（附錄 #76）。
- **屬性看不到**——只在屬性點分配那幾秒出現，決策時讀不到成長餘裕（§7.1）。
- **核心技能格違反 §22.1**「決策不提供技能讀數」：技能是導出值（§8.2），
  印在常駐區就等於給了一個可最佳化的總分。
- **沒有階段與倒數**——「距季後賽 3 月」是體力節奏（§6.1）的規劃資訊。

## 規則與不變式

- **`.abrow.mini` 必須掛 `.static`**：它是唯讀回饋，不是可按的控制項
  （`DESIGN.md` 原則 6：玩家碰得到的與碰不到的要看得出差別）。
- **狀態帶不得出現任何技能值**（§22.1）。
- **心理六維與教練評價不得顯示**（§22.4）。聲量是例外。
- `nextStageIn` 必須是純函式且 DOM-free。
- `src/styles.css` 檔頭的「鐵則」註解區塊不得失效；新增規則要一起補進去。

### 屬性條（`#attrbar`，`src/ui/attrbar.js`）

- 掛在 `index.html` 的 `#act-toggle` 與 `#act` 之間。**貼合手段：不用 sticky**——
  `#app` 是 flex column、`#log` flex:1 把它壓在行動列正上方，天然零間隙。
- 結構：`.attr-head`（只有 `〔+N〕` 鈕，無點數時整列 hidden）＋ `.attr-grid`
  （三欄×兩列 grid，六格照 `ATTRS` 權威順序）。
- 格子＝`.abrow.mini.static`，`data-attr` 帶屬性鍵；軌道三刻度：`i` 填充、
  `em` 潛力（--pot）、`u` 蓄力（--carry，分母＝當下一點成本 `growthThreshold().cost`）。
- **簽章**：`highlightAttrs(keys)`，`keys: string[]`（屬性鍵，如 `['vit','dec']`），
  傳空陣列／null 清除；對 `.abrow.hl` 切金色邊框。S39 訓練選項連動直接用。
- 〔+N〕＝`state.pendingPoints > 0` 時出現；點擊走 `askAllocation` 後把 `pendingPoints`
  歸零（避免 `phases/month.js` 的 alloc beat 重複發）。⚠ **beat 協定守衛**：
  `askChoice`／`askAllocation` 掛著時（`actions.js` 的 `isAwaitingInput()`）點按無效——
  那時候覆寫 `#act` 會讓等待中的 promise 永不 resolve。實際效果：引擎總在下一個養成
  回合自動把點數花掉，入口是空窗期快捷，不是唯一出口；S39 若想要「隨時可花」，
  得先改 alloc beat 的發射時機，別只在 UI 層繞。

### 引擎新增

`nextStageIn(state)` ＋ `STAGE_KINDS`（`engine/calendar.js`）：純函式、DOM-free，
回 `{kind, month, monthsAway}` 或 null。倒數的階段 kinds 只有
SPLIT／PLAYOFF／MSI／WORLDS——12 月的 MEDIA／SALARY／TRANSFER 不算階段（12 月必回 null）。
狀態帶的「當下階段名」在 UI 層（`board.js` 的 `currentStageName`）從 `calendarFor` 導出，
因為那是顯示問題不是倒數問題；`SEASON_END` 顯示為「賽季結算」，1／12 月顯示「休賽期」。

### 已知取捨

- DEMO 期程標籤（原年份格）併進 `#bd-stage`：`夏季賽 · DEMO 14/36`，資訊不丟。
- 屬性條〔+N〕在等待輸入時不可點（見上）；測試只約束顯隱，與此一致。
- 業餘／青訓期 `state.league` 為 undefined，`calendarFor` 退回單一「賽季」形狀，
  倒數照樣有值——階段名則由 `currentStageName` 顯示「休賽期／賽季」，可接受。
