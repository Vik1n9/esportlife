## 為什麼做這件事

現在 26 張卡 / 78 個選項。V4 §19 的 DEMO 是職業第一年、約 12 個月回合，
每回合固定 1 張（有機率 2 張）——**一年就要吃掉 12~20 張**。

26 張撐不起重玩。V4 §1.2 說「事件卡改變隱藏心理、觸發特質，特質合成形成隱藏路線」，
§1.4 說「重玩性來自不同種子＋不同選擇路徑＋隱藏探索」——這些都靠事件卡的數量與
多樣性支撐。目標 80~150 張。

## 範圍

### 要做

**必讀規格**：V4 §12（事件卡系統）、§9（隱藏心理六維——事件是唯一能改變它們的途徑）、
§13（特質雙面性）。

**必讀既有內容**：`src/data/events.js` 的檔頭註解（寫清楚了每個欄位的意思與設計理由）
與現有 26 張卡——**新卡要跟它們同一個聲音**。

**用 S18a 的編輯器寫**：`npm run serve` 之後開 <http://localhost:8080/tools/>。
id 重複、選項數不對、互斥群組沒成對這些會當場紅，不必等 `npm test`。
用法見 `tools/README.md`。手寫也可以，但錯了要自己抓。

**1. 每批 20 張，主題要分散**

不要一批全寫同類型。每批建議的組成：

| 類型 | 張數 | 說明 |
| --- | --- | --- |
| 訓練／日常 | 4~5 | 排位、訓練賽、覆盤、作息 |
| 隊內關係 | 3~4 | 隊友摩擦、教練談話、休息室、換人風聲 |
| 媒體／輿論 | 3~4 | 採訪、社群、直播、粉絲 |
| 賽場情境 | 3~4 | 賽前、賽後、關鍵局、被針對 |
| 生涯／人生 | 3~4 | 家庭、感情、學業、健康、退役念頭 |
| 版本／英雄池 | 2~3 | 大改版、新英雄、拿手英雄被砍 |

**2. 每張卡的必備欄位**（結構由 S17 定，這裡是內容要求）

- **敘事文本**：具體的場景，不是抽象描述。看現有的 `solo_queue` 那張——
  「凌晨兩點，訓練室只剩你這台還亮著」比「你在打排位」有力得多
- **2~4 個選項**：每個選項是**真的取捨**，不是「好選項 vs 壞選項」。
  安全牌的代價是它不會把你推向任何極端（現有卡的 `traits: false` 就是這個意思）
- **觸發條件**：時代／屬性範圍／特質／心理範圍／賽季階段。沒條件的就是隨機池成員
- **優先度**與**互斥群組**
- **結果**：屬性／體力／心理六維／特質線索

**3. 心理六維要被寫到**

V4 §9.1：心理**只能**透過事件卡改變。所以這一站的卡片是六維唯一的來源。
每批 20 張要確保六個維度都有卡在動它們，不能全部集中在抗壓與動機。

**4. 特質線索要鋪**

V4 §13.4：特質來源有「出生自帶、生涯條件、事件獲得」。事件獲得的特質，該事件之後
不再觸發。新卡要為 S19 的特質目錄鋪路——但**不要自己發明特質**，用 S19 定的清單
（若 S19 還沒做，先寫不掛特質的卡，或在交接筆記記下需要哪些特質）。

**5. 生涯任務卡目錄（v4.1 新增，25 張，單獨一批）**

V4 §12.3 的任務卡與一般事件卡是兩種東西（跨回合、有期限、發傳說），但寫的人是同一個，
所以掛在這一站。**單獨一批做，不要混在 20 張的批次裡**——引擎是 S17b，schema 不同。

| 類型 | 張數 | 觸發條件來源 | 達成結果 |
| --- | --- | --- | --- |
| `legend` | 20 | 條件式（§12.3）；§14.2 的素材組合表是**預設配置可改** ＋ 引擎層的底線門檻 | 傳說特質 |
| `route` | 5 | V4 §14.3 的五條生涯軌跡 | 史詩特質 ＋ 生涯標籤 |

- `legend` 的觸發條件是**條件式**（V4 §12.3），不是固定欄位。§14.2 那張 20 列的表是
  **校準用的預設配置**——照它抄是安全的起點，但**不是義務**：某張卡改成「兩個稀有」、
  「賽事成績 ＋ 一個稀有」、或純軌跡不吃素材，全都合法。條件式怎麼組是設計自由。
  - ⚠ **改了形狀就要在交接筆記寫明改了哪幾張、改成什麼**。§14.2 的配額推導
    （每個史詩恰好進兩條、稀有依取得率分配次數）只在「每張卡一史詩一稀有」時成立，
    S19c 要照實際卡表重推供給算式。不寫，S19c 就得自己一張張翻。
- **條件要推敲得出來**（§0.5 直覺檢驗）：玩家看得到自己的戰績與可見特質，所以條件要
  由這些組成，而且組合方式要符合電競邏輯——「連兩年世界賽四強 ＋ 兩個稀有」推得出來。
  **隱藏心理六維不准當條件**（不可見，§9.1），S17b 的謂詞表本來就不收。
- 底線門檻（國際賽四強以上）**寫在引擎層，不要逐卡複製** 20 遍（S17b 已實作）。
  它不在設計自由度裡——那是持有率 ≤50% 的守門員。
- `route` 五張是**平庸局的終點**，文案份量要跟 `legend` 同一級——「在同一支隊待了
  九年」寫得夠好，跟世界冠軍是一樣有力的結局。這是 §0.5 心流檢驗的實際交付物。
- 達成目標與期限的**數值先給草案**，實測校準是 S19c 的事。

**6. 死路檢驗清單（硬需求，不是「有空再說」）**

V4 §21.1 點名的兩批，這一站必須補完：

| 要補什麼 | 為什麼 |

> ⚠ 第一列那四個特質是**舊特質時代**的條目，v4.3 起具體特質由編輯器重新定義——死配方

**7c. 訓練事件卡目錄（60 張）——規則與做法（2026-08-15 定案，未施作）**

S18 任務追加（2026-08-15 與玩家定案）：除事件卡與任務卡外，另做 **60 張訓練卡**，
對應「選擇的訓練種類」（活動）與「對應的時期」（生涯階段）。本節是定案規則，
**下次動工照此製作；本次僅寫規則，程式與測試未動。**

**定案決策**（逐項與玩家確認，不可自行更改）：

1. **時期 = 生涯階段**：`AMATEUR`／`AM2`／`PRO`（不是時段標籤、不是體力區間）。
2. **60 張分配**：兜底 24（6 活動 × 4 檔位各 1 張，全階段通用）＋ PRO 20 ＋
   AM2 8 ＋ 業餘 8。
3. **不要特質欄位**：不寫特質線索／特質條件，訓練卡**不解鎖特質**（避免稀釋事件卡
   的專屬性；FLAG_TRAIT 表不動）。
4. **體力條件語意**：低體力危險卡（大失敗，`stamina [0,39]`）只在低體力進池 →
   低體力踩中高風險的機率上升；高體力時池子只剩正常卡 → 維持正常機率。
5. **範圍**：只做訓練卡；任務卡 25 張維持單獨一批。

**卡欄位形狀**（照 §5.4 結構，去掉「選項／特質條件／特質線索」）：

```js
{ id, tier, pool, weight, activity: ['mechanics'], stage: ['PRO'],
  stamina: [0, 39], text, effects: { mental?, buff?, injury?, attr? } }
```

- `activity`：6 種有卡池活動（mechanics／scrim／vod／fitness／soloq／heroes）；
  沒標＝全活動。rest／rehab 無卡池不標。
- `stage`：`STAGES`；沒標＝全階段（向後兼容語意，同事件卡 slot）。
- `stamina`：閉區間 `[lo, hi]`；沒標＝全體力。
- `effects`：`mental`（僅大成功／大失敗 ±3~5，§14.8.4）、`buff`（activeEffects，
  `trainBoost` 模式照 S16 的 momentum）、`injury`（僅大失敗）、`attr`（永久屬性
  增減，走 investAttr）。成功係數由檔位決定（`SUCCESS_COEF`），卡上不重複宣告。

**分配細則**：

| 組 | 張數 | 規則 |
| --- | --- | --- |
| 兜底 | 24 | id `tr_<activity>_<tier>`；不標 stage／stamina；weight 依檔位（success／failure 高、great 低）；任何活動 × 檔位 × 階段永不空池的保證 |
| PRO | 20 | 低體力大失敗危險卡約 4（`stamina [0,39]`，受傷／心理重擊）、高體力大成功獎勵卡約 4（`stamina [70,100]`）、一般職業文本卡 12 |
| AM2 | 8 | attr 壓 ±1、無 injury 大失敗、心理 ±3 保守、不加 flags |
| 業餘 | 8 | 同上；業餘星探不變式（nobody 測試）是紅線 |
