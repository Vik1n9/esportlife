## 為什麼做這件事

V4 §15.2 要求季後賽／MSI／世界賽的每場 BO 走五拍：

```
1. 賽前敘事（對手介紹、賽區背景、輿論氛圍）
2. 備賽戰術選擇（1 決策，3–4 選項）
3. 戰術結算：固定效果＋隨機事件判定
4. 比賽自動模擬 → 結果呈現（逐局比分、關鍵數據摘要）
5. 賽後敘事（採訪、輿論、心理結算）
```

現行 `phases/split.js` 的 `playoffs()` 已經有第 1、4、5 拍的雛形（`drawRoleplay`
留了扮演路口、`runSeries` 出比分、冠軍有敘事），**缺的是第 2、3 拍的備賽戰術**。

備賽戰術是賽事期唯一的體力調節手段（V4 §6.3：賽事期間不能休息），所以它是 S13
體力系統在賽季裡的出口。沒有它，賽事期的體力只出不進。

## 範圍

### 要做

**必讀規格**：V4 §15（賽事呈現，含 §15.2 五拍、§15.3 備賽戰術、§15.4 生死戰）、
§6.3（賽事期間的體力規則）。

**1. 新增 `src/phases/seriesEvent.js`**

把五拍抽成一個可重用的 generator，讓季後賽／MSI／世界賽三處共用。

介面大概是 `function* runSeriesEvent(g, { title, bo, oppRating, seed, stakes })`，
內部：
- 第 1 拍：賽前敘事（吃 `stakes` 決定語氣——生死戰跟八強不一樣）
- 第 2 拍：`yield { type:'choice' }` 出備賽戰術
- 第 3 拍：戰術結算 ＋ 隨機事件判定
- 第 4 拍：`runSeries(...)`（**沿用 `kernel/series.js`，不要重寫**）
- 第 5 拍：賽後敘事 ＋ 心理結算（`applyMental`）

**2. §15.3 備賽戰術選項**

| 戰術 | 效果方向 | 體力消耗 |
| --- | --- | --- |
| 針對對手弱點研究 | 特定場景機率↑，被反制時風險大 | −15 |
| 強化自身體系 | 穩定提升團隊表現 | −20 |
| 心態調整與休息 | 抗壓判定↑、恢復少量體力 | +5 |
| 高強度集訓 | 操作/默契↑，體力消耗重、受傷風險微增 | −30 |

⚠ **效果要掛在「這一場系列賽」上，不是永久加屬性。** 備賽戰術是單場的準備，
不是訓練。掛錯層會讓玩家用季後賽刷屬性。

戰術選擇除固定效果外，也可能隨機觸發事件（§15.3 最後一句）。

**3. 三個呼叫端改用共用序列**

- `src/phases/split.js` 的 `playoffs()`
- `src/phases/msi.js`
- `src/phases/worlds.js`

改完之後這三個檔應該變薄——差異只剩「對手怎麼來」「名次怎麼算」「敘事語氣」。

**4. §15.4 生死戰（區域資格賽）**

單場定生死的高壓事件序列。抗壓低者受迫性失誤放大（S12 的失誤系統要接進來）。
`stakes` 參數傳最高級，讓第 1 拍與第 5 拍的敘事跟著變重。

**5. 接上 S13 的 §6.3 規則**

賽事期間不能選「休息」行動——這條規則 S13 已經寫進 stamina.js 的介面，
這一站確認賽事月份真的擋掉休息選項，而「心態調整與休息」戰術是唯一的恢復途徑。

## 交接筆記

### 一、做了什麼

新增 `src/phases/seriesEvent.js` 的五拍共用 generator `runSeriesEvent`（V4 §15.2），
三個呼叫端全部改用：`playoff.js`（每輪，決賽 stakes 'final'）、`msi.js`（勝部／敗部／
淘汰賽）、`worlds.js`（地區資格賽／入圍賽／淘汰賽）。每場 BO 從「扮演路口 → 出比分」
變成五拍：賽前敘事 → 備賽戰術（1 決策，4 選項）→ 戰術結算 → 比分 → 賽後敘事＋心理
結算。生死戰（地區資格賽）的 stakes 給最高級 `elimination`（V4 §15.4），賽前與賽後
語氣跟著變重。

備賽戰術四項（§15.3）：`research`（−15，+3，20% 被反制翻負）、`system`（−20，+2，
無隨機）、`mindset`（恢復，+1，賽事期唯一恢復）、`bootcamp`（−30，+4，15% 受傷風險
+3）。**效果只掛這一輪 BO**——`mod` 走 `gameChance` 的加法項，不碰屬性。

### 二、兩個偏離規格書字面的決定

1. **mindset 的恢復量用 `recoveryOptions({ inEvent: true })` 的 −20，不是 §15.3
   表的 +5。** §15.3 那張表標「示例」；§6.3 與 S14 交接筆記都明說恢復量＝休息的四成、
   唯一出處在 `stamina.js`。S14 把它寫成 −20（`REST_RECOVER × 0.4`），seriesEvent.js
   讀回來用，沒有第二份數字。
2. **「變薄」只發生在 playoff（−4 行），msi／worlds 基本持平（+3~6 行）。** 抽走的是
   五拍敘事骨架（約 170 行，現在只在 seriesEvent.js 一份），但呼叫端為傳
   `stakes`／`oppNote`／`pressure` 多花的參數行抵銷了省下的行數。職責上三個檔確實只剩
   「對手怎麼來／名次怎麼算／結構狀態卡（勝部、敗部、門票）」，這才是那條驗收線的
   本意。

### 三、沒動的「要動的檔案」

- `src/phases/split.js`：S14 已把季後賽拆到 `playoff.js`，S15 改的是後者。
- `src/phases/index.js`：`seriesEvent` 不是新 kind（沒有自己的 run 入口），是三個
  賽事共用的 helper，不註冊。

  **消費**它（mindset 恢復量、確認備賽選項無 rest），沒改規則。
