## 為什麼做這件事

兩件事：

**1. 賽事五拍讀不出是一場系列賽。** §15.2 的五拍（賽前／備賽戰術／備賽結算／
結果／賽後）目前是五張與其他卡同級的卡片，散在事件文本區裡。§1.2 把
「敘事儀式感：賽事以事件序列呈現，五拍結構」列為三大核心體驗之一——
散成五張同級卡就讀不出結構。§22.1（v4.6.1）因此明訂**五拍必須成組呈現**。
⚠ S37 交接筆記點名：這條不是美化，別當 nice-to-have 砍掉。

**2. 事件文本區是無界捲軸。** 長生涯往下堆，只有年度折疊，沒有分類篩選也沒有
跳轉。§22.1（v4.6.1）新增日誌檢視控制。

## 範圍

### 要做

**1. 卡片分類（零呼叫點改動）**

`card()` 工廠住在 `src/phases/shared.js`，全專案 **91 個呼叫點**。
**不要逐點加參數**——加一個帶 `kind` 的工廠，各 phase 檔把 `card` 的來源換掉，
**一檔一行**：

```js
export const kinded = (kind) => (tone, title, body) => ({ type:'card', tone, title, body, kind });
```

分類建議（施工時逐檔確認，不要憑檔名推斷）：
訓練／賽事／事件／市場／賽季結算。

`kind` 是**純新增欄位**——既有測試只斷言 `beat.type === 'card'` 與 `beat.title`，
不會紅。

**2. 賽事五拍成組**

- 五拍的發射處（`src/phases/seriesEvent.js`）額外帶 `series` 標識（函式內已有
  賽事標題變數，直接用）。
- `src/ui/log.js` 偵測**連續同 `series` 值**的卡片，收進同一個 `.series-block`，
  標頭一列（賽事名／對手／BO 數）。
- ⚠ 五拍中間會插入 `choice`（第 2 拍備賽戰術，S39 已確認走決策槽而非 inline），
  分組判斷要能跨過它。

**3. 檢視控制**

- 事件文本區上方一排分類篩選 chips（全部／賽事／訓練／事件／市場）。
  卡片掛分類屬性，篩選**純靠 CSS 屬性選擇器**——不重繪、不重跑 generator，
  篩選是純檢視操作、不改變任何遊戲狀態。
- 年度跳轉：年度分隔線建區塊時登記進目錄，窄螢幕用下拉選單放在 chips 列右側。
  S42 會把它升級成寬螢幕左欄常駐——**登記結構要讓 S42 直接取用**。
- 既有的年度折疊行為保留（`src/styles.css` 檔頭鐵則列有這條）。

### 不要做

- **不逐點改 91 個 `card()` 呼叫**。
- **不動 `#board`**（S38）、**不動 `choice` 分派**（S39）、**不動 `#panel`**（S40）、

## 交接筆記

### 分類鍵一覽與各 phase 檔對應

| `kind` 鍵 | chip 標籤 | phase 檔 | 主要卡片內容 |
|---|---|---|---|
| `train` | 訓練 | `month.js` | 訓練結果、英雄池擴充 |
| `match` | 賽事 | `seriesEvent.js`、`playoff.js`、`msi.js`、`worlds.js` | 五拍序列、季後賽、國際賽、戰報 |
| `event` | 事件 | `split.js`、`shared.js`（drawEvent/drawRoleplay/questBeats/fusionBeats/personaBeats） | 事件卡、扮演卡、任務卡、特質覺醒、先發名單 |
| `market` | 市場 | `transfer.js`、`salary.js` | 轉會、薪資結算 |
| `season` | 結算 | `seasonEnd.js` | 年度總結、獎項、版本改動 |

`engine/game.js` 的生命週期卡（出生、退役、結局、年齡等）**沒有 `kind`**——
在任何篩選下都保持可見（CSS 選擇器只隱藏「有 `data-kind` 且不符合篩選」的元素）。

`shared.js` 保留原始 `card()`（無 kind），供 `drawEvent`、`drawRoleplay`、
`questBeats`、`fusionBeats`、`personaBeats` 使用——這些跨類別的共用 generator
由呼叫端的 `kinded()` 決定外層分類。

### 五拍分組如何跨過 `choice`

`runSeriesEvent` 的五拍中間有一個 `choice` beat（第 2 拍備賽戰術，`slot: 'act'`）。
`'act'` 的 choice 渲染在 `#act`（底部決策槽），不在 `#log` 文本區，所以不影響
分組連續性。`log.js` 用模組級狀態 `lastSeriesBlock` 追蹤最後一個 series block：

- 新卡帶 `series` 且與 `lastSeriesBlock._series` 相同 → 追加進 block
- 新卡帶 `series` 但 series 不同 → 開新 block
- 新卡不帶 `series` → `lastSeriesBlock = null`，正常渲染
- `renderDivider` 與 `renderLoose` 也會重設 `lastSeriesBlock`

### 年度目錄登記結構（S42 取用）

`ui/log.js` 模組級的 `yearEntries` 陣列：

```js
[{ text: '2015', node: <div.yr-block> }, ...]
```

`renderDivider` 每次建立年度分隔線時 push 一筆。年度下拉選單
（`#log-year-select`）的 `onchange` 讀這個陣列找到 node 後 `scrollIntoView`。

S42 寬螢幕左欄可以直接 import 這個結構（需先 export），或在 `initLog` 裡掛 callback。

### 篩選的 CSS 實作

篩選掛在 `#log`（`logRoot`）的 `data-filter` 屬性，`#log` 同時帶 `.log-filters`
class。CSS 用 20 條規則（5 種篩選 × 4 種不符合的 kind）隱藏不符合的元素：

```css
.log-filters[data-filter="train"] [data-kind="match"],
.log-filters[data-filter="train"] [data-kind="event"],
...{ display: none }
```

`series-block` 的 `data-kind` 掛在 block 層（不在內部卡片），整組一起隱藏，
不會留空標頭。沒有 `data-kind` 的元素（生命週期卡、年度分隔線、`summary.js`
的結算卡）不受任何篩選影響。

### 未一起處理

- `#log-bar` 沒有 sticky——它位於 `#board`（sticky top:0）之下，sticky 會被 board
  遮住。S42 寬螢幕版面可以考慮讓篩選列常駐在左欄頂端。
- 篩選狀態不存檔——重整後回到「全部」。如需持久化，可存 `localStorage` 一個 key。
