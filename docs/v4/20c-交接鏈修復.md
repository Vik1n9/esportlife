# S20c · 交接鏈修復

狀態：未開始
前置：S18b
預估：1~2 session
推理難度：高
建議模型：Opus 5（`claude-opus-5`）
理由：動的是 kernel 特質存放層與跨檔字串鍵表，三處「同一份資料兩份手抄本」要收斂成
單一來源。改錯的失敗模式是靜默的（查表查不到 → 回預設值 → 測試照樣全綠），
`20b` 審查抓到的 A3 就是這樣活了十幾站。降級的風險是只修表面那兩個空格、不收斂
來源，半年後第四次漂開。

---

## 為什麼做這件事

`20b-組裝前架構審查.md` 列的 A2／A3 是「前置站產出與規格不符」，但獨立查核發現
它們不是孤例，而是**同一類 bug 的三個實例**：某張查表的鍵，必須與另一個檔案產生的
字串逐字相同，而**沒有任何測試在守這件事**。

| # | 查表 | 期望的鍵 | 實際產生的字串 |
| --- | --- | --- | --- |
| A3 | `ledger.js:57` `WORLDS_ORDER` | `'世界賽 冠軍'`（有空格） | `worlds.js:204` → `'世界賽冠軍'` |
| N3 | `ledger.js:67` `msiBest` 三元鏈 | 只認冠／亞／四強 | `msi.js:156` 另有 `'MSI 止步'` |
| N4 | `career.js:51` `HONOR_POINTS` | `'季後賽冠軍'` | `playoff.js:120` → `'2020 PCS 夏季賽冠軍'` |

三個都靜默、三個都讓真實成就在查詢層消失、三個都在 18758 項全綠底下活著。

**實測後果**：

- A3：150 段生涯裡抓到一位真實世界賽冠軍 `worldsBest()` 回 **4**、一位亞軍回 **4**。
  文件說的「回 99」是罕見邊角（150 段 0 例），真正常見的是**每個冠亞軍都偏高**——
  連帶 `legend-worlds-king`（`quests.js:249` `worldsBest lte 3`）**世界賽冠軍反而
  開不了那張卡**。
- N3：`'MSI 止步'` 在 `ledger.js` 回 **99**（等同沒打過）、在 `biography.js:41` 回 **4**。
  40 段出現 2 次。`quests.js:90` 的 `msiBest lte 4` 形同虛設。
- N4：25 段生涯共 34 個以「冠軍」結尾的榮譽字串，`'季後賽冠軍'` **命中 0**。
  **每一座賽段冠軍在生涯評分裡值 0 分**（該值 80）。

這一站把三個一次收斂，並補上唯一擋得住再漂的那種測試。

A2（`unique` 階死資料）併進來，因為它同屬「資料存在、消費端不存在」，
而且要動的是同一批 kernel 檔。

## 範圍

### 要做

**1. 名次鍵入帳，三份手抄本收成一張（A3 ＋ N3 ＋ N5）**

> ⚠ **2026-08-15 改寫**（PR #16 第二輪審查）：原本的做法是「修 `ledger.js:57` 的兩個
> 空格鍵」。使用者提的「上屆同賽事名次」設計查核後確認**能從根上解掉這一類 bug**，
> 所以本項改成根治。設計全文見 [S20g](20g-賽事成績帳本與衛冕者.md) 的附錄。

**根因**：名次的機器可讀鍵（`champion`／`semi`…）**目前是被丟掉的**——它只活在
`worlds.js:93` 的區域變數 `outcome` 裡，寫進 state 之前就被轉成顯示字串
（`milestones[].text`）。於是 `worldsBest`／`msiBest` 只能**反過來解析文字**，
而那些文字有兩種空格寫法（`世界賽冠軍` 無空格、`世界賽 四強止步` 有空格，
因為 `worlds.js:204` 只在缺前綴時才補）。三份手抄本各自解析：

| 手抄本 | 狀態 |
| --- | --- |
| `ledger.js:57` `WORLDS_ORDER` | **壞的**——冠亞軍鍵有空格，永遠比不中 |
| `ledger.js:67` `msiBest` | 行內三元鏈，不認得 `'MSI 止步'`（回 99＝沒打過） |
| `biography.js:38` `INTL_SCORE` | 對的（註解卻寫「與 `WORLDS_ORDER` 同一套」——並不是） |

**做法**：

1. 建**一份共用的名次表**（鍵 → 序位＋顯示字串），取代三份手抄本。
   詞彙用三個賽事已經一致的前四名 `champion / final / semi / quarter`，
   加各自的尾巴（世界賽 `stage`／`playin`、MSI `out`、季後賽 `none`），
   並**保留 `ro16` 一個位子**（庚組 NPC 賽事模擬用得到，玩家賽程現階段不產生它）。
2. **里程碑列加上機器可讀欄位**，`text` 保留供顯示與既有讀者：
   ```js
   { year, kind: 'intl', event: 'worlds', finish: 'champion', text: '世界賽冠軍' }
   ```
3. `worldsBest`／`msiBest`／`INTL_SCORE` **改讀 `finish`，不再解析文字**。

這同時滿足 `ledger.js` 檔頭自己的規矩（「條件不得直接讀 raw state，
否則改一個欄位要改三個地方」），並且讓 S20g 的「上屆同賽事名次」變成一句查詢
（讀 `milestones` 導出），**玩家那半不必新增任何 state 欄位**。

**2. 名次對照測試（N17）——先紅後綠**

`tests/kernel/ledger.mjs` 目前**從未 import** `worldsBest`／`msiBest`／`intlSemis`
（只有 `assistsPerGame`／`distinctTeams`／`intlWinRate`／`longestTenure`），
里程碑斷言只有結構性的兩條（欄位齊備、kind 在 `MILESTONE_KINDS` 內），
**沒有任何一條在比對文字**。

補一組測試：遍歷 `WORLDS_RESULTS`／`MSI_RESULTS` 的每一個 rank，過一次
**寫入端的實際運算式**（不是手抄一份預期字串——那只是把 bug 抄第四遍），
斷言每一個名次都查得到序位。

**先寫測試、確認它在修之前是紅的**，再修。這是唯一擋得住再漂的形狀。

⚠ 名次鍵入帳之後，這組測試要驗的是**寫入端產生的 `finish` 鍵都在名次表內**，
而不是「文字對得上」——後者在改完之後就不再是正確性的來源了。

**3. `HONOR_POINTS` 比對修正（N4）**

`career.js:51` 的 `'季後賽冠軍'` 改成對得上 `playoff.js:120` 產生的字串。

⚠ **這會改變生涯評分**：每座賽段冠軍從 0 分變 80 分 → `careerScore` →
`careerTier` 分布位移 → `smoke.mjs:112`「五個等第都出現得到」與 `showcase` 的
評分會動。**本站只修比對並記錄位移量，分布重量與門檻校準留給 S20d。**

**4. `unique` 階接線（A2 ＋ N16）**

補齊八個接點：

| 檔案 | 動作 |
| --- | --- |
| `state.js:173` | 加 `unique: {}` |
| `modifiers.js:27` `TIER_STORES` | 加 `unique` 項＋ import `UNIQUE_TRAITS` |
| `modifiers.js:117` `lookupTrait` | 加 `UNIQUE_TRAITS[key]` |
| `modifiers.js:121` `traitTier` | 加 `unique` |
| `progression.js:101` `TIER_TO_STORE` | 加 `unique` |
| `conditions.js:37` `TIER_TO_STORE` | 加 `unique`（否則 `['has','unique',…]` 炸） |
| `progression.js:171` `activeTraitNames` | 加 unique |
| `ui/summary.js` | 渲染 unique 標籤 |

⚠ 授予**不能用** `unlockTrait`——`progression.js:112` 寫死 `state.traits`（common 階）。
仿 `quests.js:122` 的傳說發放形狀。

⚠ `traitTier` 若對 unique 回 `undefined`，`exclusiveHeld` 的
`TIER_STORES[undefined].store(state)` 會 TypeError。這條路今天走不到
（沒有特質的 `exclusiveWith` 指向 unique），補了 unique 之後就走得到。

三條 `grant`（`epics.js:288`）目前是**自然語言字串**，餵不進 `evalCond`，要改成
可求值謂詞。

⚠ **本站只接 `late_bloom` 與 `thousand_games` 兩條**（生涯末期單季獲獎、累計出賽數，
兩者的資料都已存在）。`torch_bearer`「世界賽淘汰現任世界冠軍」**由
[S20g](20g-衛冕者追蹤.md) 負責**——遊戲裡目前沒有「現任世界冠軍」這個東西
（`worlds.js:32` 的對手全文是一個浮點數，且玩家沒奪冠的年份不記錄誰奪冠），
那要先建對手身分層，不是本站的範圍。本站把 store 與發放形狀建好即可，
**不要硬造一個假追蹤**。

**5. A4 內容站的前置：slot 詞彙（N7）**

`tools/schema.js:38` 提供 10 個 slot，`currentSlots()`（`eventTrigger.js:56`）
只產得出 6 個——`playoffs`／`msi`／`worlds`／`qualifier` **永遠取不到**，
只標這些的卡片會是永久抽不到的死卡。今天 0 張卡用到，是留給 S20f 的陷阱。
二擇一：建賽事期觸發鉤，或把編輯器清單收斂成 6 個。**不要兩邊都留著。**

⚠ **時段過濾不是條件**（`AGENTS.md` 條件語言規則）：`slot` 是觸發演算法的步驟 0，
與 `when` 分開，這一項不受下面的 whenHits 退役影響。

**5b. `when.trait` 的三個缺陷（N6）——本站不修**

> ⚠ **2026-08-15 改變處置**（PR #16 第三輪）：使用者拍板**統一條件語言**，
> `whenHits` 由 [S20g](20g-賽事成績帳本與衛冕者.md) 退役、事件卡改吃 `evalCond`。
> 所以本站**不要**修 `whenHits`——補了也是丟掉（`AGENTS.md` 條件語言規則明文：
> 「在它消失之前不要為它補功能」）。

缺陷本身記錄在案，供 S20g 遷移時對照：文件（`eventTrigger.js:89`）寫
「持有特質（任一即可）」但實作（`:105`）是 **AND**；只讀 `state.traits`，
rare/epic/legendary **永遠不能當條件**；文件自己的範例 `godhand` 是 **epic**，
照著寫永遠不觸發。編輯器下拉卻是從全四階的 `ALL_TRAIT_KEYS` 生的。

**現在不修沒有代價**——實測 86 張卡 `when` **0 張**，這條路今天一次都沒走過。

**6. 其餘（N8／N13／N15／N18／N19／N20）**

- **N8**：`FLAG_TRAIT`（`eventTrigger.js:127`）補 `trashtalk`／`meta`。
  `events.js:299`／`:309` 兩張卡寫了旗標，卡片承諾解鎖特質、實際零給予；
  編輯器（`schema.js:230`）還把它們列為可寫旗標，不修會被再寫一次。

  `lineup.js:34` 回退 **66**。統一。

  `activeTraitNames` 對缺欄位是裸 `Object.keys` 會炸。
- **N18**：`DISBANDS` 2016 台北暗殺星永遠不觸發——該隊只存在於
  `home.js:32` 的 `from:2012 to:2014` 名單列，2016 年 era 鍵已是 LMS。
- **N19**：死程式碼——`state.sixCount` 零讀零寫；`nextStepCost`／`retentionPremium`／
  `hasSave`／`qs` 等 10 個 export 從未被 import；`trainingCards.pool` 60/60 張是
  死欄位（`drawTrainingCard` 不讀它，但 `schema.js:302` 標 `required`）；

### 不要做

## 規則與不變式

- S07 不變式全綠。
- **同一份資料只准有一份手抄本**：名次表、階名拼法收斂後，不得留下第二份。
- **新測試必須在修之前是紅的**——沒紅過的測試不算守得住。
- `npm test` 全綠；項數變動在交接筆記寫明來源。
- `SAVE_VERSION` 升版照 `state.js:19-29` 的體例加註解行。
