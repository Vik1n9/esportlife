# S27 · 參數生成（`npc_roster.json`）

狀態：未開始
前置：S25
預估：1 session（LLM 批次依清單大小；中斷可續傳）
推理難度：中
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：確定性部分是公式照抄（S23 定案），LLM 部分是 1 選手 1 呼叫＋離線快取。
風險在 Token 額度控制與生成品質抽驗，不在設計判斷。

---

## 為什麼做這件事

`cleaned_players.json` 是史實紀錄，還不是遊戲參數。本站把史實轉成 V4 的
`state` 結構：確定性數學（年齡、生命週期、潛力、位置權重）用腳本算，
需要語意理解的維度（天生特質、心理六維、敘事標籤）用 LLM 生成後落檔。
產出 `npc_roster.json` 是 S28／S29 的輸入。

## 範圍

### 要做

**1. 確定性參數（腳本，零 Token）**

- 年齡與生命週期：依出生年算年齡；依生涯長度與巔峰期經統計常態分佈指派
  `peak_age`／`rise_k`／`fall_k`（§7.2 生命週期參數——範圍照 S23 定案）。
- 基礎屬性權重：位置（Top／Jungle／Mid／Bot／Sup）套固定權重表。
- 潛力天花板：依歷史最高賽事名次與層級公式計算（S23 定案的層級→潛力映射）。
- 技能：依 §8 十二技能與位置權重導出（S23 定案的 NPC 技能規則）。

**2. LLM 語意參數（嚴格控 Token）**

- 每名選手 1 次呼叫，僅三個維度：天生特質與素材（依生涯榮譽與經典戰役）、
  `psych` 六維（依生涯波動與轉會頻率）、敘事標籤（觸發隨機事件的標籤）。
- System Prompt 帶 2–3 個完美範例（Few-Shot）；輸出純 JSON，禁前言後語。
- **結果寫入 `npc_roster.json` 快取——重跑跳過已生成選手，遊戲執行時零推論**。

**3. 校準校驗**

- 生成後跑分佈檢查：六屬性／潛力／psych 的分布與 V4 玩家起點（§7.3）的關係
  合理（S23 定案的校驗門檻：如 NPC 全體均值 vs 玩家起始評價 58 的距離）。
- 不合理的欄位（如 psych 全貼 50）回報 S23 規則而非自行調公式——公式錯誤
  改腳本，規則錯誤寫交接筆記。

**4. 產出與註記**

- `npc_roster.json` 標頭：來源（Liquipedia）、CC BY-SA 註記、生成日期、
  LLM 版本。
- 台港澳（fetch_priority 1）全量；國際賽精選（priority 2）依 S23 定案的
  是否生成／何時生成。

### 不要做

- 不改 `cleaned_players.json`（本站只讀）
- 不做引擎整合（S28／S29）與校準重驗（S30）
- 不即時推論：所有產出離線落檔
