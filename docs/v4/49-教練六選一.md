# S49 · 教練六選一（接進 modifier 系統）

狀態：未開始
前置：S47
預估：1 session
推理難度：高
建議模型：Opus 5（`claude-opus-5`）
理由：要把**第五個效果來源**接進 `kernel/modifiers.js`——那個檔是全專案效果查詢的
單一入口，改它的產生器會影響所有 `factor`／`flag`／`capOf`／`bonusOf` 消費點。
另外六個教練的戰力點有一條 §11.1 的跨筆硬約束（平均必須是 2.0），
以及一個容易被誤接的同名概念（`coachRating`）。判斷密度高。

---

## 為什麼做這件事

`src/data/coaches.js` 現在是 5 個名字配一個 `bonus`（戰力點），唯一的消費點是
`kernel/strength.js:13` 的 `coachBonus`，加進 `teamStrength`。換句話說：**五個教練
之間的差別只有一個數字大小**，沒有任何質的區別。玩家簽約時看到「教練體系：訓練狂」，
除了名字之外得不到任何資訊，也做不了任何判斷。

本站把它改成**六種各有機制效果的教練**，並讓效果走既有的 modifier 系統，
使教練從一個隨機數變成簽約時真的會權衡的條件。

> ⚠ **先釐清一個同名陷阱**：`coachRating`（`attributes.js:109`）是 §10.2 的
> 「**教練對你的評價**」，餵薪資與續約，與本站**完全無關**。
> `ui/panel/team.js:5` 已經有一條註解在守這個區別——別把兩者接在一起。

## 範圍

### 要做

**1. 新的教練表（六種並列，不分大類）**

| 教練 | 戰力點 | 機制效果 |
| --- | --- | --- |
| 戰術大師 | +3.0 | 備賽戰術的 `mod` ×1.3（§6.3 的四個戰術都更有效） |
| 版本先知 | +2.5 | `patchDebt` ×0.5（版本適應） |
| 訓練狂 | +1.5 | 訓練成長 ×1.15；**副作用**：訓練消耗 ×1.10 |
| 體能教練 | +1.5 | 訓練消耗 ×0.85、恢復量 ×1.15、受傷率 ×0.85 |
| 心理輔導 | +2.0 | 心理漂移收斂、`benchRisk` ×0.8 |
| 經紀團隊 | +1.5 | `endorsement` ×1.25、`offerPenalty` 免疫 |

**戰力點的平均必須維持 2.0。** §11.1 的驗算例把「教練 ＋ 體力」合計釘在 3.5 點、
教練平均 2.0；現行 5 個教練的平均剛好是 2.0。新的六個：
`(3.0 + 2.5 + 1.5 + 1.5 + 2.0 + 1.5) / 6 = 2.0` ✓。這不是巧合而是**硬約束**——動任何
一個數字都要把平均補回 2.0，否則整個聯盟的強度集體位移（`kernel/strength.js:160`
的註解講的就是這件事）。

戰力點與非戰鬥效果**刻意反向**：給戰力的不給成長，給成長的不給戰力。
沒有哪一個是嚴格最優，這是六選一有意義的前提。訓練狂帶副作用（消耗 ×1.10）是照
§13.1 的雙面性寫的——不該有純益的教練。

**2. 接進既有的 modifier 系統，不另開一套**

`kernel/modifiers.js` 的檔頭已寫明它的存在理由：舊版把效果寫成散在十個引擎檔裡的
`if (state.traits.clutch) p += 4`，結果新增一個特質要先在十個檔裡把它找出來；
現在效果宣告在資料檔、消費端只問四個函式。**教練應該成為第五個效果來源**，
而不是在十個引擎檔裡再長出一批 `if (state.coach === '訓練狂')`。

- `data/coaches.js` 每一筆加 `desc`（給 UI 的一句話）與 `effects`
  ——**用與 traits／epics 完全相同的鍵與寫法**（`normalize()` 的簡寫也照用）。
- `modifiers.js` 的 `effectsFor` 產生器走完 `TIER_STORES` 之後，多 yield 一段當前
  教練的 effects。**改一個產生器，所有既有消費點自動吃到教練效果，零新增串接。**
- `state.coach` 維持存**名字字串**：`coachBonus`（`strength.js:14`）本來就是
  `COACHES.find((c) => c.name === state.coach)`，沿用同一個查法就**不必做存檔遷移**。

新增的 modifier 鍵（照 `LIFECYCLE_WINDOWS` 的作法逐項 clamp，避免教練效果與史詩特質
疊起來失控）：

| 鍵 | 消費點 | clamp |
| --- | --- | --- |
| `trainYield` | `resolveTraining` 的成長式 | [0.5, 2.0] |
| `trainCostMul` | `stamina.js` 的 `trainCost`（S47） | [0.6, 1.5] |
| `recoverMul` | `stamina.js` 的 `recover()` | [0.6, 1.6] |
| `tacticMul` | `seriesEvent.js` 的 `TACTICS.mod` | [0.5, 2.0] |

`patchDebt` / `benchRisk` / `endorsement` / `offerPenalty` / `injuryRate` 都是**既有的鍵**，
直接沿用、不新增。

⚠ **`trainCostMul` 與 S47 的體能折扣是同一個乘積**：
```js
trainCost = Math.round(cost * vitCostCoef(state) * factor(state, 'trainCostMul'))
```
兩個折扣疊起來下限可到 `0.8 × 0.85 = 0.68`。顯示已走同一個函式（S47 那條
「選單不能說謊」的測試），所以**顯示自動正確**；但這個下限要寫進交接筆記交給 S50。

**3. 內容編輯器（`tools/schema.js`）**

**四個新效果鍵必須進 `EFFECT_KEYS`。** `:201` 的註解已經寫死規則：「特質宣告的效果鍵
不在這張表＝打錯鍵，特質會靜靜地沒有效果……新增效果鍵要同時改
`src/kernel/modifiers.js` 的消費端與這張表」。所以 `trainYield` / `trainCostMul` /
`recoverMul` / `tacticMul` 四個鍵要同時加進 `EFFECT_KEYS` 與 `EFFECT_KEYS_LABELS`
（訓練成長倍率／訓練消耗倍率／恢復量倍率／備賽戰術倍率）。漏掉的後果不是報錯，
是**未來寫的特質用這些鍵會靜靜地沒有效果**。

**`checkEffectConsumption()`（`:878`）的語意要擴張。** 它目前檢查「特質宣告的效果鍵
有沒有被引擎消費」。教練成為第五個效果來源之後，這個檢查要一併掃 `COACHES` 的
`effects`——否則教練打錯鍵會是唯一沒人守的那一格，而教練只有六個、每個都靠機制效果
定義身分，打錯一個就是整型教練退化成純戰力點。

**4. 讓教練成為轉隊的決策依據**

`transfer.js:184`／`:219`／`:235`／`:442` 已經在報價與簽約文案印
`教練體系：${state.coach}`——但玩家只看到一個名字，不知道它代表什麼。四處改成印
名字 + 一句話效果（讀 `coaches.js` 新增的 `desc`），`ui/panel/team.js:140` 的教練列
同樣加上效果說明。純呈現、不動平衡，但它決定了整個教練系統玩家有沒有感覺——
**這一項不做，前面的六種教練玩家分不出來。**

### 不要做

- **不做校準**（S50）。培育型教練會推高總成長，但只有 1/3 的生涯抽得到，
  它拉大的是生涯之間的**變異**而不是平均——量測要跟其他三站一起做。
- **不碰 `coachRating`**（§10.2 教練評價）與 `coachMult`（既有的評價倍率鍵）。
- **不改 `roster.js:146` 的抽籤方式**（仍是 `rng.pick(COACHES).name`）。
- **不讓編輯器能編教練**：`SCHEMAS`（`:299`）目前七類資料，教練不在其中。
  加第八類是自然的延伸（六筆、欄位少），但**本站刻意不做**——教練的 `bonus` 有一條
  「平均必須是 2.0」的**跨筆**約束，那是 `validate*` 家族現有的逐筆驗證表達不了的形狀，
  硬塞會做出一個管不住重點的表單。先讓 `tests/kernel/coaches.mjs` 守住這條約束，
  編輯器支援留給日後真的要頻繁調教練時再說。**這是刻意沒做，不是漏掉**，
  交接筆記要寫明。

## 兩件要如實說明的事（寫進說明書與規格，不要留給後人猜）

**1. 「全隊 buff」在這個模擬裡的落點。** 玩家只是五分之一，隊友僅以 `matesAverage`
一個數字存在——所以戰術／後勤性質的效果經 `coachBonus` 進 `teamStrength`
（那真的是全隊的），而**訓練類效果只落在玩家身上**（隊友不跑訓練迴圈）。
敘事上寫成全隊，機制上落在被模擬的那一半。這是**模型邊界不是漏做**，
不寫明日後會被當成 bug 修。

**2. `rng.pick(COACHES)` 從 5 筆變 6 筆會改動每一條既定種子的生涯。**
`coaches.js` 檔頭明寫「順序即抽籤順序（`rng.pick` 依索引取，改順序會改到生涯結果）」。
快照必然漂移，這是預期內的，要在提交訊息裡講明，不要讓它看起來像回歸。

## 規則與不變式

- **戰力點平均 == 2.0**（§11.1 硬約束）。
- **教練效果鍵全在 `EFFECT_KEYS` 內**——與「特質效果鍵被引擎消費」同一條紅線，
  只是母體換成 `COACHES`。
- **四個新鍵都有 clamp**，教練 + 史詩特質疊加不得突破上下界。
- **`coachRating` 不受影響**：本站不得有任何路徑改到它。
- **`state.coach` 仍是名字字串**，舊存檔不需要遷移。
- **§22.4 不變式**：教練評價與心理六維在任何版面都不得顯示——本站在 `transfer.js`
  與 `panel/team.js` 印的是**教練體系的效果**（可見層），不是評價，別印錯東西。
