# 電競人生 v5 企劃書——精簡重構版

> 基於 v4.10.1 規格分析，目標：大幅簡化架構、貼合小品遊戲定位，同時保留核心生涯模擬體驗。

## 一、v4 現狀分析：架構過度設計的問題

### 1.1 規模與定位的錯位

v4 是一份 **3757 行、254 KB** 的設計規格書，涵蓋的系統包括：

| 系統                      | 規模                     |
| ----------------------- | ---------------------- |
| 三層能力結構（六屬性＋十二技能＋隱藏心理六維） | 24 個數值維度               |
| 訓練系統（六選一活動＋兩階段判定＋卡片池）   | 含成功/失敗/大成功/大失敗四檔位      |
| 生命週期系統（每屬性 5 個曲線參數）     | 30 個隨機參數               |
| 事件卡系統（四池管理＋分類標籤）        | 訓練卡＋月度卡＋特殊卡            |
| 賽制系統（逐年演進＋多賽區＋席位變動）     | LMS→PCS→LCP 演進＋Swiss 制 |
| NPC 選手與戰隊資料庫            | 史實資料生成                 |
| 賽區背景對戰模擬（批量模擬引擎）        | 微觀數據＋動態評價              |

**核心問題**：一個「單局 30–50 分鐘」的純文字小品遊戲，承載了堪比 3A 級模擬經營遊戲的系統複雜度。v4 的設計原則寫著「直覺檢驗、防農檢驗、死路檢驗、心流檢驗」，但系統本身的複雜度已經違反了「直覺」原則——玩家無法憑電競常識推導出這麼多層的數值交互。

### 1.2 具體過度設計清單

1. **能力結構三層分離**：六屬性（可見可訓練）＋十二技能（屬性加權導出）＋隱藏心理六維（不可見）——三層抽象對小品遊戲來說是嚴重的認知負荷。

2. **生命週期曲線**：每屬性 5 個參數（peak_age／rise_k／fall_k／fall_accel／decline_pull），共 30 個種子隨機參數——玩家完全無法感知或操作這些參數的意義。

3. **賽制歷史演進**：主場聯賽隨年份演進（LMS→PCS→LCP）、賽段結構逐年變化（2015 春／夏→2025 三賽段）、MSI 停辦與復辦、世界賽賽制切換（小組賽→入圍賽→Swiss）——這些史實細節對遊戲體驗的邊際貢獻極低，但維護成本極高。

4. **NPC 與批量模擬引擎**：§23 NPC 選手資料庫＋§24 賽區背景對戰模擬——v4 甚至規劃了「純數學批量模擬引擎」來生成背景戰績，這已經偏離了「選手生涯模擬」的核心。

5. **事件卡四池管理**：persona／performance／psych／career 四池——分類過細，內容填充工作量巨大。

### 1.3 v4 保留的優點

以下設計值得在 v5 中保留：

- **月回合制**：一年 12 個月，每月選一個行動——節奏清晰。
- **體力是資源**：訓練與出賽消耗體力，休息恢復——核心取捨機制。
- **賽事事件序列**：賽前敘事→備賽戰術→戰術結算→比分→賽後敘事——儀式感強。
- **種子只決定天賦**：同種子不同人生——重玩性來源。
- **生涯傳記**：退役時生成專屬生涯總結——情感回饋。

## 二、v5 核心定位與設計原則

### 2.1 重新定位

> **一句話描述**：**「在 LoL 電競黃金年代，扮演一名職業選手，從新人打到退役。」**

- **類型**：純文字生涯養成小品
- **單局时长**：20–30 分鐘（v4 的 30–50 分鐘→縮短）
- **決策點**：60–80 個（v4 的 100–130 個→減少）
- **目標受眾**：LoL 電競觀眾，輕度模擬遊戲玩家

### 2.2 v5 設計原則（精簡版）

1. **一層能力**：取消三層分離，只有一組可見屬性。
2. **固定史實**：國際賽與世界賽對手固定為當年史實隊伍，不生成隨機 NPC。
3. **賽訓合一**：能力成長主要來自「跟隨賽程訓練」，而非抽象的每月選活動。
4. **賽事快報**：每場季後賽／國際賽後產出風格化報導。
5. **刪減優先**：任何系統若無法用一句話向玩家解釋清楚，就刪掉。

## 三、v5 具體改動方案

### 3.1 能力系統簡化（刪除三層結構）

**v4（刪除）** ：

- 六屬性（vit／agi／awr／tec／syn／dec）
- 十二技能（屬性加權導出）
- 隱藏心理六維（conf／drive／resl／...）

**v5（取代）** ：

改為 **五項選手能力**，直接對應比賽中的表現維度：

| 能力     | 說明      | 影響        |
| ------ | ------- | --------- |
| **對線** | 單人線壓制力  | 前期經濟、單殺能力 |
| **會戰** | 團戰判斷與操作 | 會戰勝率、傷害轉化 |
| **意識** | 地圖閱讀與決策 | 支援效率、視野控制 |
| **心態** | 大賽穩定性   | 關鍵局表現、失誤率 |
| **體能** | 續航與訓練量  | 傷病風險、訓練效率 |

**設計要點**：

- 五項能力 0–100，玩家可見且可追蹤成長。
- 取消「心理六維不可見」的設計——心態就是一個可見能力。
- 取消「技能」中間層——能力直接影響比賽模擬。
- 每項能力有「巔峰年齡」和「衰退速度」兩個簡單參數（而非 5 個曲線參數）。

### 3.2 訓練與成長系統重構（賽訓合一）

**v4（刪除）** ：

- 每月六選一訓練活動（健身房／團隊訓練賽／戰術覆盤／SOLO RANK／VOD 研究／休息）
- 兩階段判定（成敗→檔位）＋四檔位係數
- 訓練事件卡池

**v5（取代）** ：

改為 **「賽訓系統」** ——能力隨賽區賽程自然成長，玩家做的選擇是「訓練重點」而非「練不練」：

**賽程結構（簡化為全年固定節奏）** ：

| 月份      | 階段        | 玩家操作       |
| ------- | --------- | ---------- |
| 1–2 月   | 春季賽（常規賽）  | 選擇「訓練重點」一項 |
| 3 月     | 春季季後賽     | 賽事序列（五拍）   |
| 4 月     | MSI（若有資格） | 賽事序列       |
| 5–7 月   | 夏季賽（常規賽）  | 選擇「訓練重點」一項 |
| 8 月     | 夏季季後賽     | 賽事序列       |
| 9–10 月  | 世界賽（若有資格） | 賽事序列       |
| 11–12 月 | 休賽期       | 轉會／續約決策    |

**訓練重點（簡化為三選一）** ：

| 訓練重點 | 成長能力  | 體力消耗         |
| ---- | ----- | ------------ |
| 專注操作 | 對線＋會戰 | 中            |
| 專注大局 | 意識＋心態 | 低            |
| 體能強化 | 體能    | 高（短期透支換長期續航） |

**成長規則**：

- 每月常規賽期間，所選訓練重點的能力獲得固定成長（＋2～＋4，依當前值遞減）。
- 未選的能力獲得微量成長（＋0～＋1）。
- 體力影響成長效率（體力 > 60：正常；30–60：七折；< 30：五折）。
- 季後賽／國際賽期間不訓練，但比賽表現本身會影響能力（贏強隊→心態＋，輸弱隊→心態−）。

**刪除內容**：

- 訓練事件卡（大成功／成功／失敗／大失敗）
- 兩階段判定
- 訓練活動的複雜權重（主屬性 .7／副屬性 .3）

### 3.3 賽事系統簡化（固定史實對手）

**v4（刪除）** ：

- 逐年演進的賽制（LMS→PCS→LCP）
- 逐年變化的賽段結構（2015 春／夏→2025 三賽段）
- 逐年變化的世界賽賽制（小組賽→入圍賽→Swiss）
- NPC 選手與戰隊資料庫
- 賽區背景批量模擬引擎

**v5（取代）** ：

**固定年份範圍**：選擇一個「賽季」作為遊戲背景（如 2015、2018、2022 等），整個生涯就在該年份的電競環境中進行。

**固定賽制**：

- 各賽區統一為「春季賽→季後賽→MSI→夏季賽→季後賽→世界賽」的固定結構。
- 世界賽固定為「小組賽→淘汰賽」制（簡化，不模擬入圍賽／Swiss 等變體）。

**固定對手（核心改動）** ：

國際賽和世界賽的對手 **完全依照當年史實**，不隨機生成：

| 年份   | MSI 參賽隊伍                | 世界賽冠軍 | 世界賽亞軍 |
| ---- | ----------------------- | ----- | ----- |
| 2015 | EDG／SKT／AHQ／FNC／TSM／BJK | SKT   | KOO   |
| 2016 | SKT／CLG／RNG／FW／G2／SUP   | SKT   | SSG   |
| 2017 | SKT／G2／FW／TSM／WE／...    | SSG   | SKT   |
| 2018 | RNG／KZ／FW／FNC／TL／EVOS   | IG    | FNC   |
| 2019 | G2／SKT／IG／TL／FW／PVB     | FPX   | G2    |
| 2021 | RNG／DK／MAD／PSG／C9／...   | EDG   | DK    |
| 2022 | RNG／T1／G2／EG／PSG／...    | DRX   | T1    |

**對手強度**：

- 史實冠亞軍 = 遊戲中的 Boss 級對手（高能力值）
- 史實四強 = 強隊
- 史實小組賽隊伍 = 中堅隊伍
- 玩家戰隊的「強度」由五項能力的平均值決定，對戰勝率由此推算。

**賽區聯賽對手**：

- 固定為該賽區當年史實隊伍（如 2015 LPL 有 EDG、LGD、IG、OMG 等）
- 常規賽為循環賽，戰績由隊伍強度決定（無需模擬每場細節）

### 3.4 賽事快報系統（新增）

**目標**：在每次季後賽和國際賽的每場比賽結束後，產出類似虎撲賽事快報的短報導。

**快報格式**（約 150–200 字）：

```
【賽事快報】S5 世界賽 八強賽 Day 1
[隊伍A] 3-1 [隊伍B]

【戰報】
首局 [隊伍A] 憑藉 [選手名] 的 [英雄] 完美發揮先下一城。
次局 [隊伍B] 調整戰術扳回一局。
第三局 [隊伍A] 在 35 分鐘的遠古龍團戰中打出 0 換 4，奠定勝局。
第四局 [隊伍A] 未給對手機會，以 3-1 晉級四強。

【MVP】
[選手名]（[位置]）— [關鍵數據，如 12/2/8]

【下一場】
[隊伍C] vs [隊伍D]，[日期]
```

**觸發時機**：

- 季後賽每一輪（BO5）結束後
- MSI 每一場（BO5）結束後
- 世界賽每一場（BO5）結束後

**內容生成**：

- 使用預設模板＋比賽結果數據填充
- 關鍵選手 = 比賽中能力值最高的選手
- 關鍵數據 = 根據能力值模擬生成（對線壓制數／會戰參與率等）
- MVP = 該場表現最佳的選手

**儲存與回顧**：

- 所有快報儲存於「生涯紀念冊」
- 退役時可回顧整個生涯的重要賽事

### 3.5 特質系統簡化

**v4（刪除）** ：

- 事件卡四池管理（persona／performance／psych／career）
- 特質合成系統（配方表）
- 天生特質（0–2 個）
- 隱藏特質的 Rogue 探索玩法

**v5（取代）** ：

**特質 = 賽事中取得的「標籤」** ，而非抽象的隱藏系統：

| 取得方式    | 範例特質   | 效果                   |
| ------- | ------ | -------------------- |
| 贏得重要比賽  | 「大賽選手」 | 國際賽能力＋5%             |
| 擊敗強敵    | 「強隊殺手」 | 對戰強隊時心態＋10           |
| 連續高水準表現 | 「穩定核心」 | 每場比賽最低表現提升           |
| 輸給弱隊    | 「爆冷陰影」 | 對戰弱隊時心態−5（可透過後續勝利消除） |
| 長期擔任先發  | 「隊魂」   | 團隊默契加成               |

**特質上限**：同時持有最多 3 個特質（取代 v4 的複雜合成樹）。

**刪除內容**：

- 事件卡池管理
- 特質合成配方
- 隱藏心理六維與特質的交互

## 四、其他系統的修正建議

### 4.1 體力系統（保留但簡化）

v4 的體力系統已經相對成熟，保留核心機制但刪除過度設計：

- **保留**：上限 100、每月自然恢復＋10、訓練消耗、休息恢復＋50
- **保留**：低體力懲罰曲線
- **刪除**：體能（vit）的三條體質修正曲線（恢復量、訓練消耗、受傷機率）——改為體能單一能力直接影響體力上限和恢復速度
- **刪除**：restYieldMul 的複雜曲線

### 4.2 時間結構（大幅簡化）

v4 的逐年賽制演進刪除，改為：

- 玩家在遊戲開始時選擇一個「賽季年份」（2015–2022）
- 整個生涯的賽制、對手、Meta 都固定在該年份
- 生涯長度：5–8 年（視表現而定），而非 v4 的 10 年

### 4.3 退役與結局（保留核心）

v4 的三層退役機制保留核心概念，簡化為：

- **自然退役**：年齡增長＋能力衰退到一定程度
- **榮耀退役**：贏得世界賽後可選擇光榮退役
- **被淘汰**：長期板凳或合約到期無隊伍續約

### 4.4 生涯傳記（保留並強化）

v4 的生涯傳記是優秀設計，v5 中強化為：

- 整合賽事快報
- 列出生涯高光時刻（擊敗的強敵、贏得的冠軍）
- 獲得的所有特質
- 最終能力值與歷史定位評價

### 6.2 技術建議

1. **代碼重構**：v4 的 `ESPORT-DESIGN-V4.md` 有 3757 行，建議 v5 設計文件控制在 **800 行以內**。

2. **數據簡化**：史實隊伍數據可直接以 JSON 靜態儲存（每年約 20–30 支隊伍），無需資料庫或批量模擬引擎。

3. **快報生成**：使用模板引擎＋比賽數據填充，無需 LLM。

4. **存檔相容**：v5 應直接廢除 v4 存檔相容性（如同 v4 所做），避免繼承包袱。
