## 為什麼做這件事

現行觸發是**隨機不重複**：`rng.pick(availableEvents(state))`，最近 6 張不重抽，
每個賽段抽 2 張。

V4 §12.1 要**條件優先**：

```
1. 收集本月所有條件命中的事件卡
2. 取最高優先度者為候選
   - 單一：直接觸發（事件一）
   - 多張同優先度且互斥：在候選間隨機抽取一張
3. 擲「第二張」機率
   - 命中：再取一張（優先從剩餘條件事件按優先度，無則隨機池）；須與事件一做互斥檢查
   - 未命中：本月僅事件一
4. 若第 1 步候選為空：隨機池抽事件一，再擲第二張
```

差別在於**事件變成對玩家狀態的回應**，而不是純粹的隨機裝飾。狀態符合條件時該來的
事件會來，這是 rogue-like 的 build 探索能成立的前提。

S14 在 `phases/month.js` 的第 4 步留了 `TODO(S17)` 等這一站。

## 範圍

### 要做

**必讀規格**：V4 §12（事件卡系統，含 §12.1 觸發模型與 §12.2 事件卡結構）。

**1. 新增 `src/engine/eventTrigger.js`**

實作 §12.1 的四步演算法。純函式：吃 `state` ＋ 事件庫 ＋ `rng`，回傳這個月要出的
1~2 張卡。**不做呈現**——呈現留在 `phases/shared.js` 的 `drawEvent`。

這個切分很重要：觸發是規則（可測），呈現是敘事（難測）。分開之後觸發邏輯可以寫
純函式測試，不必跑完整生涯。

**2. `src/data/events.js` 的卡片結構擴充**

V4 §12.2：

```
事件卡 = {
  id, 敘事文本,
  觸發條件（時代/屬性範圍/特質/心理範圍/賽季階段）,
  優先度,
  互斥群組,
  選項（2–4 個）,
  各選項結果（屬性/體力/心理/特質線索/觸發後續事件）,
  成功判定 = f(體力, 相關屬性, 相關心理, 特質)
}
```

現有 26 張卡要**補上新欄位**（`when` 觸發條件、`priority`、`exclusive`），
沒有條件的卡就是隨機池成員。

**新增的結果欄位**：
- **體力**（S13 已實作）
- **心理六維**（S12 已實作，現在只有機械對映的暫時狀態）
- **觸發後續事件**（連鎖）

**成功判定改成 `f(體力, 相關屬性, 相關心理, 特質)`**——現行是固定的 `opt.odds`
加上 `giftedDice` 的 +20。新公式讓低體力時事件也更容易失敗，跟訓練成功率同一套邏輯。

⚠ **這一站不寫新卡片內容**（那是 S18）。只改結構、補既有 26 張的欄位。

**3. 接上 `phases/month.js` 第 4 步**

「每回合固定觸發 1 張，有機率觸發 2 張」（§12.1 最後一句）。第二張的機率值要定，
寫進規格書。

**4. `phases/shared.js` 的 `drawEvent` 拆分**

現行 `drawEvent` 一手包辦抽卡 ＋ 呈現 ＋ 結算。抽卡那段交給 eventTrigger.js，
`drawEvent` 改成吃一張指定的卡來呈現。

⚠ `drawEvent` 裡有一串硬寫的特質解鎖判斷（`if (flags.popular && unlockTrait(...))`
那十來行）。**這一站不動它們**，S19a 重整特質時再處理。

**5. 讓 S07 的「事件互斥」SKIP 生效**

檢查同一回合的兩張卡不屬於同一互斥群組。這是本站最重要的驗證。

**6. 為觸發引擎寫純函式測試**

新增 `tests/kernel/eventTrigger.mjs`。要涵蓋四步演算法的每個分支：
- 有條件命中 → 取最高優先度
- 多張同優先度 → 隨機抽一張
- 候選為空 → 落到隨機池
- 第二張命中 → 互斥檢查生效
- 第二張未命中 → 只出一張

### 不要做

- **不要寫新的事件卡內容**（S18）。這一站只改結構
- **不要重整特質解鎖那串硬寫的判斷**（S19a）
- **不要碰扮演卡系統**（`drawRoleplay`，S20）。它有自己的抽卡邏輯（依權重、
  不擲骰決定成敗），跟事件卡是兩套，刻意的
- **不要把觸發與呈現寫在一起**
