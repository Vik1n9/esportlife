## 範圍

### 要做

**1. 修「傳奇要罕見」不變式**（`tests/regression/smoke.mjs:67`）

檢查式是 `tierCounts.spread[0] * 3 <= tierCounts.focus[0]`，現況 `5 * 3 = 15 > 8`。

`spread`（新手打法＝平均分配訓練點）不該打得出跟 `focus`（老手打法＝集中投資）
一樣多的傳奇。現在 5 vs 8 表示新增的傳說特質對「隨便練」的打法也給得太大方。

**方向已經被記錄過**，照 `docs/superpowers/specs/2026-08-12-four-tier-trait-synthesis.md`
的結論走：

> 頂端加成刻意用**成長×N 與突破上限**（練得越準越吃得到），而不是平白加分——平白
> 加分會幫新手打法也越過傳奇門檻。實測時把傳說加 `careerScore` 會讓新手打法出現
> 傳奇、`spread*3 <= focus` 失敗，故棄用。

所以先查 `src/data/epics.js` 的六個 `LEGENDARY_TRAITS`，找出哪幾個的效果是「平白
加分」性質（`careerScore`、`ovrAdd` 這類與練得準不準無關的），改成吃準度的形式
（`growthMult`、`abilityCapUp`、階梯門檻下移）。

**同時要守住**：`史詩持有率`不得明顯下滑（那份 spec 記的基準是 63/80），
`老手打法：傳奇不得超過三成` 也不能因此破掉。

**2. 重刷 golden 基準**

```bash
npm run test:golden
```

這會把 `tests/regression/golden.json` 重寫。**一定要在第 1 項改完之後才刷**，
否則刷的是錯的基準。

**3. 提交並打 tag**

```bash
git add -A
git commit -m "..."
git tag v4-before
```

commit 訊息要說明 golden 基準為什麼變（照 `tests/regression/golden.mjs` 檔頭的要求）。

### 不要做

- **不要碰 `ESPORT-DESIGN-V4.md`**（那是 S08）
- **不要開始任何 V4 的重寫**（屬性刻度、技能表、月回合……全部不是這一站）
- **不要淨室重寫任何檔案**（那是 S03/S04/S05）
- **不要改測試的檢查式來讓它變綠**。`spread*3 <= focus` 是刻意設計的門檻，要改的是
  特質效果不是門檻。如果你判斷門檻本身有問題，寫進交接筆記讓人決定，不要自己改

## 規則與不變式

跑完 `npm test` 全綠，而且下面四項要同時成立（都在 `tests/regression/smoke.mjs`）：

- 老手打法：傳奇不得超過三成
- 新手打法：傳奇要罕見（不到老手的三分之一）
- 老手平均巔峰 OVR 至少比新手高 1.5
- 五個生涯等第都出現得到

另外對照 `docs/superpowers/specs/2026-08-12-four-tier-trait-synthesis.md` 的實測表：

| 指標 | 該 spec 的基準 |
| --- | --- |
| 平均巔峰 OVR | 59.9 |
| 史詩持有率 | 63/80 |
| 稀有持有率 | 69/80 |
| 傳說持有率 | 23/80 |

改完之後這幾個數字不該大幅偏離（傳說持有率本來就會降，那是目的；其餘三個要穩）。
測試 log 會印出來，抄進交接筆記。
