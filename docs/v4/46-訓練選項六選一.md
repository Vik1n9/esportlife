理由：動的是**成長模型的入口**——`TRAINING_ACTIVITIES` 是 §5.3 成長公式唯一的
權重來源，改它等於同時改動屬性曝光分布、體力經濟與訓練卡池三件事，而三者各自有
回歸不變式在守。休息從「純資源」變成「也給成長」還會動到 §6.1 的休息節奏紅線。
判斷密度高，不是照表填值。

## 為什麼做這件事

§5.2 的訓練活動菜單自 S16 上線後一直是八項：個人機械訓練／強化訓練賽／戰術復盤／
體能健身／排位衝分／英雄池練習／休息／復健預防。八項的規則彼此不同構——有的吃
2 個屬性、有的吃 3 個，有的（英雄池／休息／復健）完全不漲屬性。玩家每個月要在
八個規則各異的選項之間比較「體力／屬性／成功率」三欄才選得下去。

這對一款**手機網遊**來說太重。本站把菜單收斂成 **6 個選項對應 6 個基礎屬性**，
每個選項一主一副、六組配對互不重複，讓決策退化成一句話就講得完的形狀：
「這個月要哪兩個屬性，體力還撐不撐得住。」

順帶把「休息」拉進同一套規則——它現在也給屬性成長，於是六個選項是**同構**的，
不再有「三個會漲屬性、三個不會」這種要另外記的例外。

**2. 休息也給屬性成長（低體力給越多）**

休息**不分成敗、不抽卡、不受傷、不動心理**——成長是決定性的，倍率讀「休息**前**的體力」。

在 `src/engine/stamina.js` 新增，**照 `successMul` 的寫法長寫**（用既有的 `BAND_FRESH`／
`BAND_TIRED`，不要為它引進 `lerp` 這種新helper——這個檔的曲線家族目前都是長寫，
多一種寫法只會讓下一個人以為兩者有語意差別）：

```js
/**
 * 休息的屬性成長倍率（§6.2 曲線家族的新成員）：越透支，休息學到的越多。
 * 這條曲線本身就是防濫用機制——滿血休息 ≈ 訓練月的 10%（等於白費一個月）。
 */
export function restYieldMul(s) {
  const v = clamp(s, 0, STAMINA_MAX);
  if (v >= BAND_FRESH) return 0.15 - ((v - BAND_FRESH) / (STAMINA_MAX - BAND_FRESH)) * 0.05;
  if (v >= BAND_TIRED) return 0.15 + ((BAND_FRESH - v) / (BAND_FRESH - BAND_TIRED)) * 0.20;
  return 0.35 + ((BAND_TIRED - v) / BAND_TIRED) * 0.20;
}
```

落點：100→0.10、60→0.15、30→0.35、0→0.55，區間內線性內插（與 §6.2 同一條原則）。

`resolveTraining` 的 `rest` 分支改成先算成長、再回體力：

```js
if (activity.kind === 'rest') {
  const before = staminaOf(state);            // ⚠ 先讀，再 recover
  const mul = restYieldMul(before);
  const drive = driveMul(state);
  const gains = [];
  for (const [attr, w] of Object.entries(activity.weights)) {
    const gained = investAttr(state, attr, TRAIN_YIELD * w * mul * drive);
    if (gained > 0) gains.push({ attr, points: gained });
  }
  recover(state, REST_RECOVER);
  return { activity, kind: 'rest', recovered: staminaOf(state) - before, gains };
}
```

休息**不壓** `tempInjuryRisk`——受傷風險交給體力管理、體能屬性（S47）與事件卡。

## 規則與不變式

- **權重和為 1**（既有測試 `training.mjs:38`）——.7/.3 照樣過。
- **錯位輪替**（本站新增）：六個選單活動的主屬性集合 == 副屬性集合 == `ATTRS`，
  且每個活動主 ≠ 副。這條守住整份設計的骨架，之後有人加活動會立刻被擋下。
- **兜底卡恰好 1 張**（`training.mjs:126`）：搬標籤後要重新成立，母體換成五活動。
- **編輯器與引擎同源**：`ACTIVITY_KEYS` 逐字等於
  `TRAINING_ACTIVITIES.filter(a => a.pool).map(a => a.id)`，且每張訓練卡的 `activity`
  值都在其中（沒有標著不存在活動的死卡）。
- **§5.4 不顯示失敗率**：`rest` 的 `successRate` 是 `null`，不是 100。
- **§22.2.1 三欄**：`note` 與結構化欄位仍須同源（S39 定的規則，別退化成手抄字串）。
