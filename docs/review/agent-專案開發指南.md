# AI Agent 專案開發管理指南

## 核心問題與管理原則
在由 AI Agent 執行的長期專案中，主要成本並非來自「執行任務」，而是來自「每次對話重新理解專案」。此成本具備三項特性：乘法效應（每次對話皆需支付）、隱蔽性（無系統主動警示）以及單向增長性（文件僅增不減）。

核心管理原則：每一項專案知識都必須選擇其「計費模式」。
- 寫入規則檔：成本最高，每次對話皆需讀取。
- 寫入測試或檢查腳本：成本為零，僅在觸發或失敗時產生成本。
- 寫入自動化腳本：成本為零。
- 寫入按需拉取的文件：僅在實際需要時產生成本。

「寫入規則檔」應為最後手段，而非預設選項。

## 階段零：外部工具與環境建置
目標為盤點、安裝並驗證專案所需之所有非自行開發的外部能力。

1. 盤點外部能力：包含執行環境、專案相依套件、流程用 CLI 工具、Agent 擴充功能與外掛。
2. 驗證可用性：每個工具安裝後必須執行煙霧測試。嚴禁在規則檔中強制要求使用未經安裝驗證的工具。
3. 定義必要程度與降級路徑：區分硬相依、流程工具與手動工具。流程工具必須明確定義環境缺失時的降級執行路徑。
4. 消除功能重疊：單一職責僅保留一個工具。避免輸出壓縮工具與規則檔中的風格定義重複。
5. 優先使用自動化接管：若工具提供 Hook、Wrapper 或 Proxy 等自動接管機制，應優先採用，並刪除規則檔中的對應提醒。
6. 環境可重現：提供單一的 Setup 腳本，確保在乾淨環境下可一次性完成安裝與驗證。
7. 清理冗餘：移除未使用的 Agent 工具與外掛，以減少每次請求的隱性載入成本。

## 階段一：規則檔撰寫規範
規則檔為每次對話皆會載入之文件，具備最高的字元成本。

1. 預算控制：設定嚴格的 Token 上限，並由檢查腳本強制執行。
2. 允許包含的內容：專案不變之事實、必要工具之使用方式與降級路徑、標準流程順序、輸出格式規範、詳細規則之索引。
3. 嚴禁包含的內容：可由自動化測試驗證的規則、僅適用於特定目錄的規則、完整的工具指令表、專案現況描述、通用工程教學、架構文件全文。
4. 標註執行者：每條規則必須標註負責檢查的機制。無法透過自動化驗證的規則應予以刪除。
5. 語法規範：使用祈使句、具體檔名與指令，省略理由說明，禁止使用依賴記憶之表述。
6. 分層管理：善用子目錄規則檔，僅在 Agent 異動該目錄時才載入特定規則。

## 階段二：任務單位與狀態管理
目標為定義 AI 可精確讀取與處理的資料結構。

1. 定義工作單位：將任務切分為單次對話可完成之規模，具備明確且可驗證的完成定義，並設定規模上限以避免中途耗盡額度。
2. 結構化狀態資料：專案狀態必須以結構化資料儲存，嚴禁使用表格或散文描述狀態。
3. 定義文件壽命：
   - 規則檔：永久保留。
   - 規格與設計文件：永久保留，按需切片讀取。
   - 決策紀錄：預設不載入，僅於修改該決策時讀取。
   - 交接筆記：僅保留至下一個任務完工為止，其後進行精簡與刪除。
4. 單一資料來源：常數與設定值僅能存在於單一權威來源，文件中的數據應由腳本自動生成。

## 階段三：專案專屬工具與防護機制
目標為建立自動化流程，減少 Agent 讀取與處理冗餘資訊的成本。

1. 統一驗證入口：建立單一指令作為判斷任務是否完成的唯一標準，內部整合程式碼檢查、型別檢查與單元測試。
2. 輸出配置：測試與建置工具應設定為僅輸出失敗訊息，關閉進度動畫與色碼，並啟用自動修復功能。
3. 專屬腳本開發：
   - 狀態查詢：提供當前進度與下一步任務。
   - 上下文組裝：將開始任務所需之多份文件，自動壓縮並組裝為精簡的切片簡報。
   - 狀態更新：自動化處理收尾時的狀態異動。
   - 資源回收：自動掃描並清理過期之交接筆記與工作日誌。
4. 自動化守門：將規則轉化為可執行的檢查。錯誤訊息必須具備自我修復指引，使 Agent 無需讀取額外文件即可修正問題。
5. 預算量測：實作腳本以估算每次任務的前置 Token 消耗量，超過門檻即阻擋執行，並掛載於統一驗證入口。

## 階段四：接手既有專案流程
接手已產生冗餘文件之專案時，必須嚴格遵循以下順序：

1. 階段 A（測量）：測量文件與程式碼比例、文件刪除率、規則檔大小、最大文件體積、跨檔重複率，並盤點規則檔中強制要求但環境中缺失的工具。
2. 階段 B（止血）：補齊環境設定與降級路徑、建立預算量測基線、精簡規則檔、移除已被腳本取代的全檔案讀取流程。此階段嚴禁修改文件內容。
3. 階段 C（建立防護）：將規則檔中無執行者的規則，逐條轉化為自動化檢查或移至子目錄規則檔。
4. 階段 D（收斂內容）：統一資料來源、定義文件壽命、拆分大型文件、將決策理由抽離為預設不載入之紀錄。

## 階段五：防止系統劣化機制
為確保系統不隨時間推移而重新膨脹，必須將以下五項檢查掛載於統一驗證入口：
1. 工具煙霧測試：規則檔強制之工具若未安裝，則驗證失敗。
2. 預算上限：前置 Token 消耗量超過門檻，則驗證失敗。
3. 規則檔字數：超過字數上限，則驗證失敗。
4. 壽命檢查：自動掃描並回報已過期之文件。
5. 資料一致性：生成檔案與原始來源不一致，則驗證失敗。

## 最小可行性實作規模
依據專案規模調整實作範圍：
- 短期原型：僅執行階段零（環境與工具建置）。
- 小型專案：執行階段零、統一驗證入口、輸出配置、預算量測。
- 長期專案：增加規則檔上限控制與守門機制骨架。
- 大型專案：完整執行所有階段。
