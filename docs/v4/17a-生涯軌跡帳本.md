## 為什麼做這件事

V4.1 增訂了兩個系統，它們要的資料是同一批：

- **§14.3 替代性生涯路線**：五條 `route` 路線的觸發條件裡，有四格 `state` 現在沒有。
- **§15.5 生涯傳記生成**：拼接文本的事實來源。

現況的 `state` 只記得了「總數」，記不得「過程」：

| 要什麼 | 現在有什麼 | 差在哪 |
| --- | --- | --- |
| 國際賽勝率 | `intlAppearances`、`worldsWins`、`msiPodiums` | 只有**出場次數與名次**，沒有勝負場 |
| 歷任戰隊 | `team`（現在這支）、`teamYears` | 換過哪幾支查不到 |
| 降級危機次數 | `disbandThreat`（布林） | **每季重置**，累計不下來 |
| 個人獎項數 | `honors[]`（字串陣列） | 要靠 `includes('MVP')` 撈，脆弱 |
| 關鍵事件 | `recentEvents`（暫存） | 只留最近幾張，不是生涯紀錄 |

所以這一站先把帳本記起來，**S17b（生涯任務引擎）與 S21a（生涯傳記）才有東西可讀**。
它是那兩站的共同前置，單獨做的價值就在這裡——兩站都不必自己去改 `phases/`。

## 範圍

### 要做

**必讀規格**：V4 §14.3（五條路線各讀哪一格）、§15.5（傳記的資料來源限定）、
§20.2（state 結構）。

**1. `src/engine/state.js` 新增帳本欄位**

```js
// 生涯軌跡帳本（V4 §14.3／§15.5）。與既有的總數欄位分開：
// 總數回答「拿了幾個」，帳本回答「怎麼走到這裡的」
intlRecord: { W: 0, L: 0 },   // 國際賽系列賽的勝負場（MSI ＋ 世界賽）
teamHistory: [],              // [{team, league, fromYear, toYear, firstSeasonRating, teamAvgRating}]
disbandCrises: 0,             // 生涯累計的降級危機／重建期次數
awards: 0,                    // 個人獎項數（MVP／最佳新人／單殺王／全明星）
milestones: [],               // [{year, kind, text}] 給 §15.5 拼接用的事實流
```

`SAVE_VERSION` 13 → **14**。

**2. 在既有掛載點記帳**

| 檔案 | 記什麼 |
| --- | --- |
| `phases/msi.js`、`phases/worlds.js` | `intlRecord` 的勝負場；晉級／淘汰寫進 `milestones` |
| `engine/market.js`、`phases/transfer.js` | 換隊時關掉上一筆 `teamHistory` 並開新的一筆；被開除／解散寫進 `milestones` |
| `engine/game.js` | `disbandThreat` 由 false→true 的那一次 `disbandCrises += 1`（**不是每季都加**） |
| `phases/seasonEnd.js`、`phases/split.js` | `awards += 1` 與現有的 `honors.push` 同一個地方，不另外撈字串 |

**3. `teamHistory` 的首季評價**

「流浪傭兵」要「每次轉會後首季教練評價 > 隊伍平均」。轉會後第一個賽季結束時，把
該季的教練評價與隊伍平均一起寫進當筆 `teamHistory`。隊伍平均讀 `state.mates`——
`engine/mental.js` 已經有隊友強度，不要新造一套。

**4. 純讀取的查詢函式**

`src/engine/ledger.js`（新檔）：`intlWinRate(state)`、`assistsPerGame(state)`、
`distinctTeams(state)`、`longestTenure(state)`。純函式，吃 state 回傳數字。
S17b 與 S21a 都讀它，**條件判斷不准直接翻 `state` 的原始欄位**——那樣改一次欄位要
改三個地方。

### 不要做

- **不要做任務卡的觸發判斷**（S17b）。這一站只記帳，不判斷
- **不要做傳記文本**（S21a）
- **不要動既有的總數欄位**（`intlAppearances`、`worldsWins`……）。帳本是**加上去**的，
  不是取代——`engine/career.js` 的評分還在讀那些
- **不要用字串比對重算獎項**。`awards` 在 `honors.push` 的同一行加，不要事後 `includes`
- 不要碰 `positionPower` 的任何乘法項（S12 交接筆記第一節）
