## 為什麼做這件事

兩件事：

**1. 賽事五拍讀不出是一場系列賽。** §15.2 的五拍（賽前／備賽戰術／備賽結算／
結果／賽後）目前是五張與其他卡同級的卡片，散在事件文本區裡。§1.2 把
「敘事儀式感：賽事以事件序列呈現，五拍結構」列為三大核心體驗之一——
散成五張同級卡就讀不出結構。§22.1（v4.6.1）因此明訂**五拍必須成組呈現**。
⚠ S37 交接筆記點名：這條不是美化，別當 nice-to-have 砍掉。

**2. 事件文本區是無界捲軸。** 長生涯往下堆，只有年度折疊，沒有分類篩選也沒有
跳轉。§22.1（v4.6.1）新增日誌檢視控制。

## 範圍

### 要做

**1. 卡片分類（零呼叫點改動）**

`card()` 工廠住在 `src/phases/shared.js`，全專案 **91 個呼叫點**。
**不要逐點加參數**——加一個帶 `kind` 的工廠，各 phase 檔把 `card` 的來源換掉，
**一檔一行**：

```js
export const kinded = (kind) => (tone, title, body) => ({ type:'card', tone, title, body, kind });
```

分類建議（施工時逐檔確認，不要憑檔名推斷）：
訓練／賽事／事件／市場／賽季結算。

`kind` 是**純新增欄位**——既有測試只斷言 `beat.type === 'card'` 與 `beat.title`，
不會紅。

**2. 賽事五拍成組**

- 五拍的發射處（`src/phases/seriesEvent.js`）額外帶 `series` 標識（函式內已有
  賽事標題變數，直接用）。
- `src/ui/log.js` 偵測**連續同 `series` 值**的卡片，收進同一個 `.series-block`，
  標頭一列（賽事名／對手／BO 數）。
- ⚠ 五拍中間會插入 `choice`（第 2 拍備賽戰術，S39 已確認走決策槽而非 inline），
  分組判斷要能跨過它。

**3. 檢視控制**

- 事件文本區上方一排分類篩選 chips（全部／賽事／訓練／事件／市場）。
  卡片掛分類屬性，篩選**純靠 CSS 屬性選擇器**——不重繪、不重跑 generator，
  篩選是純檢視操作、不改變任何遊戲狀態。
- 年度跳轉：年度分隔線建區塊時登記進目錄，窄螢幕用下拉選單放在 chips 列右側。
  S42 會把它升級成寬螢幕左欄常駐——**登記結構要讓 S42 直接取用**。
- 既有的年度折疊行為保留（`src/styles.css` 檔頭鐵則列有這條）。

### 不要做

- **不逐點改 91 個 `card()` 呼叫**。
- **不動 `#board`**（S38）、**不動 `choice` 分派**（S39）、**不動 `#panel`**（S40）、
  **不加斷點**（S42）。
- **不讓篩選影響存檔或引擎**。

## 規則與不變式

- `kind`／`series` **皆為純新增欄位**，既有斷言不碰。
- **單一來源規則**：分類鍵存機器可讀值，顯示字串由鍵導出——不要反過來解析標題文字
  判斷分類（那是下一個空格 bug 的溫床）。
- 篩選與跳轉不得改變引擎狀態或存檔。
- `src/styles.css` 檔頭鐵則（年度折疊）不得失效。
