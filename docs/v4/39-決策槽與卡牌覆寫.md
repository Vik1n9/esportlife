# S39 · 決策槽與卡牌覆寫（§22.2／§22.2.1）

狀態：完成（2026-08-17）
前置：S38
預估：1 session
推理難度：高
建議模型：Opus 5（`claude-opus-5`）
理由：本站是壬組唯一動到 **beat 協定**的站（`choice` 加 `slot`），改的是引擎與 UI
的界面，而且 `choice` 有 11 個發射點、分流錯了沒有任何測試會紅。其餘四站都只在 UI 層。

---

## 為什麼做這件事

§22.2 的**卡牌覆寫整條未實作**（S37 盤點，附錄 #75）。規格原文：

> **卡牌覆寫**（按鈕直接出現在文本區卡牌下方，卡牌結束歸還決策槽）：
> 1. 訓練事件卡　2. 月度事件卡　3. 生涯任務卡開卡／達成
> 4. 賽事五拍（§15.2）：第 2 拍備賽戰術選項**回到底部決策槽**。

現行實作把**所有** `choice` beat 一律送進底部決策槽（`src/ui/runner.js`）。
第 4 條看起來剛好正確，但那是因為全部都在底部，不是因為有分流。

分兩處的理由（§22.2 v4.6.1 補記）：1–3 是卡牌內的即時反應，選項留在敘事旁邊，
視線不必在「讀文本」與「按按鈕」之間來回；4 與訓練菜單同性質（規劃型決策，
要對照屬性條與體力才選得下去），所以回到決策槽。

另外兩項 §22.2.1 不變式也沒做到：決策槽會依當月選項數量抽長縮短（位置與高度隨
回合跳動），訓練選項的三段資訊（體力增減／影響屬性／預期成功率）被壓成單行字串。

## 範圍

### 要做

**1. `choice` beat 加 `slot` 欄位**

- 值域：`'act'`（預設，決策槽）／`'inline'`（卡片下緣）。
- **由發射端指定，不由 UI 猜**。⚠ S37 交接筆記點名：讓 UI 依 beat 內容猜，
  猜錯的那天沒有測試會紅。
- 現行 `choice` 共 11 個發射點。需改為 `'inline'` 的是 §22.2 的 1–3：
  月度事件卡、扮演卡、訓練事件卡、生涯任務卡開卡／達成。
  **維持 `'act'`**：賽事五拍第 2 拍備賽戰術（§22.2 第 4 條明訂）、訓練菜單
  （決策槽本體）、轉會與退役等階段決策。
- 逐點確認一次，不要憑檔名推斷。

**2. UI 分派**（`src/ui/runner.js`／`src/ui/log.js`／`src/ui/actions.js`）

- `'inline'`：新的 `askInline()`，把選項接在**剛才那張卡的下緣**
  （`src/ui/log.js` 需記住最後一張卡的節點）。
- 選定後**就地換成定格文字**（「你選了 X」，`--dim`，不留可按外觀），
  卡牌結束**歸還決策槽**（§22.2 原文）。
- `'act'`：維持現行行為。

**3. 決策槽三模式標題**（§22.2 表格）

常規月「本月訓練」／休賽期「休賽期行動」／賽事期「備賽戰術」。
模式由 beat 帶下來（引擎已有 `title`），UI 只負責顯示，不自行判斷月份。

**4. 訓練選項結構化**（§22.2.1 第三條）

- `src/engine/training.js` 的 `trainingMenu` 在既有 `note` 字串之外**增加結構化
  欄位**（體力增減／影響屬性鍵／預期成功率）。三段值 `activityNote` 已經算好，
  只是被 join 成一條字串——**不要重算，拆出來就好**，也**不要移除 `note`**
  （純新增，既有呼叫端不受影響）。
- `src/ui/actions.js` 把選項畫成三欄可掃讀，並在 hover／focus 時呼叫 S38 的
  `highlightAttrs(attrKeys)` 讓上方屬性條對應列高亮。
- ⚠ **仍然不顯示失敗率與細分機率**（§5.4 原則不變）。

**5. 決策槽不跳動**（§22.2.1 第二條）

`#act` 給最小高度，內容超出改槽內捲動，取代現行「依選項數抽長縮短」。

### 不要做

- **不改事件卡／任務卡的內容或機率**——本站只動呈現位置。
- **不動 `#board`**（S38 已定案）、**不動 `#panel`**（S40）、**不加斷點**（S42）。
- **不移除 `trainingMenu` 的 `note` 欄位**。

## 規則與不變式

- **`slot` 是純新增欄位**：既有測試只斷言 `beat.type` 與 `beat.title`，加欄位不會紅。
- **`trainingMenu` 的 `note` 保留**——單一來源規則：三段值只算一次，
  結構化欄位與 `note` 都從同一次計算導出，不要出現第二份手抄本。
- 不顯示失敗率與細分機率（§5.4）。
- 心理六維與教練評價不得顯示（§22.4）。
- `src/styles.css` 檔頭「鐵則」註解要跟著補（`#act` 的最小高度是新的載重規則）。

### `trainingMenu` 結構化欄位最終命名

`note` 保留，結構化欄位與它同源于 `training.js` 的 `activityInfo`（算一次）：
`staminaDelta`（正＝恢復）、`attrs`（影響屬性鍵陣列；英雄池／休息／復健為空）、
`effectText`（中段顯示字：屬性名串接／練英雄專精／恢復體力／降低受傷風險）、
`successRate`（整數百分位；休息／復健為 `null`）。測試以欄位重建 note 逐字比對
（過寫入端運算式，不手抄字串）。

### `askInline` 與 `askChoice` 的生命週期差異

- 兩者都設 `awaitingInput`（屬性條〔+N〕靠它避開等待期）、都回 Promise<option.id>。
- `askChoice` 選定後 `clear(#act)`——決策槽留空等下一個 beat 填。
- `askInline` 不碰 `#act`（決策槽因而「自動歸還」——它從沒被佔用）；選定後選項組
  **就地換成定格文字**（`.inline-opts.picked > .inline-picked`，「你選了 X」），
  留在卡片裡成為敘事的一部分。
- 錨點：`ui/log.js` 的 `lastCard()` 記最後一張卡的節點；divider／loose 會清掉。
  防呆退回：找不到錨點時 `askInline` 轉調 `askChoice`（引擎層測試守著這不會發生）。
- ⚠ `actions.js ↔ attrbar.js` 現在是循環 import（`highlightAttrs`）——兩邊都只在
  事件回呼裡用對方，模組求值期零相依，瀏覽器 ESM 實測無礙；改成第三方共檔前先確認
  沒有新增求值期呼叫。
