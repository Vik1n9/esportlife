# 00 · 共通規則

**每個 session 開工前都要讀這份。** 不管你要做哪一站。

## 一、repo 事實

零建置、零相依。沒有 `npm install`，沒有打包器。純 ES modules。

```bash
npm test                    # = node tests/run.mjs，跑全部（約 0.8 秒，8900+ 項檢查）
node tests/run.mjs kernel   # 只跑某一區（kernel / phases / history / regression）
node tests/run.mjs series   # 只跑檔名或 suite 名符合的
npm run serve               # = python3 -m http.server 8080，然後開 localhost:8080
```

引擎完全不依賴 DOM，所以測試在 Node 裡實跑 160 段完整生涯。**任何引擎改動都必須
在 Node 測試裡驗證，不能只靠瀏覽器看。**

`tests/run.mjs` 自動掃 `tests/{kernel,phases,history,regression}/*.mjs`，新增 suite
不必改 runner。每個 suite 匯出 `name` 與 `async run({ check, log })`。

⚠ **現況不是全綠**：四階特質合成那一輪紅著提交，2 項檢查失敗。基準與紅燈細節見
[`00b-穩定點快照.md`](00b-穩定點快照.md)，修綠是 [`01-穩定點.md`](01-穩定點.md)。

### 目錄分層

```
src/
├── main.js       進入點
├── core/         種子化亂數
├── data/         純資料，零邏輯
├── engine/       規則與流程，不碰 DOM
├── kernel/       跨階段共用的計算核心（強度、系列賽、小組賽、特質修正）
├── phases/       一個賽事一個檔，各自 export { kind, run }
└── ui/           唯一碰 DOM 的一層
```

依賴方向是單向的：`ui → engine/phases → kernel → data → core`。
**phases 不 import `engine/game.js`**——主迴圈認得階段，階段不認得主迴圈。破壞這條線
會產生循環依賴，瀏覽器的 ESM 會直接爆掉。

架構全貌見 `ARCHITECTURE.md`；設計規格見 `ESPORT-DESIGN-V4.md`。

## 二、A／B 批血緣規則

原作者未回覆授權申請，所以**以「未獲正式授權」處理**。承襲自原棒球專案的程式碼要
淨室重寫，不能直接改。

以下是 git 歷史查出來的事實血緣，不是著作權判斷：

- repo 歷史的 `3c23597 Initial commit` ～ `3379e0b` 共 20 個 commit **就是原始棒球
  遊戲本體**（`yakyolife.html`）
- 整個 `src/` 是 `a71ee13`「v3.0.0 — 單檔 HTML 重寫為分層 ES 模組」從那份單檔拆出來的

### A 批 — 承襲（`a71ee13` 或更早加入）

`core/rng.js`、`data/events.js`、`data/traits.js`、`data/abilities.js`（今
`data/skills.js`）、`data/world.js`（今 `data/regions/*` ＋ `data/formats/*`）、
`engine/{career,game,market,progression,season,state,abilities}.js`、`main.js`、
`styles.css`、`ui/{actions,board}.js`

### B 批 — 原創（2026-08-11 之後）

`data/{mental,roleplay,attributes,epics}.js`、`kernel/*`、
`engine/{lineup,imports,calendar,retire}.js`、`phases/*`

### ⚠ 陷阱

`phases/*` 是 `6ec9575` 從 `engine/game.js` 拆出來的 refactor。**搬過去的那段仍帶
A 批血緣**——不能因為檔案是 2026-08-12 才建立就當成原創。判斷看的是那段程式碼的
來源，不是檔案的建立日期。

### 兩種處理方式

| 情況 | 做法 |
| --- | --- |
| A 批檔案，V4 本來就要整段重寫（`data/events.js`、`data/traits.js`、`engine/{game,progression,season,state,abilities}.js`、`ui/actions.js`） | 照 V4 規格重寫即可，重建本身就把承襲的表達換掉了 |
| A 批檔案，V4 沒有理由改（`core/rng.js`、`engine/market.js`、`engine/career.js`、`data/regions/*`、`data/formats/*`、`main.js`、`ui/board.js`、`styles.css`） | 排入 S03/S04/S05 **淨室重寫**：只看介面與測試，不看原實作，重寫後跑測試確認行為等價 |

**好消息**：README 點名承襲的三樣（引擎骨架、事件卡、隱藏特質）正好就是 V4 本來就要
整段重寫的東西。V4 完成後殘留的承襲面只剩約 900 行。

### 淨室重寫的具體做法

1. 先讀該檔的**匯出介面**與**呼叫端**，寫下「這個模組對外承諾什麼」
2. 讀對應的測試（`tests/` 全屬 B 批原創，可以放心看）
3. **關掉原檔**，依規格重新實作
4. 跑測試確認行為等價
5. 資料表類（`regions`／`formats`）的史實內容是公開事實（賽區賽段數、MSI 年表、
   Worlds 格式），內容照抄沒問題，要換的是**資料結構的排法**

## 三、絕對不碰清單

- **其他站的檔案。** 每份說明書的「不要做」那節寫得很明確，照著劃線。順手改隔壁是
  額度殺手
- **沒讀過 `ESPORT-DESIGN-V4.md` 對應章節就不動數值。** 每份說明書都會指名該讀哪幾節
- **不改 `tests/run.mjs` 的掃描邏輯**（新增 suite 不需要改它）
- **不破壞依賴方向**（見第一節）
- **git 歷史的處置只在 S06 做**，而且要先問過人

## 四、難度分級規則

`推理難度` 標的是**判斷成本**，不是工作量。內容量大但照 schema 填的站可以是「低」。

| 難度 | 判準 | 建議模型 |
| --- | --- | --- |
| 低 | 照表施工、機械改名、依既有樣板填內容，錯了測試會直接抓到 | Haiku 4.5（`claude-haiku-4-5-20251001`） |
| 中 | 要讀懂既有耦合才動得了手，跨 3~8 個檔，但正確答案是唯一的 | Sonnet 5（`claude-sonnet-5`） |
| 高 | 要做設計取捨或調平衡數值，錯了測試不會當場報錯、要跑完 160 段生涯才看得出來 | Opus 5（`claude-opus-5`） |

判「高」的實際訊號：這一站會改到「跑完才知道對不對」的數值（成長曲線、權重表、
懲罰曲線、配方門檻），或它的產出會被後面五站以上依賴。

標註是建議值。要不要降級由人依當下額度決定——每份說明書的「理由」欄寫的就是降級
的風險，看得到才好取捨。

## 五、兩個貫穿全程的鐵則

### 鐵則一：測試網先於數值

V4 §20.1 廢決定論等於廢掉 `tests/regression/golden.json`——那是 `WORKLOG.md` 記載的
兩次大改平衡時**唯一的安全網**。

- S07 的不變式 suite 必須**在舊程式上先跑綠**（證明它抓得住既有平衡），才准進丙組
- `tests/regression/determinism.mjs` 與 `golden.json` 到 S09 才刪，不要提早

沒有這條，丙組改完數值之後沒有任何東西告訴你平衡跑掉了。

### 鐵則二：位置身分不准被平均掉

`WORKLOG.md` 2026-08-12 記載過這個陷阱：第一版讓每項技能都沾到五、六個屬性，折疊後
五路的屬性權重長得幾乎一樣（最扁的中路最高／最低只差 2.8 倍），位置身分被平均掉。
寫純之後輔助的靈巧權重掉到 0.028——**靈巧對輔助幾乎沒有意義，這正是位置該有的樣子**。

S10 換十二技能表時，`ROLE_ATTR_WEIGHTS` 的五路差異度不得低於現行水準，而且要做成
不變式檢查，不能只靠眼睛看。

## 六、寫程式的風格

跟現有 codebase 對齊，不要引進新風格。

- **註解與文案一律繁體中文**
- 註解寫「**為什麼這樣設計**」與「**舊版錯在哪**」，不寫「這個函式做什麼」那種廢話。
  現有 codebase 的檔頭註解就是範本，照那個密度寫
- 不加相依套件。零建置是這個專案的硬約束
- 資料與邏輯分離：`data/` 不寫 `if`，效果用資料表達（見 `kernel/modifiers.js` 的
  四種寫法：加法／`mul`／`floor`／`cap`／旗標）
- 狀態是純 JSON——沒有函式、沒有 DOM 參照、沒有 class 實例。這是存檔與 headless
  測試能成立的前提

## 七、每一站的收尾動作

順序固定，不要跳：

1. **跑測試**：`npm test`，確認符合該站「完成定義」寫的預期
2. **回填交接筆記**：在該站說明書尾端寫實際做了什麼、遇到什麼、留給下一站什麼。
   下一站的人只會讀這裡，不會讀你的 session
3. **更新狀態表**：`docs/v4/README.md` 把該站改成「完成」
4. **更新 `WORKLOG.md`**：在最上方加一筆（格式見 `~/.claude/worklog.md`）——記的是
   意圖與脈絡，不是逐檔 diff
5. **commit**：一站一個 commit，用現有慣例（`feat:` / `refactor:` / `docs:` / `chore:`）

改到存檔結構時記得把 `src/engine/state.js` 的 `SAVE_VERSION` 加一，舊存檔會自動作廢。

### 做不完的時候

不要硬塞。把做到哪裡寫進「交接筆記」，狀態表改成「進行中」，commit 現況，然後停。
下一個 session 讀得懂就接得上——這比硬撐到額度耗盡好。
