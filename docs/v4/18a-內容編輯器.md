## 為什麼做這件事

S18（事件卡 26 → 80~150 ＋ 25 張任務卡）與 S19b（傳說 6 → 20）是整條線最大的兩塊
內容工。手寫這些條目要同時記住：欄位名、觸發條件語法、互斥成對、選項 2~4、效果只能
用 modifiers 的四種寫法（或 S15b 的窗口）、素材分池不重疊、天生特質必須指派池……
**記錯一項，測試才會告訴你。**

v4.3.1 把事件卡與特質卡合併成單一編輯器，理由寫在 §14.8：**素材競態、死配方、觸發
條件斷裂都是「兩套 schema 各自為政」的後果**。所以這一站不再做「事件卡編輯器」和
「特質編輯器」兩個工具，而是一個能同時看到事件卡與特質卡、並做雙向連結檢查的工具。

**這個工具只面向專案開發者，不是遊戲的一部分。**

## 範圍

### 必讀規格

V4 §14.7（特質編輯器七功能＋圖譜）、§14.8（編輯指南與整合原則）、§12.2（事件卡
結構：訓練／一般／特殊三類）、§12.3（任務卡 schema）、§14.4（掛載點全景表，自由
掛載）、§5.4（訓練事件卡結構）。

### 要做

**1. `tools/` 單一編輯器**

```
tools/
├── index.html        入口：事件卡 ／ 特質卡 ／ 任務卡 ／ 配方 ／ 天生特質 五個分頁
├── editor.js         表單渲染與驗證（由 schema 驅動）
├── schema.js         ★ 欄位描述：各類資料的權威 schema 描述
└── editor.css        樣式（沿用 src/styles.css 色階，獨立一份）
```

- **不改 `index.html`**，不從遊戲任何地方連過去。頁面明寫「開發者工具，非遊戲內容」。
- `npm run serve` 之後開 <http://localhost:8080/tools/>。

**2. `schema.js` 是核心——覆蓋七類資料**

| schema | 定案於 | 主要約束 |
| --- | --- | --- |
| 訓練事件卡（§5.4） | S16 | 檔位（great_success/success/failure/great_failure）＋池別（success_pool/failure_pool）＋適用活動＋體力條件；大成功/大失敗才可動心理 |
| 一般事件卡（§12.2） | S17 | 四池（persona/performance/psych/career）＋子標籤＋時段標籤；選項 2~4；互斥成對 |
| 特殊事件卡（§12） | S17 | 含生涯任務卡／傳說配方，四池分類 |
| 生涯任務卡（§12.3） | S17b | `類型` legend/route；觸發條件與達成目標是**條件式**——驗語法與謂詞名，**不驗形狀**；未達成結果只能是生涯標籤 |
| 特質卡（§13／§14.1） | S19a | 雙面性（益處＋副作用都有）；效果鍵真的被引擎消費；池歸屬（四池，未指定預設 persona）；種類 common/rare/epic/legend/unique |
| 合成配方（§14.6） | S19a | 稀有＝2 persona 素材；史詩＝2~3 performance 素材；傳說不進配方；素材分池不重疊 |
| 天生特質（§14.1） | S19d | 只收人格／體質類；`mentalBias`；必須指派素材池；池上限 5 |

欄位描述宣告式（`type`／`enum`／`list`／`min`／`max`／`required`／`unique`），`editor.js`
依它渲染。schema 變了只改這一個檔。

**3. 特質編輯器的七項功能＋圖譜（§14.7）**

特質分頁要能：宣告下層素材／上層產物／觸發條件（**可讀隱藏心理六維**，§12.3 舊約束
已廢）／池歸屬／種類歸屬／益處與副作用文本／特質影響（時段/月份/年份條件）。
**圖譜視圖**：力導向佈局展示「下層素材 → 上層產物」的合成樹全貌。

**4. 關係屬性檢查（§14.8 的核心價值）**

合併成單一系統後，要能當場紅這些跨資料的關係：

| 檢查 | 對象 |
| --- | --- |
| 素材競態：一個素材被多條配方共用、且共用會造成搶素材（§14.6 池內共用、跨池不共用） | 配方 ↔ 特質 |
| 死配方：配方的素材沒有可達獲取路徑（§14.2 取得率 < 15% 為死） | 配方 ↔ 事件卡／天生特質 |
| 觸發斷裂：事件卡產出的特質線索鍵不存在；特質的觸發條件引用不存在的謂詞 | 事件卡 ↔ 特質 |
| 效果鍵被引擎消費：掃 `src/` 有沒有人讀這個效果鍵 | 特質 |
| 池指派完整：特質（含天生）都有池歸屬；psych/career 不入合成 | 特質／配方 |

最後一項「效果鍵被引擎消費」特別有價值——打錯效果鍵不會報錯，特質就靜靜地沒有效果。

**5. 直接讀現有資料，可瀏覽可改**

零建置 ESM，直接 import 遊戲資料模組填下拉選單、載入既有條目。屬性鍵、心理維度、
特質鍵、謂詞名一律從資料模組／求值器取，不手打。

**6. 即時驗證 ＋ 輸出**

單筆級驗證（id 唯一、選項 2~4、互斥成對、效果四種寫法＋窗口）在表單旁就紅。
輸出只有剪貼簿與下載 `.js` 片段，排版與既有檔案一致（貼回去不產生無關 diff）。

**7. `tools/README.md`**

開法、每欄意思、產出怎麼貼回去、schema 改了動哪裡。S18／S19b／S19c 的執行者先讀它。

### 不要做

- **不要動 `src/` 任何檔案**（唯讀消費者）
- **不要動 `index.html`**
- **不要讓工具寫檔**（無 File System Access API、無後端）

### schema.js 涵蓋到哪

- 七類資料（規格表列六類＋訓練卡）：SCHEMAS 的 `event`／`trainingCard`／`quest`／
  `trait`／`fusion`／`innate`。規格說「七類」把訓練與一般事件卡拆兩格，實作上一般
  事件卡內含 options（含 `on.good/bad`），訓練卡另有 `effects{mental,buff,injury}`。
- 單筆級驗證：`validateEntry`（id 唯一、選項 2~4、excl 必填、效果四寫法＋窗口 op
  方向、cond 語法＋謂詞名、maintain 函式放行）。跨資料六檢查：素材競態（只報跨池
  共用為 error，池內共用為 warn）、死配方、觸發斷裂、效果鍵被引擎消費、池指派、
  天生池 ≤5。
- 效果鍵清單 `EFFECT_KEYS` 43 個＋窗口六鍵：**grep 過消費端**——modifiers.js 四查詢、
  §7.2 窗口（`peak_age_shift` 加法、其餘乘法）、psych 六鍵、market.js 動態 capKey
  （`contractCap`／`contractCapShort`）。新效果鍵要同步這裡＋消費端，否則工具報「不
  被引擎消費」。
- 來源表 `sourceOf`：事件卡 FLAG_TRAIT（10 鍵）＋扮演卡 PERSONA_RULES（6 鍵）＋生涯
  條件（veteran/single/disc）＋天生池＋其他配方產出。生涯條件的 28 歲／4 年門檻是
  寫死在條件式裡，工具只認鍵名，不驗門檻值。

### 規則驗不到（下一站注意）

- **死配方是真實現況**：關係檢查報 7 條（franchise/genius/clutch/meta/intlghost/
  underdog 素材無來源）＋10 條池內競態（warn）。這不是工具 bug，是 S18／S19b／S19c
  要補的內容缺口——**別把「關係檢查有紅」當成沒做完的站**。
- **取得率 ≥15% 是 S19c 的 160 段生涯實測**，工具只查「有無來源」。
- 條件式「不驗形狀」：`['and', ...]` 結構的自由組合引擎吃得下才有效，工具只擋
  語法錯與不存在的謂詞。
- `maintain`（維持條件）舊資料是函式：載入檢視放行、產出函式原樣保留；新寫的
  請用條件式陣列。

### 踩過的坑（改動時小心）

1. **TABS 解構**：`TABS.find(...)[2]` 才是 schema id 清單，`[1]` 是分頁 label。
2. **cond 欄位寫回時序**：input 事件要「先 renderErrors 寫回 value 再 onChange 跑
   live-errs」，順序反了驗證會晚一拍。
3. **輸出 pre 要隨 onChange 更新**：只重算 live-errs 不更新 pre，複製片段會複製到
   舊內容。
4. **關係檢查與合成圖譜共用 `.graph-overlay`**：開啟前先移除既有 overlay，否則兩
   個疊著。
5. **複製條目**：`excl` 若為 `solo_*` 要改為 `solo_<newKey>`，否則複製卡共用原卡的
   互斥群組。
6. `FLAG_KEYS`／`ALL_TRAIT_KEYS` 必須在 SCHEMAS 之前宣告（const 初始化順序）。

### 給 S18／S19b／S19c 的話

工具不是內容萬能藥：選項文本、數值平衡、池子配比還是人肉判斷。工具保證的是
「貼回去不會壞」——欄位名、效果寫法、關係斷裂都有擋。總數斷言（特質 54、事件卡
數等）是各內容站自己的驗收數字，新增內容後要更新它們。
