# S50 · 校準重驗（天組收斂）

狀態：✅ 完成（2026-08-19，v4.10.1）
前置：S46 S47 S48 S49
預估：1 session
推理難度：高
建議模型：Opus 5（`claude-opus-5`）
理由：與 S30（庚組收斂）、S36（辛組收斂）同型的站——要判讀四站疊加後的偏移、
決定動哪一個旋鈕、以及**不動哪一個**。旋鈕之間有反向作用，判錯方向會把問題推得更深。

---

## 為什麼做這件事

天組前四站各自動了旋鈕，而且**方向不一致**：

| 旋鈕 | 來源 | 對總成長的方向 |
| --- | --- | --- |
| 權重從分散變集中（.7/.3） | S46 | **↓** `investAttr` 的成本階梯（`attributes.js:212`）對集中投注是遞增的 |
| 休息開始給成長 | S46 | ↑ |
| 活動從 8 → 6 | S46 | 中性（總 yield 不變，選擇面變窄） |
| 體能折扣訓練成本 | S47 | ↑ 可訓練的月份變多 |
| 培育型教練 | S49 | ↑ 但只有 1/3 生涯抽得到，拉大的是**變異**不是平均 |

淨值只能實測，不能推算。而且**分站各自校準會互相蓋掉**——S46 調完 `TRAIN_YIELD`，
S47 一上線又把它推翻。所以四站一律「不做校準、把漂移數字記進交接筆記」，
到本站一次收斂。

（S48 不動成長，但它會改變事件卡的出現分布，間接影響屬性增減的期望值——
一併在本站量，不要假設它是零。）

## 範圍

### 要做

**三條紅線，逐條判讀後才決定動哪個旋鈕。**

**1. §7.1 的 `平均巔峰 ÷ 屬性上限 ≈ 0.755`**
（`tests/regression/invariants.mjs` 的潛力衰減不變式）

偏離就調 `TRAIN_YIELD`（目前 6.5）。§21.2 明說它是**最後才收斂的旋鈕**——
先把衰減係數與起始值固定下來，再調基礎成長值讓比值回到 0.755。
不要改 `GROWTH_BASE`、不要改潛力區間、不要改 `stepCost` 的形狀。

**2. §6.1 的休息節奏**（`invariants.mjs:860-875`）

要求：平均休息間隔落在 3–4 個養成回合、且休息佔比 < 50%。
休息在 S46 之後變好看了，佔比會升。若破線：

- **優先**調 `restYieldMul` 的高體力端（把 100→0.10 那一端再壓低）。
- **其次**微調 S46 表格裡的五個體力消耗（30/30/22/26/20，平均 25.6，
  略低於舊的 5 個 train 活動平均 27；疊上體能折扣與教練折扣後實效更低）。
- **最後**才考慮 `MONTHLY_RECOVER`。
- ⚠ **不要動 `REST_RECOVER`**——§6.1 明說調休息回復量會讓休息變萬靈丹，
  那正是 §6.2 整條懲罰曲線要防的事。

**3. 體能雪球（本站新增的觀測項）**

`vit` 在 S47 之後有三個消費者（恢復 ↑、成本 ↓、受傷 ↓），而它又是**健身房的主屬性、
休息的副屬性**——存在「練體能 → 訓練變便宜 → 能練更多月 → 什麼都長更快」的迴路。

量法：比較「高 `vit` 潛力」與「低 `vit` 潛力」兩組的**巔峰 OVR**。
判準：**體能該讓生涯更順，不該讓生涯更強**。高 vit 組的巔峰 OVR 拉開 >3 點就是警訊。

處置：把 `vitCostCoef` 的斜率 0.005 → 0.003（成本折扣是迴路的入口）。
**不要動受傷係數**——那是玩家最有感的一項，動它會讓 S47 的手感白做。

這條觀測要**補進 `invariants.mjs`** 成為常設不變式，不是量完就算。

天然剎車有三道，判讀時要記得它們已經在運作：係數小且有 clamp；`vit` 受 `investAttr`
的潛力天花板限制；**`vit` 的 OVR 權重是 0**——堆體能的人在十二技能上付出真實的機會
成本，這是主要對沖。

**4. 快照回寫**

`node tools/demo-sim.mjs` 對照 `snapshots/`。**兩個獨立的漂移來源**：
訓練改動（S46–S47），以及教練從 5 筆變 6 筆造成的 `rng.pick` 索引位移（S49）。
確認漂移方向合理（不是崩掉）之後用 `npm run sim:demo:update` 回寫。

### 不要做

- **不做新功能**。本站只調數值、補觀測不變式、回寫快照。
- **不放寬既有不變式的容差**來換綠燈。容差被撐破時先找是哪一站的旋鈕過頭
  ——特別是「某一型教練過強」與「體能折扣過大」兩個候選。
- **不動 §7.1 的曲線形狀**（`TIER_POWER`／`CEILING_FLOOR`／`CEILING_TAPER`）。
- **不改測試的斷言方向**，只改被校準的常數。

## 規則與不變式

- **一次只動一個旋鈕，量完再動下一個。** 五個旋鈕方向不一致，同時動兩個就分不出
  是誰造成的。
- **`TRAIN_YIELD` 最後動**（§21.2）。
- **不動 `REST_RECOVER`**（§6.1）。
- **不動受傷係數**（S47 的手感）。
- 校準理由要寫進對應檔案的檔頭註解——`stamina.js` 的既有註解就是這樣記錄
  「+12 → +17 → +10」三次調整的，照同一個格式續寫：**寫清楚是「分布搬了家」
  還是「手感要調」**，這兩者的後續處理完全不同。

### 體能雪球：說明書給的量法量不到，換成控制變因微基準

說明書的判準是「拿天生 `vit` 潛力分兩組比巔峰 OVR，高組拉開 >3 點就是警訊」。
照做的實測是 **−2.44 點**（高組反而**低**），而且把 `vitCostCoef` 的斜率調壞 **10 倍**
（vit 100 幾乎免費訓練）也只走到 **+0.14**。原因是潛力採「1 頂尖／1 優質／1 中上／
3 平庸」分派：`vit` 拿到高潛力就代表別的屬性拿不到，而 `vit` 的 OVR 權重是 0——
那個機會成本是一個固定的 −2.5 點偏移，把迴圈訊號整個蓋掉。

⚠ 一條**在機制整個壞掉時還亮綠燈的檢查等於沒有檢查**（`topEndPayoff` 拿掉那條的同一
個教訓，該處註解寫明「後面的站不要再把它加回來」）。所以生涯分組**只留 log 量測**，
門檻改用控制變因微基準：同種子同位置、同一套保守策略、`vit` 每月釘死在 100 與 20
兩端跑 36 個養成回合，比 OVR 成長。

- 實測（40 組）：高體質多練 **6.5 個月**（32.6 vs 26.1），OVR 多長 **3.18 點**。
- 先調壞驗過會紅：`vitCostCoef` 斜率 0.005 → 0.01 走到 **6.03**、`vitCoef`（恢復）
  同樣加倍走到 **5.28**，門檻 4.5 兩種都抓得到（實測值有三成餘裕）。
- 破線時第一個要動的仍是 `vitCostCoef` 斜率（0.005 → 0.003，成本折扣是迴路入口），
  **不是受傷係數**（S47 的手感）。

S46／S47 兩份交接筆記都點名「照 S16 的判準重量一次是 S50 的事」。**已重量，結論是
不動**，理由是它不是天組造成的漂移，而動它是改平衡不是換讀數來源：

### OCR 審查補記（3 條，medium 1／low 2）

`rule`）跑不起來（S46–S49 四站同樣狀況）。審查照委託模式的本意由 host agent 逐檔做完，
意見寫成 JSON 走 Phase 2b 閘門：**critical 0／high 0／medium 1／low 2，exit 0**。

1. **medium**（`tests/regression/invariants.mjs`）：偏離說明書字面——說明書把「生涯分組
