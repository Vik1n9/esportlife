# S21b · DEMO 三年期程

狀態：完成（2026-08-16）
前置：S21
預估：1 session
推理難度：中
建議模型：Opus 5（`claude-opus-5`）
理由：改的是**生涯主迴圈的收束條件**——退役訊號、最後一搏續跑、期滿收束三條路徑
共用同一個迴圈，接錯就會出現「期滿卻走退役文案」或「最後一搏跑不完」。同時要判斷
哪些東西該掛 state（期程，讀檔要還原）、哪些不准掛（測試旗標，會漏進玩家存檔），
以及量到的分布問題哪些該當場改、哪些該留給校準站（本站兩者都遇到）。

---

## 為什麼做這件事

S21 把 DEMO 組裝完成，但 §19 的範圍是**職業第一年**——使用者實玩後的回饋是
「時間太短，測不到多樣系統」。

一年的 DEMO 結構上就測不到**跨年機制**，實測逐項對照：

| 系統 | 一年 DEMO 看得到的 | 為什麼要跨年 |
| --- | --- | --- |
| 合約 | 出道 2 年約走掉第一年 | 到期→續約／FA／轉隊要第二年底 |
| 生涯任務（§12.3） | 開卡 | deadline 多為 2 年，收束在第三年開季 |
| 生命週期衰退（§7.2） | 單點快照 | 斜率要兩個以上的年界才量得出來 |
| 三層退役（§18.2） | 只有第一年就崩的極端段 | 市場淘汰多發生在首約到期後 |
| 轉會窗口 | 傳聞 | 買斷／切割／解散要合約狀態變化 |

所以 DEMO 期程改為 **36 個月＝三個賽季（2015–2017）**：跨得過上面每一條，
又短到一次坐得完（實測期滿段 ≈ 一小時內的決策量）。

期滿之後不能無聲停住——36 個月跑完沒觸發任何結局時，顯示「DEMO 結束」，
其餘**比照退役**跑結算（任務收束 → 第三層結局結算 → §15.5 傳記與結算畫面）。

## 範圍

### 要做

**必讀規格**：V4 §19（全節，本站改寫）、§18.2（三層退役——期滿要接在它旁邊，
不是取代它）、§12.3（任務收束時點）、§15.5（傳記）。

**1. 期程常數與判斷函式**

`DEMO_YEARS = 3`／`DEMO_END_YEAR`（`data/eras.js`），月數由年曆導出
（`engine/demo.js` 的 `DEMO_MONTHS = DEMO_YEARS × MONTHS_PER_YEAR`），
不手抄第二個 12。

**2. 期程掛 state，不掛 `g.opts`**

`demoEndYear`（業餘起點為 `null` ＝ 不設上限）與 `demoEnded`。

⚠ 這與 `forceIntl` 的掛法**相反**且兩者都對：測試旗標不進 state（會漏進玩家
存檔），期程不進 opts（讀檔回來會忘記自己是 DEMO，變成永遠跑不完的生涯）。

**3. 主迴圈的三條收束路徑**

退役訊號、最後一搏續跑、期滿收束共用一個迴圈。期滿檢查排在退役判定之前，
但**條件含 `!state.done`**——同一刻若已有退役訊號，那是真的結局，走 §18.2。

**4. 期滿停在第三季，不跨年**

第 36 個月月底就收，不做 `year += 1`。退役是「在哪一年退就結算在哪一年」，
期滿照同一個規矩——否則結算畫面會出現玩家一場都沒打過的 2018 年。

**5. 措辭：期滿不是退役**

結算畫面標籤（`退役` → `DEMO 終點`）、分享圖副標、§15.5 傳記結局段
（新增 `ending.demoEnd` 模板，現役措辭）。

**6. 期程可見**

狀態列年份格改成「DEMO 14/36」。三年是有限期程，剩幾個月會直接影響玩家要不要
為第三年鋪路（合約、任務期限），看不到就不成決策（§22.4 的同一條理由）。

**7. 測試**

`tests/regression/demo.mjs` 補「三年期程」區塊：上限成立、兩種收束互斥且各自
恰好結算一次、期滿措辭不是退役、業餘路線沒被截斷。

### 不要做

- **不要改業餘路線的任何行為**——13 站校準基線量在那條路線上。
- **不要在這一站調平衡**（本站量到的自由市場淘汰率見交接筆記，留給校準站）。
- 不要為期滿另開一套結算——「比照退役」就是重用 `finale()`，不是複製一份。

## 交接筆記

（S21b 完成，2026-08-16）

### 方向

DEMO 期程由一年改為 36 個月（2015–2017），期滿未觸發任何結局即以「DEMO 結束」
比照退役結算。引擎邏輯除主迴圈收束條件外零改動，**沒有調任何平衡數字**。

### 實作細節

1. **期程的單一來源是 `src/engine/demo.js`**：`DEMO_MONTHS`／`isDemo`／
   `demoStartYear`／`demoMonth`／`demoExpiring` 五個純函式，引擎、狀態列、
   結算畫面、測試共用。`DEMO_YEARS = 3` 是資料（`eras.js`），月數由
   `MONTHS_PER_YEAR` 導出——不手抄第二個 12（單一來源規則）。
2. **期程掛 state**：`demoEndYear`（業餘起點 `null`）＋ `demoEnded`。
   SAVE_VERSION **22 → 23**：舊存檔缺 `demoEndYear` 會被當成完整生涯永遠跑下去，
   收束畫面永遠等不到，故作廢。
   ⚠ 與 `forceIntl`（掛 `g.opts`）**方向相反**且兩者都對，理由寫在 `demo.js` 檔頭。
3. **主迴圈重整**（`game.js`）：原本「跑年 → catch → 退役 → 最後一搏再跑年」是
   兩段幾乎相同的程式碼各寫一次；改成 `for(;;) { runYears → 期滿? → retirement }`，
   跑年的那段只剩一份（`runYears`）。期滿檢查是 `!state.done && state.demoEnded`
   ——**結局優先於期滿**（§19.2 收束優先序）。
4. **期滿不跨年**：`runYear` 的年界推進前檢查 `demoExpiring`，命中就設
   `demoEnded` 並 return。結算停在 2017 年 · 21 歲 · 3 季，而不是玩家一場都
   沒打過的 2018。
5. **措辭三處**：結算檔案卡標題「生涯檔案（DEMO 3 季）」＋ 欄位「DEMO 終點」、
   分享圖副標、傳記 `ending.demoEnd`（「截至 2017 年……仍是現役選手」）。
   期滿不設 `retireReason`——它是退役專用的欄位，期滿寫進去就等於把 DEMO
   說成退役。
6. **狀態列年份格**：DEMO 路線顯示「DEMO 14/36」，完整生涯顯示「年份」。

### 未一起處理（⚠ 下一站請評估）

- **首約到期的市場斷崖（本站最大發現，屬校準）**：73/100 的段在**第 24 個月**
  收場，其中 67 段是「FA 市場乏人問津」。根因量測：2016 年 12 月（出道 2 年約
  到期月）玩家 `effectiveCoachRating` 平均 **61.9**，而 `positionDemandThreshold`
  平均 **62.6**——48 段裡 30 段低於門檻，於是續約選項與市場報價同時為空，
  §18.1「無報價只剩退役」直接生效。一年 DEMO 期間這條線在畫面外，三年期程把它
  暴露出來。**這是平衡校準，不在本站範圍**（S21 定的規則：發現數值不對回報給
  對應的站，不就地改）。要讓 DEMO 的三年真的被玩到，下一站要在
  「新秀第二年成長曲線」與「`positionDemandThreshold` 對 21 歲選手的取值」
  之間選一邊調。
- **最後一搏會重跑同一年（既有行為，非本站引入）**：`retire()` 從 12 月的
  TRANSFER 階段拋出時年界還沒推進，選「最後一搏」續跑會把該年整年重跑一次
  （賽段、季後賽、世界賽都會再打一遍）。DEMO 的上限讀年份，所以期程仍然收得住
  （重跑的那年結束時 `demoExpiring` 一樣命中），但這是 S20e 留下的缺口——
