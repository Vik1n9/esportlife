## 範圍

### 要做

**1. 基礎欄位解析（規則制）**

- 解析 Infobox 與 Tournament Results 表格：出生年（不抓真實姓名，依 §23.1）、
  位置、所屬戰隊歷史、賽事名次。
- 依 S23 定案的 NPC schema 欄位對齊（schema 是權威，欄位對不上就回報）。

**2. 實體解析與標準化**

- 戰隊別名統一映射到 `team_history.json` 的 `team_id`（如 TPA／台北暗殺星／
  Taipei Assassins → 同一縮寫）。
- 模糊描述打包成批次（每次 10 筆）呼叫 LLM 輸出 `team_id` JSON 陣列；
  **映射結果寫入本地字典檔，後續查表不再呼叫 LLM**。
- 字典檔進 repo（S27 也用它）。

**3. 產出 `cleaned_players.json`**

- 每名選手一筆：標準化基礎資料、生涯履歷、Wiki 有提供的粗略賽事統計。
- 去重：同名 ID 跨年度合併成單筆生涯。

### 不要做

- **不做遊戲參數計算**（潛力、屬性、特質）——那是 S27
- 不抓真實姓名（§23.1）
- 清洗規則與 S23 schema 衝突時：**照 schema 改腳本**，不回頭改 schema
- 不碰 `src/` 與 `tests/`

- 純工具站：`npm test` 前後完全不變
