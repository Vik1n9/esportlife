## 為什麼做這件事

外部提出的《V4.1 規格企劃書修訂清單》要增訂六件事：

1. §0.5 設計原則（四項檢驗）
2. §15.5 生涯傳記生成
3. §1.4／§9.1 種子決定天生特質
4. §12.2 傳說事件卡
5. §14.2 移除傳說的合成硬門檻，改由傳說事件卡決定
6. 五條「替代性生涯路線」，讓平庸局有明確的 Build 終點

這一站做的是**可行性研究**，不是照抄：先確認每一條在現行引擎與既有校準底下站不站得住，
站不住的提出替代寫法，然後把結論寫回規格書與工作說明書。

**這一站只改文件，不碰程式。** 落地是 S17a／S17b／S19d／S21a 四站的事。

## 可行性研究：四個發現與處置

### 一、傳說配方不能整段丟，要轉成觸發條件

增訂書要「傳說完全由傳說事件卡決定」。若照字面整段刪除 §14.2 的傳說配方表：

- 稀有與史詩會變成**沒有出口的終點**，§13.3 第三層約束（合成消耗＋跨配方共用元件）
  在頂端失效
- 「生涯至少一次國際賽四強」那份 **30.0% 的實測聯合命中率**作廢，持有率要從零重量
- S19c 的配額推導（每個史詩恰好進兩條、稀有依取得率分配次數）跟著作廢

**處置**：傳說事件卡成為唯一取得口（照增訂書的意圖），但**觸發條件的語法包含「持有
指定史詩＋稀有」**。20 組素材組合**原地轉成 20 張 `legend` 任務卡的觸發條件**，
底線生涯門檻升格為所有 `legend` 卡的共同觸發條件（寫在引擎層，不逐卡複製）。

代價是持有率的推導多了一層：原本「持有素材即得」，現在是「開卡率 × 達成率」。
30.0% 因此從持有率變成**持有率的上界**，S19c 要重量。

### 二、平庸局的 Build 終點不是傳說特質

增訂書要五條替代路線都通往傳說，同時要「允許單局複數傳說」。但 S07 不變式寫死
**「持有傳說特質的生涯不得超過一半」且註明不准放寬**，§14.2 的目標值是 28–35%。
替代路線的觸發條件刻意設計成平庸局也達得到——兩件事加起來會直接頂破 ≤50%。

**處置**：`route` 類任務卡的達成結果是**史詩特質 ＋ 生涯標籤**，不是傳說。
傳說維持榮譽路線專屬，28–35% 與 ≤50% 兩個數字都不動。

增訂書自己的「未達成結果 → 轉為史詩特質或生涯標籤」寫法已經蘊含這個階梯，
這裡只是把它從退化路徑變成 `route` 的常態結果。心流檢驗仍然過得了：平庸局拿到的是
**有名字的結局**（賽區統治者、不滅隊魂），而不是一張更強的牌。

同時新增兩條驗收線：單局傳說 ≥3 的生涯 ≤5%（管疊加，因為 §12.3 允許複數傳說）、
後段局的 `route` 覆蓋率 ≥60%（管心流檢驗有沒有真的兌現）。

### 三、兩條替代路線的條件目前算不出來

| 增訂書原文 | 為什麼算不出來 |
| --- | --- |
| 究極綠葉：助攻／保護數據**前 10%** | 引擎只有對手隊伍的**聚合強度**（`kernel/strength.js`），全聯盟沒有逐選手的個人數據列，百分位沒有母體 |
| 網紅選手：生涯評分低於**中位數** | 中位數要跨局的評分母體，單局算不出來 |

補這個母體等於在比賽模擬層新加一個子系統（每場為所有對手生成個人數據列），
成本與風險都遠高於這兩條路線本身的價值。

**處置（已與需求方確認）**：暫時改寫成引擎已有的量的**絕對門檻**——生涯場均助攻 ≥
固定值且個人獎項 = 0；`fame` 達最高分級且 `careerScore < 900`（沿用 §10 分級的既有
中段線，不新增常數）。**未來製作「歷史上所有選手卡片」的資料庫之後，就有真實母體了，
這兩條要回來改回百分位定義**——已登記在 §21.3。

### 四、三件增訂書沒寫、但做下去會撞到的事

1. **狀態欄位不夠**。五條路線要的量有一半不在 `state` 裡：國際賽勝負紀錄（只有
   `intlAppearances` 與名次）、歷任戰隊清單（只有 `team`／`teamYears`）、降級危機
   累計（`disbandThreat` 是每季重置的布林旗標）、個人獎項計數（只有 `honors` 字串
   陣列）。§15.5 生涯傳記要的是同一批資料。→ 獨立成 **S17a**，兩者的共同前置。
2. **跨回合期限需要新狀態機**。§12.1 的觸發模型是單月結算完就結束，任務卡的
   「達成目標／期限／未達成結果」需要一份跨回合存活的清單。→ 獨立成 **S17b**。
3. **天生特質會位移既有種子的天賦**。`createState` 的 `birth` 亂數流是有序的，插入
   天生特質的抽取會讓後面的心理 jitter／`fame`／英雄池全部改變。V4 本來就會 bump
   `SAVE_VERSION`，可以接受——但抽取順序要在規格書裡寫死，之後不准再插隊。已寫進 §1.4。

順帶解掉一個既有問題：§14.2 死配方規則點名的 `鐵人`（取得率 0%，**完全沒有來源**）
是體質類，收進天生特質池就活了，S18 不必再為它補卡。其餘四個死素材是競技／媒體類，
不進天生池，仍是 S18 的硬需求。

## 交接筆記

做完了，程式一行沒動（`git diff --stat -- src tests` 為空），`npm test` 與改動前逐項相同。

**下一站不是 S14。** 依賴圖沒變，S14（月回合制）仍然是丁組的下一站，新增的四站全部
在戊組往後排。真正要注意的是**開工順序改了**：

- `S18a` 的前置從 `S17 S19a` 變成 `S17b S19a S19d`——編輯器現在要覆蓋三套 schema，
  提前開工會做出一個少一套的工具
- `S19c` 的前置多了 `S18`——要有 25 張真卡才校準得了任務卡的數值，S17b 放的是假卡
- `S21` 的前置多了 `S21a`

**三個數字不准動**：傳說持有率目標 28–35%、硬上限 ≤50%、老手傳奇 ≤30%。這一站唯一
往上加的是 `route` 覆蓋率 ≥60%，而它吃的是史詩與標籤，不吃傳說的預算。

**S19c 會很重。** v4.1 之後它從「一個旋鈕」（配方門檻）變成「三個旋鈕」（配方門檻、
開卡率、達成率），而且素材取得率會先被 S19d 的天生特質整批推高。排 Opus 5 的理由
比 v4.0 時更強。
