狀態：未開始
前置：S38 S39 S40 S41
預估：1 session
推理難度：中
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：規格 §22.6 的三條不變式已把設計空間收死，工作量集中在 CSS。

## 為什麼做這件事

§22.6（v4.6.1 新增）。現行版面固定單欄置中，寬螢幕兩側大量留白，選手資料被關在
底部抽屜裡——即使螢幕有空間也看不到。

**壬組最後一站**：前四站把豎屏版面補完，本站才加寬螢幕層。順序不能顛倒——
寬螢幕是在既有骨架上加斷點，骨架沒定就無從加起。

## 範圍

### 要做

**1. 兩個斷點**（`DESIGN.md` Layout）

```
<720px   單欄（基準版面，選手資料為底部抽屜）
≥720px   兩欄：敘事流 ｜ 選手資料常駐 340px
≥1024px  三欄：年度目錄／賽程摘要 240px ｜ 敘事流 ｜ 選手資料 340px
```

狀態帶橫跨整寬。中欄維持與豎屏同一個行長上限。

**2. `#board` 移出 `#app`**

改成 body 的直接子元素，才能橫跨整寬。`src/ui/board.js` 全靠 id 取節點，
**JS 零改動**；只需在窄螢幕補回置中與寬度上限，寬螢幕解除。

**3. 年度目錄升級**

S41 建的年度下拉在寬螢幕升級成左欄常駐（年度目錄＋賽程摘要）。
**直接取用 S41 登記的結構**，不要重建一份。

**4. `#panel` 就地變右欄（不複製 DOM）**

寬螢幕時把抽屜的定位、遮罩、動畫與最大高度取消，成為常駐右欄；隱藏開關按鈕。

⚠ **兩個明確的坑**：

- **`src/styles.css` 檔頭鐵則衝突**：現行寫「`#panel` 預設隱藏、`.open` 才顯示」。
  媒體查詢覆寫後這條在寬螢幕不成立。**鐵則註解必須同步改寫成「窄螢幕抽屜／
  寬螢幕常駐」兩態**——鐵則是給後人看的載重清單，留著錯的比沒有更糟。
- **`src/ui/panel/index.js` 的可見性守衛**：現行 `refreshPanel()` 只在面板有
  `.open` 時重繪，`togglePanel()` 只在開啟時渲染。寬螢幕常駐時 `.open` 永遠是
  false，面板會**完全不更新**。改成一個統一的「目前可見嗎」判斷（含斷點查詢），
  並在斷點跨越事件上重繪一次。

**5. 開場畫面**

- 移除裝飾用的假導覽列（現行掛 `aria-hidden="true"`，寬螢幕更明顯是死重量）。
- 建角表單在寬螢幕改雙欄（左說明／右表單）。

**6. 順手對齊視覺語言**（S37 交接筆記列的既有偏差，非本站造成）

- `src/ui/summary.js` 的分享圖用的是舊配色與**未載入的字型**
  （`Cinzel`／`Rajdhani` 從未被載入，實際落到系統回退）。改讀現行色票與 `--ui`。
- `index.html` 的 favicon 仍是舊金色，一併對齊。

### 不要做

- **不重排決策動線**（§22.6 不變式 1）：決策槽在任何寬度都錨定在事件文本區正下方、
  屬性條正下方，不得移到側欄或改成浮動控制。同類養成遊戲皆為豎屏專用，
  **沒有可照抄的寬螢幕先例**——動線是豎屏調校出來的，沒有理由重推。
- **不讓文本行長隨螢幕拉寬**（不變式 2）。
- **不在寬螢幕顯示豎屏看不到的資訊**（不變式 3）——否則 §22.4 的資訊公開性
  會因裝置而異。
- **不加淺色主題**（不在壬組範圍）。
- **不動遊戲邏輯**：本站是純 UI 站，引擎一行不改。

## 規則與不變式

- §22.6 三條不變式（決策動線不變／文本行長不隨螢幕拉寬／寬螢幕不得出現豎屏
  看不到的資訊）。
- §22.4 資訊公開性在所有寬度一體適用：心理六維與教練評價任何寬度都不得顯示。
- 色票／字型／圓角尺度不動（`DESIGN.md`）。
- 維持純前端零建置 ESM——不引入任何建置工具或相依。
- `src/styles.css` 檔頭鐵則必須反映改動後的真實載重規則。
