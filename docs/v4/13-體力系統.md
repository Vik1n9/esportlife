## 為什麼做這件事

**體力在現行程式裡不存在。**

現在的 `sta`（體力）是一個**技能**——由 `vit` 屬性導出（`sta: {vit .85, agi .15}`），
餵給 `formFactor()` 當手感係數。它不會消耗、不會恢復，是一個穩定值。

V4 §6 要的是完全不同的東西：**0–100 的消耗資源**。訓練扣、比賽扣、休息回、
每月自然回，低了會顯著降低訓練成功率與受傷風險。這是賽馬娘式養成的核心壓力來源——
沒有它，月回合制（S14）與設施制訓練（S16）都少了取捨。

S10 與 S11 各留了一個 `TODO(S13)` 等這一站接上去。

## 範圍

### 要做

**必讀規格**：V4 §6（體力系統，含 §6.1 數值框架、§6.2 低體力懲罰曲線、§6.3 賽事期間）、
§5.4（訓練成功率）。

**1. 新增 `src/engine/stamina.js`**

V4 §6.1 的草案框架：

| 參數 | 值 |
| --- | --- |
| 上限 | 100 |
| 每月自然恢復 | +12 |
| 訓練消耗 | 約 −25~−30 |
| 休息恢復 | +50（含自然恢復共 +62） |
| 常規賽比賽消耗 | 約 −12/月 |
| 季後賽每場 BO | 約 −18 |
| MSI/世界賽每場 BO | 約 −22 |

**目標節奏：保守玩法約每 3–4 個月休息一次。** 這是 S07 不變式要守的。

§6.2 的懲罰曲線草案：

| 體力區間 | 效果 |
| --- | --- |
| ≥60 | 正常成功率 |
| 30–59 | 成功率 −15%~−25% |
| 1–29 | 成功率 −40%~−60%，受傷風險上升 |
| 0 | 仍可行動，失敗率極高，受傷／心態崩盤風險大增 |

⚠ **這些是草案，V4 §6.2 明說要 playtest。** 這一站的工作有一半是調它們——
跑 160 段，看實際的休息間隔落在哪，往 3–4 個月調。把調整過程與最終值寫進交接筆記，
並回寫進規格書 §6。

**2. `state.stamina` 進 state**

`src/engine/state.js` 新增欄位，`SAVE_VERSION` 加一。

**3. 接上兩個 `TODO(S13)`**

- `src/engine/season.js` 的 `formFactor` 改吃 `state.stamina`。現有註解說明得很清楚
  「體力進表現，不進場次——LoL 是五個固定先發，隊伍打幾場你就打幾場」，這個原則不變
- `src/kernel/strength.js` 的體力修正項

**4. 受傷機率掛上體力**

`src/engine/progression.js` 的 `injuryProbability` 現在吃年齡與特質。
§6.2 說低體力會提高受傷風險，加上去。

**5. §6.3 賽事期間的規則**

賽事期間不能選「休息」，改提供「減少訓練」。備賽戰術裡的「心態調整與休息」是賽事期
唯一的恢復手段。**這一站先把規則寫進 stamina.js 的介面**，實際的選項清單是 S15
（賽事事件序列）與 S16（訓練選單）的事。

**6. 讓 S07 的「體力節奏」SKIP 生效**

檢查保守玩法的平均休息間隔落在 3–4 個月。**這是本站的主要驗證。**

⚠ 但**月回合制還沒做**（S14）。所以這一站的體力消耗還沒有真正的「每月」節奏可掛。
處理方式：
- 把 stamina.js 寫成**與回合粒度無關**的介面（`consume(state, amount)`／
  `recover(state, amount)`／`monthlyDrift(state)`），S14 再接上月迴圈
- S07 的體力節奏檢查在 S14 之後才會真的有意義。這一站確認它**跑得動**（不再 SKIP），
  數字對不對留給 S14 驗

### 不要做

- **不要做月回合制**（S14）。stamina.js 保持與回合粒度無關
- **不要做設施制訓練選單**（S16）。這一站只提供消耗／恢復的介面
- **不要把 `sta` 技能改回來。** S10 已經把它從技能表拿掉了，那是對的
- **不要把體力藏起來。** 體力是玩家要管理的資源，必須顯示在面板上（跟隱藏心理相反）

## 規則與不變式

- S07 不變式全綠，「體力節奏」SKIP 轉為實際檢查（數字驗證留 S14）

  若超過一半，曲線太重

  若幾乎沒出現，代表恢復太快，壓力不存在
- 這兩條的實際比例抄進交接筆記，S16 調訓練成功率時要用
