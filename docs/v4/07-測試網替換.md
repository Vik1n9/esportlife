# S07 · 測試網替換

狀態：未開始
前置：S01
預估：1 session
推理難度：**高**
建議模型：Opus 5（`claude-opus-5`）
理由：這一站設計的不變式會被後面每一站當守門員用。設計錯了——太鬆抓不到平衡跑掉、
太緊在合理改動下誤報——整條丙丁戊組都在錯的訊號上做決定。降級的風險是產出一堆
「跑得過但抓不到東西」的檢查。

---

## 為什麼做這件事

**這是 `00-共通規則.md` 鐵則一的執行站。**

V4 §20.1 廢掉決定論，等於廢掉 `tests/regression/golden.json`——那是 `WORKLOG.md`
記載的兩次大改平衡時**唯一的安全網**（九素質→六屬性、四階特質合成，兩次都靠它抓
出通膨）。

`golden` 走了之後，剩下能守平衡的只有 `tests/regression/smoke.mjs` 那四項不變式。
四項不夠——它們守的是「傳奇稀有度」與「加點是不是決策」，但 V4 新增的體力節奏、
潛力衰減、心理修正、事件互斥全部沒有守門員。

**這一站要在動任何核心層數值之前，把網子先織好。**

## 範圍

### 要做

**1. 讀懂現有的測試網**

- `tests/lib/harness.mjs` — `playCareer` / `playMatrix` 怎麼在 Node 裡跑完整段生涯，
  `focus`（老手：餵權重高且沒到潛力天花板的屬性）vs `spread`（新手：輪流平均投）
  兩種打法怎麼定義
- `tests/regression/smoke.mjs` — 現有四項不變式與它們的設計理由（檔內註解寫得很清楚，
  說明了為什麼九素質時代的舊斷言在六屬性下「不可能成立，也不該成立」）
- `tests/regression/golden.mjs` — 快照機制，`UPDATE_GOLDEN=1` 重刷

**2. 設計新的不變式 suite**

新增 `tests/regression/invariants.mjs`（或分成數個檔，你判斷）。要涵蓋的面向：

| 面向 | 要守什麼 | 對應 V4 章節 |
| --- | --- | --- |
| 巔峰上界 | 技能值與教練評價的分布上界合理，沒有通膨 | §7.1 §10.2 |
| 打法差距 | 老手 vs 新手仍有可測量的差距（現行守的是巔峰 OVR 差 ≥1.5） | — |
| 傳奇稀有度 | 沿用現有兩項 | — |
| 等第涵蓋 | 五個等第都出現得到 | — |
| **體力節奏** | 保守玩法的平均休息間隔落在 3–4 個月 | §6.1 |
| **潛力衰減** | 屬性越接近潛力天花板，同樣訓練的成長越少（單調性） | §5.3 §7.1 |
| **位置身分** | `ROLE_ATTR_WEIGHTS` 五路差異度不低於現行水準 | §8.2 ＋ 鐵則二 |
| **事件互斥** | 同一回合的兩張卡不屬於同一互斥群組 | §12.1 |
| **合成消耗** | 被合成消耗掉的低階特質不會再被取得 | §14.1 |
| **心理是放大器不是決定器** | 心理極端值造成的發揮差距在有界範圍內 | §9.2 |

**⚠ 關鍵要求：後五項在舊程式上還沒有對應機制**（體力、潛力衰減、十二技能、事件互斥、
六維心理都還沒實作）。做法：

- **現在就寫**，但用「若機制不存在則跳過並印出 SKIP」的形式
- 每個 SKIP 要指名它在等哪一站（例如「等 S13 體力系統」）
- 這樣後面的站做完之後，這裡的檢查會自動生效，不必回頭補

**3. 前五項必須在舊程式上先跑綠**

這是鐵則一的具體要求。能跑綠代表這些檢查**真的抓得住既有的平衡**，不是空跑。

驗證方法：把某個已知會破壞平衡的改動臨時套上去（例如把 `GROWTH_COST` 的門檻整體
下移 10），確認你的檢查會紅。確認完把改動還原。**這一步不要省**——沒被驗證過會紅的
檢查，等於沒有檢查。

**4. 保留 `golden` 與 `determinism` 不動**

它們到 S09 才刪。這一站是加網子，不是拆網子。

### 不要做

- **不要刪 `tests/regression/{golden.mjs,golden.json,determinism.mjs}`**（S09 才刪）
- **不要改任何 `src/` 檔案。** 這一站只寫測試。如果你發現引擎缺了讓測試好寫的介面，
  寫進交接筆記，不要順手加
- **不要改 `tests/lib/harness.mjs` 的 `allocate` 策略。** 它定義了 focus/spread 兩種
  打法，改了會讓所有既有基準失去意義。S16 換設施制時才會動它
- **不要放寬現有四項不變式的門檻**

## 規則與不變式

- **`npm test` 全綠**，包含新增的 suite
- 新 suite 的 SKIP 項目要印得出來，且每個 SKIP 都指名在等哪一站
- 每個「已生效」的檢查都做過**故意弄壞 → 確認會紅**的驗證，結果寫進交接筆記
- 不動 `src/`：`git diff --stat -- src/` 為空
