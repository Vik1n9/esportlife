## 為什麼做這件事

§22.3 定了四個 tab（賽程／生涯／隊伍／選手），現行只有一個 11 section 的長捲抽屜。
後果不只是難翻：

- **賽程 tab 的內容完全沒有出口**——年曆、冠軍積分（§16.3）、時代（§17.1）
  玩家一個都看不到。賽程攤開年曆是 §0.5 直覺檢驗的落點：玩家自己看得出
  「為什麼下個月不能練」。
- **生涯 tab 的內容完全沒有出口**——S17a 建的生涯軌跡五欄位
  （`milestones`／`teamHistory`／`awards`／`intlRecord`／`disbandCrises`）
  只在退役傳記用到，遊玩途中讀不到。§22.4 明訂 route 任務卡的軌跡數字**全公開**
  ——看不到就湊不成（§12.3「看不到就不成決策」同一條理由）。

另外 S38 從狀態帶移除的兩項（本位置技能讀數、生涯薪資）在本站落地到選手 tab。

## 規則與不變式

**§22.4 資訊公開性——逐條自查，這是本站的主要風險**：

1. **隱藏心理六維在任何 tab 不得顯示**（§9.1）。
2. **教練評價在任何 tab 不得顯示**（§10.2）。
   ⚠ 注意分辨：現行 `panel.js` 顯示的 `coachBonus` 是**教練對隊伍戰力的加成**，
   不是 §10.2 的教練評價（教練對選手的隱藏總評）。前者可留。
3. **聲量是例外**：它是顯性層，可見且有分級標籤（§9.4）。
4. **route 任務卡**：觸發條件事先公開、進度可見；生涯 tab 的軌跡數字因此全公開。
5. **legend 任務卡**：開卡制——觸發前不公開，觸發當下起目標／期限／素材／進度全公開。
6. **特質配方維持不揭露**（§14.1）；特質列表只顯示已持有者的益處與副作用。

其他：

- 技能全部唯讀（§8.2 導出值）。可加點的屬性列與唯讀的技能列必須看得出差別
  （`DESIGN.md` 原則 6）。
- 心理值不給數字也不給標籤（`PRODUCT.md` 策略原則 7）。
- `src/styles.css` 檔頭鐵則「`#panel` 預設隱藏、`.open` 才顯示」在本站仍成立
  （S42 才會改成兩態）。

### `panel/index.js` 對外的 API 簽章（S42 靠它）

```
initPanel(state)       綁定事件、設初始狀態
setPanelState(state)   更新狀態引用
togglePanel(force?)    開關面板（force: boolean 強制開／關）
refreshPanel()         若面板開啟則重繪當前 tab
questRows(state)       匯出給 board.js 第四列共用
```

`togglePanel`／`refreshPanel` 的可見性守衛：`refreshPanel` 只在
`root.classList.contains('open')` 時重繪；`togglePanel` 由
`force ?? !root.classList.contains('open')` 決定開關。S42 要改成兩態
（桌面常開／行動抽屜）時改這兩處即可。

### 分頁狀態

`activeTab` 是模組變數（`'schedule'`／`'career'`／`'team'`／`'player'`），
預設 `'player'`。切 tab 透過 `root` 上的 event delegation（`[data-tab]`），
更新 `activeTab` 後呼叫 `renderCurrentTab()` 只重繪當前 tab 內容。
`refreshPanel` 同樣只繪當前 tab——跨月後狀態變了不會重繪四個 tab。

### DOM 結構

```
#panel
└ .panel-sheet
    ├ .panel-head（h3「選手資料」＋ #panel-close）
    ├ .seg.seg-4.panel-tabs（四個 [data-tab] 按鈕）
    └ #panel-body（當前 tab 的 innerHTML）
```

分頁列沿用 `.seg` 語彙＋`.seg-4` modifier（四等分），不另造樣式。
`.panel-tabs` 加 `margin: 0 -16px` 把按鈕撐到面板邊緣。
