# V5.1 修訂工作索引

> **狀態：提案，未拍板。** 本組六站在 §待拍板 第 4 項拍板前不得開工。
> 企劃書 `PROPOSAL-v5.1.md`。基準 v4.10.1。

## 這一組要做什麼

外部提案《電競人生 v5 企劃書——精簡重構版》要把 v4 的複雜度降 60–70%，
開出三項 P0：刪三層能力結構改五項能力、刪逐年賽制演進改固定年份、固定史實對手刪 NPC 生成。
評估結論（`PROPOSAL-v5.1.md` §1）：**三項 P0 要付 68 站級的重建成本，
換到的玩家端結果可以用一張分組表、一個開局參數、一次擲骰折疊拿到。**

所以本組**不是重建**，與 V4 剛好相反——V4 同時動四根互相咬死的柱子、沒有分批上線的路徑
（`../v4/README.md`）；本組六站**彼此沒有依賴**（只有 V06 要等 V01），
可以一站一站獨立上線，隨時停。

工作量 7–12 天。對比原 v5 自估的 12–19 天：原案動的是四柱裡的兩柱（屬性刻度、成長模型），
專案自己的紀錄說那是 68 站級的工程。

⚠ **組名**：本組不進千字文序（天／地／玄／黃…），站號用 `V01`–`V06`——
它不是 V4 主線的續站，是 V4 之後的獨立修訂組。

> **現況**（2026-10-19）：企劃書寫完，六站全部**未開工**。
> 程式與測試未動（`npm test` 項數不變）。等 §待拍板 四項拍板。

## 逐站摘要

### V01 賽事快報 · 2–3 天 · 零依賴

每場玩家自己的系列賽結束後產出 150–200 字報導，掛在 `phases/seriesEvent.js` 第 4 拍之後。

資料源全部現成：`kernel/series.js`（逐局比分、決勝局）、`engine/microStats.js`
（K/D/A、DPM、CSM、VSPM、MVP 率）、`kernel/leagueStats.js`（百分位詞條）、
`kernel/text.js` ＋ `phases/shared.js` 的 `kinded`（拼接）、
`engine/ledger.js` ＋ `engine/biography.js`（儲存與回顧）。

三條鐵則：
1. 確定性拼接，同 seed 必出同一篇（§15.5：「沒有 LLM，沒有隨機文案」）。
2. 不得洩漏隱藏心理六維與教練評價（§9.1／§22.4 的不顯示邊界）。
3. 不出現空欄位或佔位符。

新增 `tests/kernel/report.mjs` 守 1 與 3；2 比照 `tests/kernel/cardText.mjs` 的同類斷言。

⚠ **這一站排第一是刻意的**：零依賴、資料現成，做完就能用實測回答
「快報值不值得為它做後面五站」。同時要量兩件事：讀完一段生涯的時長、
模板重複感從第幾篇開始。

### V02 五項顯示維度 ＋ 心態折一維 · 1–2 天 · 零依賴

`data/skills.js` 加 `DISPLAY_GROUPS` 分組表（純資料，每組權重和 1.00，比照 `OVR_WEIGHTS`）：
對線 ← `lane`；會戰 ← `tf`；意識 ← `vis`／`rotate`／`gank`／`jg`；體能 ← `vit` ＋ 體力；
心態 ← 心理六維折一維粗略標籤。

`ui/panel/player.js` 預設只顯示五項，六屬性與十二技能收進二級 `<details>`（`.attr-item` 既有模式）。

⚠ 五項一律 `.static`。理由在 `data/attributes.js` 檔頭：讓玩家直接餵導出值，
就會退回「哪個 OVR 權重高就餵哪個」的打卡。

### V03 出道年份選擇 · 0.5–1 天 · 零依賴

建角畫面加一個「出道年份」選項（現在固定 2012）。改 `engine/state.js` 的 `createState` 與建角 UI。
`SAVE_VERSION` 加一。

⚠ 出道年份是**玩家輸入不是擲骰**，所以它**不進**出生亂數流
（§1.4 鐵則：潛力分佈 → 起始屬性 → 天生特質 → 心理六維 → fame → 英雄池 → 業餘隊伍 → 生命週期參數）。
這一點要寫進註釋，避免後人誤以為既有種子被位移。

### V04 訓練四檔位 → 三檔 ＋ 校準重驗 · 2–3 天 · 零依賴

刪 `data/trainingCards.js` 的卡池分檔，`engine/training.js` 的
`TRAINING_ACTIVITIES` 每項活動的 `pool:{successBias, greatSuccess, greatFailure}` 收成兩個旋鈕。
兩階段判定 → 一次擲骰、三檔結果（大成功／成功／失敗）。玩家仍看得到預期成功率。

⚠ **選項數不動**（維持六選一）。S46 剛把八選一收成六選一、S50 剛校準完
（`TRAIN_YIELD = 6.5`，平均巔峰 ÷ 上限 0.761），再動選單結構等於推翻剛做完的兩站。

⚠ **必須配校準重驗**。檔位分布一改，成功係數的期望值就動。
跑 `tools/calibrate-160.mjs` 160 段，驗三條紅線：平均巔峰 ÷ 上限 0.755 ± 0.02
（入站 0.761，已用掉三成容差）、平均休息間隔 3–4 個養成回合、休息佔比 < 50%。

⚠ **不得與其他站併站**。S46–S50 的教訓：分站各自校準會互相蓋掉
（`CHANGELOG.md` [v4.10.1]：S46–S49 各自動了方向不一致的旋鈕，四站一律不校準、把漂移交 S50 一次收斂）。

### V05 事件卡四池併一池 ＋ 分類標籤 · 1–2 天 · 零依賴

`data/events.js`（1,129 行）的 persona／performance／psych／career 四池合併成一池，
分類改用標籤；`engine/eventTrigger.js` 的抽取改讀標籤。

⚠ S48 的「事件卡傾向」抽選邏輯掛在池結構上，合池要一起改並重量
（S48 的傾向抽選換掉抽到的卡，生涯結果會重排——`CHANGELOG.md` [v4.10.1]）。

### V06 賽事取得標籤特質 · 1–2 天 · 前置 V01

把「贏得重要比賽」「擊敗強敵」「連續高水準表現」「輸給弱隊」「長期擔任先發」
做成特質的新來源，加進 `data/traits.js`。合成樹保留不動。

⚠ **每個標籤必須附反向消除路徑**。原 v5 只給「爆冷陰影」寫了消除，
其餘四個沒有——只能加不能減的標籤會讓後段局單向惡化，而且五個標籤全是
「贏了加成／輸了減益」的正回饋，放大而非收斂結果差異。

`tests/kernel/traits.mjs` 已有正向與反向死鍵掃描，新標籤會被它守到。
