狀態：未開始
前置：S01

推理難度：中
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：查 git 是機械的，但 `phases/*` 那批「檔案是新的、程式碼是搬過去的」要逐段判斷
血緣，不是 `git log` 查得出來的。降級到 Haiku 的風險是把 `phases/*` 整批誤標成原創，
S03–S05 就會漏掉該重寫的東西。

## 為什麼做這件事

原作者未回覆授權申請，以「未獲正式授權」處理。要清除承襲的程式碼，得先知道**哪些
是承襲的**。

`00-共通規則.md` 第二節已經給了粗分（A 批 / B 批），但那是用 `git log --diff-filter=A`
查檔案建立時間得到的。**這個方法對 refactor 搬過去的程式碼會判錯**——`phases/*` 全部
是 2026-08-12 建立的，看起來像原創，實際上是從 `engine/game.js`（A 批）拆出來的。

這一站把粗分變成逐段的、可查核的標記表。S03–S05 照這張表施工。

## 範圍

### 要做

**1. 逐檔標記**

`src/` 目前 57 個檔。每個標成三類之一：

| 標記 | 意思 | 處置 |
| --- | --- | --- |
| `A` | 承襲：`a71ee13` 或更早加入，或內容從 A 批檔案搬過來 | 需淨室重寫或由 V4 整段重寫 |
| `B` | 原創：2026-08-11 之後從零寫的 LoL 內容 | 可直接沿用與修改 |
| `A/B` | 混合：檔案裡同時有搬過來的段落與新寫的段落 | 標出是哪些函式屬 A，只重寫那幾段 |

**2. `phases/*` 要逐函式查**

這是這一站的重點。方法：

```bash
git show 6ec9575 --stat
git log -p --follow -- src/engine/game.js | head -400
```

`6ec9575` 是「refactor: 年曆抽成資料表，game.js 拆成 driver + phases/」。比對拆分
前後的 `engine/game.js`，看每個 `phases/*.js` 的函式是**搬過去的**還是**當時新寫的**。

同理要查的還有：
- `e07427c`「world.js 依實體重切成 data/regions/ 與 data/formats/」→ `data/world.js` 是 A 批
- `b2cdc80`「特質效果資料化，收進 kernel/modifiers.js」→ 效果值搬自 `data/traits.js`（A 批），但聚合機制是新寫的
- `667ec4c`「抽出 kernel/{series,groups,strength}」→ `strength.js` 可能搬自 `engine/team.js`（A 批）
- `876c76b`「六屬性＋導出技能雙層養成」→ `data/skills.js` 由 `data/abilities.js`（A 批）演化

**3. 產出標記表**

寫進 `ARCHITECTURE.md` 新的一節「## 程式碼血緣」。格式：

```markdown
| 檔案 | 血緣 | 依據 | 處置 |
| --- | --- | --- | --- |
| `core/rng.js` | A | a71ee13 建立 | S03 淨室重寫 |
| `kernel/groups.js` | B | 667ec4c 新寫，原專案無小組賽 | 沿用 |
| `phases/msi.js` | A/B | 敘事段新寫；`run()` 骨架搬自 game.js | S04 重寫 run() |
```

「依據」欄一定要寫得出來是哪個 commit 或哪段推理——這張表之後會被引用，不能是印象。

**4. 更新 S03/S04/S05 的檔案清單**

如果審計結果跟 `00-共通規則.md` 的粗分不一致（很可能），去改那三份說明書的「要動的
檔案」節，以審計結果為準。同時修正 `00-共通規則.md` 第二節。

### 不要做

- **不要開始重寫任何檔案。** 這一站只產出表格
- **不要動 git 歷史。** 那是 S06，而且要先問過人

## 規則與不變式

- `npm test` 在這一站前後應該**完全不變**（沒改程式碼，測試結果就不該動）
- 標記表要涵蓋 `src/` 下**每一個** `.js` 與 `.css` 檔，一個都不能漏。漏掉的等於預設
  它是 B 批，那是最危險的預設
- 有疑慮的一律標 `A`。誤標成 A 的代價是多寫一次；誤標成 B 的代價是留著承襲程式碼
