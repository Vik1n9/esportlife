## 範圍

### 要做

**1. Liquipedia 探勘驗證（第一件事，決定後續可行性）**

- 驗證 GPL／LMS／PCS／LCP 的隊伍分類頁與選手頁覆蓋：S2（2012）起各年度的
  隊伍與選手 ID 是否齊全。
- 照 S23 定案的備援規則處置缺口（Leaguepedia 補抓並標記來源）。

**2. 隊伍演變樹（`team_history.json`）**

- 由分類頁解析台港澳賽區戰隊的成立、更名、解散、合併紀錄。
- 欄位：`team_id`（縮寫）、`display_name`、`active_years`、`predecessors`、
  `successors`。輸出格式依 S23 定案的 schema。

**3. 目標選手清單（`target_players.csv`）**

- 台港澳全量（S2 至今參與過頂級聯賽的選手 ID）+ 國際賽精選（歷屆 MSI／世界賽
  參賽名單提取當屆選手）。
- 欄位：`wiki_url`、`player_id`、`region`、`fetch_priority`（台港澳 1、國際賽 2）。

**4. 安全分批抓取（`raw_data/`）**

- 每批 50–100 個 URL；請求間隔 2–5 秒隨機延遲；User-Agent 輪替。
- 中斷續傳：記錄已成功抓取的 URL，重啟跳過。
- 原始 HTML 或 Wikitext 落檔，**不做任何解析**（解析是 S25 的事）。

**5. 工具落點**

- 腳本放 `tools/`（與既有內容編輯器並列），資料檔標頭 CC BY-SA 出處註記。
- `raw_data/` 是否進 repo 由 S23 定案；若不入 repo，交接筆記寫明存放位置與
  重新下載方式。

### 不要做

- **不要解析或清洗資料**——raw_data 就是 raw，S25 才動它
- **不呼叫 LLM**
- **不要「順便修正史實」**（S05 同款規則）：發現 Liquipedia 資料可疑，寫進
  交接筆記，不在本站改
- 不碰 `src/` 與 `tests/`
