# 開發工具（tools/）

開發者工具，**不是遊戲的一部分**。目前有兩樣：內容編輯器（網頁，寫事件卡／特質卡／
生涯任務卡／合成配方／天生特質）與 DEMO 模擬腳本（Node CLI，見檔尾「DEMO 模擬腳本」
節）。遊戲不從任何地方連到這裡，`index.html` 沒動。

## 開法

```bash
npm run serve
```

開 <http://localhost:8080/tools/>。頁面直接 import `src/data/*.js` 填下拉選單、
載入既有條目——所以工具**永遠跟遊戲資料同源**，欄位可選值不會對不上。

## 五個分頁

| 分頁 | 資料 | 規格 |
| --- | --- | --- |
| 事件卡 | `src/data/events.js`（一般事件卡）＋ `src/data/trainingCards.js`（訓練事件卡） | §12.2／§5.4 |
| 特質卡 | `src/data/traits.js`（通用＋稀有）＋ `src/data/epics.js`（史詩＋傳說） | §13／§14.1 |
| 任務卡 | `src/data/quests.js` | §12.3 |
| 配方 | `src/data/epics.js` 的 `FUSIONS` | §14.6 |
| 天生特質 | `src/data/innate.js` | §14.1 |

## 每欄的意思

- **四池**（persona／performance／psych／career）：事件卡與特質卡共用同一套
  （§12.2）。psych／career 不入合成。
- **時段標籤**：觸發的前置過濾器。不匹配當下時段的卡連候選池都進不去。
- **互斥群組**：同一回合的兩張卡不得同組；`solo_<id>` 表示自成一格。**必填**。
- **連續事件的三欄**（事件卡結果與選項，§12.2）：`點亮旗標`／`熄滅旗標`／`計數 +1`。
  鍵是**自由字串**（新連鎖的旗標第一次寫時，卡庫裡還沒有那個鍵），已用過的鍵掛在
  輸入框的提示清單裡。條件式端用 `['eventFlag', 鍵]` 與 `['eventCount', 鍵, 比較子, 值]`
  讀；計數的鍵可以直接寫**卡 id**（每張卡出場自動 +1，不必宣告）。
  ⚠ **一段連鎖一定要熄**：條件卡不受防重擋，旗標亮著的期間那張卡月月都是事件一。
  一次性門檻請寫成「計數 ≥ N 且 `not` 已出過旗標」，每個選項都點亮那個閂。
- **條件式**（任務卡的 trigger／goal、特質的 maintain）：
  `['and', ['stat', 謂詞, 比較子, 值], ['has', 階, 鍵]]`。
  工具驗**語法與謂詞名**，不驗形狀——形狀由 §12.3 條件式自由組合。
  **兩種模式**（S18b）：
  - **積木**（預設）：`and`／`or`／`not` 容器可加減子條件，葉節點是下拉＋數字框，
    只產得出合法結構。換節點型別＝換成該型別的預設形狀，不硬轉舊值。
  - **原始 JSON**：既有的 textarea，手打整串條件式。
  兩模式共用同一份資料，**切換不掉東西**，隨時可以來回。
- **效果**（特質的 effects／sideEffects）：`kernel/modifiers.js` 的四種寫法
  （數字簡寫＝加法、`{mul}`／`{floor}`／`{cap}`／`true` 旗標）＋§7.2 六窗口。
  副作用與益處共用同一組鍵，方向相反。
- **maintain（維持條件）**：特質分頁的維持條件欄位。舊資料裡它是函式
  （`data/traits.js` 的單身／圈內毒瘤）——載入檢視時放行，產出時原樣保留；
  新寫的請用條件式陣列。

## 單筆驗證（表單旁即時）

填的時候就紅。**紅的規則一律對得到 `tests/kernel/*.mjs` 的某一行**——工具的職責是把
「貼回去才紅」提前到「填的時候紅」，所以它不准比測試嚴，也不准比測試鬆。

| 類別 | 擋什麼 |
| --- | --- |
| 共通 | 辨識鍵唯一、必填、效果四寫法＋六窗口的 op 方向、條件式語法與謂詞名 |
| 事件卡 | 選項 2~4、選項 id 不重複、互斥群組必填（獨佔要寫 `solo_<id>`）、連鎖旗標點得亮／熄得掉 |
| 特質卡 | 副作用非空、重度副作用只給史詩／傳說、傳說必 heavy＋career 池、**互斥對稱** |
| 配方 | 稀有恰 2 素材／史詩 2~3、稀有吃 persona／史詩吃 performance、產物不得是傳說 |
| 訓練卡 | **單純成功／失敗絕對禁止動心理（§14.8.4）**、受傷只在大失敗、pool 與 tier 一致 |
| 天生特質 | 池 ≤5 與取得率、必須指派 persona／performance、mentalBias 維度不得重複 |

⚠ 訊息開頭有 **⚠** 的是**警告不是硬紅**：規格寫了但測試沒驗的規則（例如「益處非空」
——`glass` 現況就是空的）。警告不擋事，但值得看一眼。

⚠ 兩個豁免與 `tests/kernel/traits.mjs` 同源，**改要一起改**：
`tilt`／`pariah` 是 common 卻標 heavy（v4.2 雙面特質，測試 83-87 行明文豁免）。

## 天生特質分頁的取得率

分頁頂端常駐一行 `0.8 ÷ N`（§1.4 種子期望值 0.8 個／均勻抽取）：
N=4→20%、**N=5→16%（現況，貼線警告）**、N=6→13.3%（破 §14.2 的 15% 死線）。
池開得越大每一個越拿不到，與直覺相反，所以不藏在按鈕後面。

**這是整個系統裡唯一封閉式算得出來的取得率**——其餘素材的取得率要跑 160 段生涯才量
得到（§21.3），工具只查「有沒有來源」，機率層留給 S19c 驗收。

## 關係檢查（右上角按鈕）

橫跨資料掃五類問題（§14.8）：

1. **素材競態**：一個素材被多條配方共用。池內共用是設計上的取捨（同階配方爭奪素材），
   跨池共用（同一素材同時被稀有與史詩配方引用）才是錯誤。
2. **死配方**：素材沒有可達取得路徑。可達來源＝事件卡（FLAG_TRAIT）、扮演卡
   （PERSONA_RULES）、生涯條件（veteran／single／disc）、天生特質池、其他配方產出。
   ⚠ 工具只查「有沒有來源」——取得率 ≥15% 的實測線在 S19c 用 160 段生涯驗收。
3. **觸發斷裂**：事件卡旗標指向不存在的特質鍵、任務卡條件式引用不存在的謂詞或素材鍵。
4. **效果鍵被引擎消費**：特質宣告的效果鍵不在 `schema.js` 的 `EFFECT_KEYS`＝打錯鍵，
   特質會靜靜地沒有效果。⚠ 訓練卡效果欄的 `mental`／`buff`／`injury`／`attr` 不是
   modifiers 的效果鍵（各有自己的消費端），跳過不驗——`attr` 是 S18b 補上的，
   在那之前 60 張訓練卡有 28 張被誤報。
5. **池指派完整**：特質都有池歸屬（未指定預設 persona）；psych／career 不入合成。
6. **天生特質池上限**：≤ 5（§14.1，0.8 ÷ N ≥ 15% 死線）。

## 合成圖譜（右上角按鈕）

力導向佈局（自製模擬，零相依），展示「下層素材 → 上層產物」的合成樹。節點顏色
= 階級（common 灰／rare 藍／epic 紫／legend 金）。

## 產出怎麼貼回去

1. 編輯完成後按「複製片段」或「下載 .js」。
2. 把片段貼進對應資料檔的陣列／物件裡。排版已對齊既有檔案：**2 空格縮排、單引號、
   短的物件與陣列內聯**（100 欄放得下就不換行），貼回去的 diff 只有新增那幾行。
3. 跑 `npm test`——工具產出的卡片要能過全部測試。
4. ⚠ 貼回去時**留意既有卡片的結構**（欄位名、效果寫法），工具的 schema 是權威，
   遊戲引擎的消費端在 `src/engine/*`。

## schema 改了動哪裡

欄位描述集中在 `tools/schema.js`。**改 schema 只改這一個檔**，不要動 `editor.js`
的表單邏輯。

⚠ 兩個同步點（新內容會踩到）：

- **新增效果鍵**：`src/kernel/modifiers.js` 的消費端＋`schema.js` 的 `EFFECT_KEYS`
  要一起加——否則工具會把新鍵標成「不被引擎消費」。
- **新增謂詞**：`src/engine/conditions.js` 的 `QUERIES`＋`schema.js` 的 `PREDICATES`
  要一起加——否則條件式驗證會擋掉新謂詞。

## 產出的假卡測試

完成定義第 4 項：「產出一張事件卡＋一個特質，貼進資料檔，`npm test` 全綠，然後
移除」——那是人工驗證步驟，工具本身不寫檔（無 File System Access API、無後端）。

# DEMO 模擬腳本（tools/demo-sim.mjs）

調數值用的可重現量測工具（規格書 §19.5），**不是遊戲機制**。跑一批 DEMO 路線
（PRO 起點、三年 36 個月）生涯，印平衡指標；改數值前後對照用。

## 開法

```bash
npm run sim:demo                 # 跑 100 段、印指標、與快照印 diff
npm run sim:demo:update          # 跑完把指標寫回 snapshots/demo.json
node tools/demo-sim.mjs --runs 200 --style focus   # 加樣本／換打法
```

參數：`--runs`（目標段數，實跑＝種子數 × 5 位置 × 2 打法，就近取整）、
`--seed-prefix`、`--roles`、`--style`。

## 快照的語意

`snapshots/demo.json`（commit 進 repo）是 **before/after 對照基線，不是斷言**：

- 種子固定，同一份碼跑出來的指標完全重現——改數值前後的差異由 diff 行直接讀。
- 一般執行只**印 diff 不硬紅**：調數值本來就是要動這些數，硬紅的職責在
  `npm test`。
- 基線不同（runs／seedPrefix 不一致）只警告。

## ⚠ 同步義務（機制／資料更動時）

- 腳本駕駛與斷言用的常數（`DEMO_YEARS`／`DEMO_END_YEAR`／`DEMO_MONTHS`）全從
  `src/` 匯入、不手抄——資料檔改了腳本自動跟。
- **機制改了、快照過期，是人為步驟**：跑 `npm run sim:demo:update` 落地新基線，
  與程式同一個 commit。
- `npm test` 的 `tests/regression/tools-sim.mjs` 會端到端跑 10 段完整 DEMO：
  腳本跑不動、收束不自洽，當場紅——改機制沒同步改腳本就過不了收尾閘門。
