# S34 · 玩家戰績接入與相對評價（Phase 3）

狀態：完成
前置：S33
預估：1 session
推理難度：中
建議模型：Sonnet 5（`claude-sonnet-5`）
理由：接入規則與掛載層由 S31 定案，本站照做。要小心的不是設計，是不動到
§10 教練評價與既有 fame 流的定義權，以及編輯器 schema 的增量不破 S18a 的
既有檢查。

---

## 為什麼做這件事

NPC 的聯賽數據有了（S32／S33），但玩家的數據還在自己那條線（`season.js` 的
K／D／A／VIS、§15 賽事序列），兩邊不通。本站把玩家數據併入統一資料池，擴充
玩家端微觀維度（DPM、分均補刀），上動態評價基準——玩家的表現評價與媒體敘事
從「絕對數值」變成「偏離基準的相對判定」，並讓聯賽數據里程碑成為任務卡與
合成的條件式謂詞。

---

## 入口狀態

```bash
node docs/v4/next-station.mjs
```

回報本站為下一站。S31 定案：資料池寫入點、玩家端維度擴充規格、動態基準算法、
謂詞語法、掛載層清單。S33 的 NPC 微觀數據與榜單就位。

---

## 範圍

### 要做

**1. 玩家端微觀維度擴充**

- `src/engine/season.js` 加 DPM 與分均補刀，照 S31 定案的公式（與 NPC 端同
  維度、同量級，池子兩邊才對得齊）。
- 舊欄位（K／D／A／VIS）照 S31 定案接軌或改寫。

**2. 玩家數據併池**

- §15 賽事序列與 §11.3 常規賽的玩家產出，照 S31 定案的寫入點進聯賽資料池。
- 與 NPC 數據同格式、同去重規則。

**3. 動態評價基準**

- 各位置平均數據基準（KDA、DPM）依 S31 定案的算法動態計算。
- 玩家表現評價與媒體敘事改相對判定：偏離基準程度 → 照 S31 掛載層清單接入
  （戰報文本／聲量／事件卡）——**不得碰 §10 教練評價**。

**4. 條件式謂詞落地**

- 里程碑謂詞（如「KDA 同位置前 20%」）接進 §12.3 條件式求值，吃當季模擬
  母體（§24.1 第 2 條）。
- §14.7 編輯器 schema 增量：新謂詞進條件式語法與表單欄位，S18a 既有檢查
  不破（`npm test` 與編輯器冒煙測試）。

### 不要做

- 不改 §10 教練評價的定義與輸入
- 不混用母體：§14.3 生涯路線仍吃史實母體（S26），只有任務卡／合成謂詞吃
  當季模擬——切分規則以 S31 為準
- 不做國際賽（S35）

### 併池覆蓋

- **賽區內（`splits`）**：玩家常規賽數據（`phases/month.js` 的
  `regularSeason` → `simulateSeason` → `recordPlayerLeagueResult`）逐月併入，
  鍵固定 `PLAYER_STAT_ID`（`'player'`）。
- **國際賽（`intl`）**：MSI／世界賽的 Swiss／淘汰賽／地區資格賽（一律經
  `kernel/series.js` 的 `runSeries`）併入，寫入口是 `phases/shared.js` 的
  `recordIntlSeries`。**舊制小組賽（`runGroup`，2012–2022 BO1）未併入**——沒有
  陣亡數據可用，見規格 §24.4.3 的落地註記；不影響 Swiss 制年份（2023 起）。
- 兩池都是**總量格式**（K/D/A 直接搬、DPM 是場均比例乘回場次、CSM/VSPM 用
  CS/VIS 總量頂替）——與 NPC 端 `accumulateMicroStats` 的累加語意對齊，
  `metricAverage` 統一除以 G 才可比。

  `COND_KINDS`／`evalCond`，`tools/schema.js` 的 `COND_NODES`／
