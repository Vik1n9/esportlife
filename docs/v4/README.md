# V4 重建工作說明書 · 索引

`ESPORT-DESIGN-V4.md` 要把 esportlife 從「年回合 × 擲骰加點 × OVR」翻成
「月回合 × 賽馬娘設施制 × 十二技能／隱藏心理／教練評價」。

這不是改版，是重建。V4 同時動四根互相咬死的柱子——屬性刻度（1–80 → 0–100）、
回合粒度（年 → 月）、成長模型（擲骰加點 → 設施制）、評估層（OVR → 教練評價）。
任一根單獨改都會讓其餘三根的既有校準失效，所以沒有分批上線的路徑。

工作量約 2400 行重寫 ＋ 900 行淨室重寫 ＋ 事件卡 26→80~150 張 ＋ 特質全面補副作用。
**單一 session 吃不下**，所以拆成 31 站，每站一份說明書，各自能獨立開工。

## 怎麼用這套文件

> 說「動工」即由 `next-station.mjs` 自動解析下面的狀態表、抓出下一站並載入對應說明書
> ——不必手動找「第一個未開始且前置完成」的站。腳本與本表同源，本表一變動腳本必須
> 同步更新（見 `AGENTS.md` 收尾流程）。

1. 看下面的狀態表，找第一個「未開始」且前置都已「完成」的站
2. **依該站的建議模型切換**（模型選單操作，不是這裡跑指令）
3. 讀 [`00-共通規則.md`](00-共通規則.md)（每次都要，不要跳過）。
   要知道「現在長什麼樣」看 [`00b-穩定點快照.md`](00b-穩定點快照.md)——基準座標、
   承重牆、量到的數字、已知缺口
4. 讀該站說明書，照著做
5. 收尾：跑測試 → 回填該站的「交接筆記」→ 更新下面的狀態表 → 更新 `WORKLOG.md` → commit

一個 session 只做一站。做完就停，不要順手開下一站——「不要做」那節存在的理由就是
防這個。

## 額度分配

31 站裡 13 站標高（Opus 5），全部集中在平衡數值與架構。內容類 9 站判斷成本低但
文案品質要求高，標 Sonnet 5 而不降到 Haiku。只有 S06／S22 兩站掛 Haiku 4.5。

v4.3 新增的 **S15b 標 Opus 5**——生命週期曲線一次動成長與衰退兩端的平衡，而且它的
產出（effective_potential 曲線）被 S16 訓練、S21 退役直接依賴，正是「產出被後面
多站依賴」的典型高難度站。

v4.1 新增的四站裡只有 **S17b 標 Opus 5**——它握著傳說特質的唯一發放口，S07 的兩條
傳奇不變式全部經過它。另外三站（S17a 記帳、S19d 填天生特質池、S21a 拼傳記）規則都
由規格書寫死了，判斷成本不高。

丙組（S09–S13）是整條線的成本重心，五站全高——那也是最不該省的地方，因為它的產出
被後面每一站依賴。真的要省，省在戊組的內容站：那裡降級最多是文案平淡，測試抓得到
結構錯誤。

## 關鍵路徑

```
S01 ─┬─ S02 ─┬─ S03 ─┐
     │       ├─ S04 ─┼─ S06                        （授權線，可獨立推到底）
     │       └─ S05 ─┘
     │
     └─ S07 ─┐
             ├─ S09 ─ S10 ─ S11 ─ S12 ─┬─ S19a ─ S19d ─┐
S08 ─ S08b ──┘                         ├─ S17a ────────┤
                                       ├─ S20 ─────────┼──────────┐
                                       │               │          │
                                       └─ S13 ─ S14 ─┬─ S15        │
                                                     ├─ S15b       │
                                                     ├─ S16        │
                                                     └─ S17 ─ S17b ┤
                                                                   │
        S17b ＋ S19a ＋ S19d ─→ S18a ─┬─ S18 ──┬─ S19c ────────────┤
                                      └─ S19b ─┘                   │
                       S17a ＋ S18 ＋ S19d ─→ S21a ────────────────┤
                                                             S21 ←─┘
                                                              └→ S22
```

S15／S16 同時要 S12（失誤系統、心理修正）與 S14（月回合骨架）。

**S15b 要 S09（屬性層，曲線直接改 `effective_potential`）與 S14（月回合年曆，衰退是
年度 pull、年界由月曆定位）。** S16 排在 S15b 之後——它的前置是 S12＋S14＋S15b，
訓練成長讀的 `effective_potential(attr, age)` 就是 S15b 的產出。圖上為省空間把
S15／S15b／S16 並列畫在 S14 之下，實際順序是 S15b → S16。

戊組的入口變成三條可並行的線：**S19a→S19d**（特質側）、**S17a**（資料側）、
**S17→S17b**（引擎側）。三條都到齊 S18a 才開得了工，而 S18a 是兩個大內容站的門。
S17a 與 S19d 都只依賴 S12，**可以在 S13～S17 那條長線推進的同時分開的 session 做掉**
——它們是這張圖裡少數不卡在關鍵路徑上的站。

甲組（S02–S06，淨室重寫與授權）與乙丙丁戊是**平行的兩條線**——淨室重寫是授權問題，
V4 重建是設計問題，兩者只在 S01 交會。額度緊的時候可以先把一條線推到底。
